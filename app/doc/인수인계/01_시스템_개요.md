# 01. 시스템 개요

> 인수인계 문서 01/11 · 작성일 2026-10-22
> 기준: 앱 커밋 `93cab85` · versionCode 4 / versionName 1.00

---

## 1. 이 시스템은 무엇인가

(주)하이랜드이노베이션 물류센터에서 **마트 출하 박스를 계근하는 Android PDA 앱**이다.

1. 서버(ERP)에서 그날 출하할 대상(마트·센터·품목·수량)을 PDA로 받는다.
2. 박스 바코드를 스캔하면 바코드에서 중량·제조일자를 읽어 출하 대상과 맞춘다.
3. 마트별 물류 라벨을 블루투스 라벨 프린터로 출력한다.
4. 계근 결과를 서버로 보내 ERP 출고계근 테이블에 저장한다.

이마트·홈플러스·롯데·도매업체와 비정량(이마트·홈플러스) 출하를 한 앱에서 처리한다.

## 2. 프로젝트 목적과 원칙

### 2.1 원칙
**기존 기능과 100% 동일하게 동작해야 한다.** 기능은 그대로 두고 장비와 DB만 바꾸는 전환 프로젝트다.
회사코드와 하드코딩(창고코드 등)만 예외로 바꿀 수 있다.

### 2.2 목적
| # | 목적 | 내용 |
|:-:|------|------|
| 1 | 장비 전환 | PDA는 Honeywell, 프린터는 BIXOLON으로 교체 |
| 2 | DB 전환 | Oracle → MSSQL. ERP 프로그램 변경에 따라 테이블·컬럼도 변경 |
| 3 | 하드코딩 변경 | 창고코드 등 고정값을 ERP 조회로 변경 |
| 4 | 소스 정리 | 큰 Activity를 역할별 클래스로 분리, 미사용 소스 삭제 |
| 5 | 회사코드 추가 | 회사코드 `20` 기준으로 조회·저장 |
| 6 | 기존 기능 유지 | 위 변경 외 동작은 원본과 동일 |

## 5. searchType별 마트 구분

메인 화면에서 누른 버튼에 따라 `Common.searchType`이 정해지고, 계근 화면은 이 값으로 처리 클래스(`shipment/mode/`)를 고른다(`ShipmentModeFactory`).

| searchType | 업무 | 출하대상 조회 JSP | 계근 전송 JSP | 처리 클래스 | 운영 |
|:-:|------|------|------|------|:-:|
| 0 | 이마트 출하 | `search_shipment.jsp` | `insert_goods_wet.jsp` | `EmartMode` | 사용 |
| 1 | 생산 계근 | `search_production.jsp` | `insert_goods_wet_production.jsp` | `ProductionMode` | **미사용** (버튼 숨김) |
| 2 | 홈플러스 하이퍼 출하 | `search_shipment_homeplus.jsp` | `insert_goods_wet_homeplus.jsp` | `HomeplusMode` | 사용 |
| 3 | 도매업체 출하 | `search_shipment_wholesale.jsp` | `insert_goods_wet_new.jsp` | `WholesaleMode` | 사용 |
| 4 | 비정량 출하 (이마트) | `search_production_nonfixed.jsp` | `insert_goods_wet_new.jsp` | `EmartNonfixedMode` | 사용 |
| 5 | 홈플러스 비정량 출하 | `search_homeplus_nonfixed.jsp` | `insert_goods_wet_new.jsp` | `HomeplusNonfixedMode` | 사용 |
| 6 | 롯데 출하 | `search_shipment_lotte.jsp` | `insert_goods_wet_lotte.jsp` | `LotteMode` | 사용 |
| 7 | 생산 라벨 | `search_production_4label.jsp` (서버에서 삭제됨) | `insert_goods_wet_production.jsp` | `ProductionLabelMode` | **미사용** (버튼 숨김) |

> - searchType 4의 버튼 ID(`btnproductionNonfixedlist`, `btnProdNonfixedWet`)에 `production`이 붙어 있지만 **생산이 아니라 비정량 출하**이며 운영에서 사용한다.
> - 1·7은 화면에서 숨기고(`visibility="gone"`) 코드는 보존했다. 정리하지 않기로 결정된 상태다.

## 6. 화면 구성

```
LoginActivity ── 사번·비밀번호 입력, 창고 선택
   │
   ▼
MainActivity ── 작업일자 선택, 마트별 [출하대상받기] / [계근입력시작]
   │
   ├─▶ BixolonShipmentActivity ── 계근 화면 (스캔 · 계근 · 라벨 출력 · 전송)
   │      ├─ WetDetailDialog ───── 계근 상세 팝업 (삭제, 합산 라벨)
   │      ├─ ExpiryEnterActivity ─ 소비기한 입력 (수기 중량 입력 시 일부 센터)
   │      └─ DeviceListActivity ── 블루투스 프린터 선택
   │
   ├─▶ ProductionActivity ── 생산 계근 계산
   └─▶ SettingActivity ───── 프린터 사용 ON/OFF
```

### 6.1 화면별 역할

| 화면 | 역할 | 비고 |
|------|------|------|
| `LoginActivity` | 로그인, 창고 목록 조회·선택, 로컬 DB 테이블 생성, 프린터 설정값 읽기 | |
| `MainActivity` | 작업일자 선택, 출하대상 다운로드, 계근 화면 진입, 계근대상 삭제, 종료 | 다운로드한 타입과 다른 [계근입력시작]을 누르면 막는다 |
| `BixolonShipmentActivity` | 바코드 스캔 → 출하대상 매칭 → 라벨 출력 → 계근 저장 → 서버 전송 | 메뉴에 [테스트 출력] 있음 |
| `WetDetailDialog` | 품목별 계근 내역 조회, 선택 삭제, 합산 라벨(파렛트당 박스 수 입력) | `shipment/dialog/` |
| `ExpiryEnterActivity` | 수기 중량 입력 시 소비기한 입력 (킬코이 미트센터, 수입육 센터·롯데) | |
| `DeviceListActivity` | 페어링된 블루투스 프린터 선택 | |
| `SettingActivity` | 프린터 사용 ON/OFF (숨김 기능: 이미지 7회 터치 시 전체 계근내역 삭제) | |
| `ProductionActivity` | 생산 중량 합산 계산 | 현 상태 유지, 현장 사용 여부 확정 전까지 우선순위 낮음 |
| `ShipmentActivity` | 원본 Woosim용 계근 화면 | **진입 불가.** 원본 비교용으로 삭제하지 않고 보존 |

### 6.2 메인 화면 메뉴 (우상단)

| 메뉴 | 동작 |
|------|------|
| 프린터설정 | `SettingActivity`로 이동 |
| 출하대상 / 바코드정보 / 계근데이터 | 로컬 DB에 받아 둔 데이터를 팝업으로 확인 |
| 계근내역 삭제 | 로컬 `TB_GOODS_WET` 전체 삭제 |
| 날짜설정 | 작업일자 선택 |

## 7. 한눈에 보는 업무 흐름

```
로그인(창고 선택)
  → 작업일자 선택
  → [출하대상받기]   서버 → 로컬 TB_SHIPMENT · TB_BARCODE_INFO
  → [계근입력시작]   BixolonShipmentActivity
  → 센터·점포 선택
  → 박스 바코드 스캔  중량·제조일자 추출 → 출하대상 매칭 → 박스 순번 부여
  → 라벨 출력        마트별 라벨 (BIXOLON)
  → 로컬 저장        TB_GOODS_WET
  → [전송]           계근 전송 JSP → ERP SM_출고계근
```

마트별 상세 흐름은 `06_마트별_업무흐름`, 라벨 규격은 `08_라벨_규격`, 바코드 규칙은 `09_바코드_규칙`에 정리한다.
