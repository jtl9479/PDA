## 2. 공통 흐름

### 2.1 출하대상 받기 (메인 화면)

```
[작업일자 선택] (안 고르면 오늘)
  → 마트별 [출하대상받기]
       받기 전 로컬 정리: 출하대상·바코드정보 전체, 서버에서 받은 계근('Y') 삭제 / 미전송 계근('F')은 유지
       ① 출하대상     search_*.jsp            → TB_SHIPMENT
       ② 바코드정보   search_barcode_info*.jsp → TB_BARCODE_INFO
       ③ 기존 계근분  search_goods_wet.jsp     → TB_GOODS_WET ('Y')
       → "바코드정보 없는 상품" 팝업 (바코드 규칙이 없는 품목 목록)
  → 같은 마트의 [계근입력시작]
       다른 마트 목록을 받아 둔 상태거나 목록이 비어 있으면 진입 차단
```

- 바코드정보 없는 상품은 스캔해도 품목을 찾지 못한다. ERP 품목 마스터(`CO_품목코드`)에 바코드 위치 정보를 넣어야 한다.
- ③ 덕분에 이미 전송한 출고를 다시 받아도 계근 수량이 채워진 상태로 나온다.

### 2.2 계근 화면 구성

| 영역 | 내용 |
|------|------|
| 상단 | 뒤로가기, 초기화, **인쇄 ON/OFF 스위치**(이번 작업에서만 라벨 출력을 끔) |
| 작업방식 | 바코드 / 수기(중량) / 상품코드 |
| 센터 | 출하대상에 있는 센터 목록 |
| 작업지점 | "거래처명 / 수입식별번호" 목록. 품목을 처음 스캔하면 채워지고, 계근이 끝나지 않은 첫 지점이 자동 선택된다 |
| BL번호 | 같은 품목의 BL(이력)번호 목록 |
| 계근 현황 | 센터 총 수량·중량(요청 / 계근), 지점 수량·중량 |
| 목록 | 출하대상 행. 행을 누르면 계근 상세 팝업(2.7) |
| 버튼 | [입력], [전송](계근 완료 전에는 비활성) |

### 2.3 바코드 작업 (작업방식 = 바코드)

| 단계 | 동작 | 막히는 경우 (안내 문구) |
|:-:|------|------|
| 1 | 박스 바코드 스캔 → 바코드정보에서 **패커상품코드**로 품목을 찾는다 | 품목을 못 찾음: "패커상품이 존재하지않거나, 바코드가 정확하지 않습니다." |
| 2 | 작업 중인 품목이 없으면 그 품목으로 정하고 **작업지점 목록을 불러온다** | 출하대상이 없음: "조회결과가 없습니다." |
| 3 | 작업 중 **다른 품목**을 스캔하면 "상품 변경 — 다른 상품을 계근하시겠습니가?" 확인 후 바꾼다 | |
| 4 | 같은 품목이면 선택된 BL번호와 같은 행 중 **계근이 끝나지 않은 첫 행**을 찾아 계근 대상으로 정한다 | "해당하는 BL상품이 없습니다. BL번호를 확인해주세요." |
| 5 | 소비기한 정보 검사 — ① 킬코이 패커 + 미트센터 지점(전 마트) ② 이마트이고 센터명이 `용인TRD`·`대구TRD`·`시화(W)_TRD`·`여주TRD`이거나 `E/T`·`WET` 포함. 품목 마스터에 소비기한·제조일자 위치가 없으면 계근 불가 | "미트센터 납품 - KILKOY 상품의 경우 소비기한정보가 필수로…", "트레이더스 납품 상품의 경우 소비기한정보가 필수로…" |
| 6 | 같은 바코드로 이미 계근했는지 확인 (비정량 4·5는 확인 안 함) | "이미 스캔한 바코드입니다. 다른 바코드를 스캔하세요." |
| 7 | 바코드에서 중량·제조일자·박스시리얼 추출 (2.6) → **저장 → 라벨 출력** | 품목에 중량 위치가 없으면 경고 창 |

> **실기기 확인 필요**: 코드상으로는 작업 중인 품목이 없을 때 첫 스캔은 2단계(작업지점 목록 불러오기)까지만 하고, 계근은 그다음 스캔부터 된다. 테스트 문서(테스트/04·07)에는 "첫 스캔에 계근"으로 적혀 있어 현장 동작을 한 번 확인해 두는 것이 좋다.
> 같은 바코드가 0.5초(수신)·1초(처리) 안에 다시 들어오면 무시한다(스캐너 중복 입력 방지).

### 2.4 수기(중량) 작업

1. 먼저 바코드·상품코드로 품목을 정해 둔다(품목이 없으면 "상품패커코드가 없습니다.").
2. 작업방식을 **수기(중량)** 로 바꾸면 계근이 끝나지 않은 첫 지점이 자동 선택된다.
3. 중량을 입력하고 [입력](또는 Enter).
   - 이마트(0)는 입력 중량을 **소수 1자리에서 버린다.**
4. 아래 경우 **소비기한 입력 화면**(`ExpiryEnterActivity`)이 떠서 제조일자를 받는다.
   - 킬코이 패커 + 미트센터 지점 (전 마트)
   - 이마트이고 센터명에 `TRD`·`WET`·`E/T` 포함
   - 롯데 (항상)
5. 저장 → 라벨 출력.

### 2.5 상품코드 작업

바코드 대신 **상품코드(바코드상품코드)** 를 입력해 품목을 찾는다. 이후 흐름은 바코드 작업과 같다.

### 2.6 중량 추출 (품목 타입별)

| 품목 타입 | 중량 | 비고 |
|------|------|------|
| `W` 바코드 계근, `HW` | 바코드의 중량 위치(품목 마스터 중량시작~끝)에서 읽음 | 단위가 LB면 KG로 환산(× 0.453592) 후 버림 |
| `S` 저울 계근 | 바코드에서 읽음 | 같은 환산 |
| `J` 지정 중량 | 출하대상의 박스중량(PACKWEIGHT) 사용 | 바코드에서 중량·제조일·박스시리얼을 읽지 않음 |
| `B` 비정량 | 바코드에서 읽음 | |

LB 환산 후 자릿수: 이마트는 품목 자릿수 기준 버림, 그 외는 소수 2자리 버림.

> 품목 타입은 출하대상 응답 19번 값이다. 실제로 내려오는 값은 이마트 = 매핑 타입구분(`W`), 이마트 비정량 = `HW`, 홈플러스·도매·롯데 = `S`, 홈플러스 비정량 = 매핑 타입구분이다(06 문서 3.2). 조회 조건의 타입구분과 다르다.

### 2.7 저장과 라벨 출력

```
계근 대상 행이 이미 다 찼으면 → "계근이 끝난 지점입니다. 다음 지점을 작업해주세요." (마지막 지점이면 "계근 완료")
  ↓
TB_GOODS_WET 저장 (박스 번호 = 그 행 계근수량 + 1, SAVE_TYPE='F' 미전송)
  ↓
인쇄 스위치 ON이면 마트별 라벨 출력 → 출력한 라벨 값 11개를 같은 행에 다시 저장 (ERP 재출력용)
  ↓
화면 수량·중량 갱신. 센터 전체가 다 차면 "계근 완료 — 모든 지점 계근 완료" → [확인] 시 [전송] 활성화
```

### 2.8 계근 상세 팝업 (목록 행 누르기)

| 기능 | 동작 |
|------|------|
| 목록 | 그 출하대상 행의 계근 내역(박스별 중량) |
| [재출력] (행별) | 그 박스의 라벨을 다시 출력 (롯데는 저장된 박스순번 사용) |
| [삭제] | 체크한 박스를 "정말 삭제하시겠습니까?" 확인 후 로컬에서 삭제, 수량·중량 차감, [전송] 비활성 |
| [합산] | "파렛트당 박스 수"(기본 36) 입력 → 파렛트 단위 합산 라벨. 잘못 입력하면 입력창 다시 표시, 취소 불가 |

### 2.9 전송

- [전송]은 지금 화면에 불러온 출하대상(센터·품목의 작업지점들)의 **미전송('F') 계근**을 보낸다.
- **건별**(이마트·홈플러스·롯데): 한 박스씩 보내고 성공한 박스마다 'Y' 처리.
- **일괄**(이마트비정량·홈플러스비정량·도매): 한 번에 모아 보내고, 성공하면 남은 행까지 모두 'Y' 처리(개발/74).
- 끝나면 "전송 완료 — 다른 상품 계근을 시작하세요." 안내 후 [전송] 비활성. 실패한 박스는 'F'로 남아 다음에 다시 보낼 수 있다.
- 전송 순서: 출고상세 → 출고 LOT → 박스 번호 순(롯데 박스순번 등록 순서 보장).

## 3. 마트별 차이 상세

### 3.1 이마트 (0)
- 정량 품목(`타입구분 W`)만 조회. 창고 조건 적용.
- **저장 중량을 소수 1자리로 버림**(수기·바코드 모두). 누적 계근중량은 소수 1자리 반올림.
- 트레이더스(TRD)·E/T·WET 센터는 품목 마스터에 소비기한 정보가 있어야 계근된다. 수기 입력이면 소비기한 창이 뜬다.
- 라벨: 바코드타입 M0 / M8 / M9 (이마트 라벨), 그 외는 이마트 미등록 라벨. 물류코드가 비어 있으면 `0000000`.
- 건별 전송 → `SM_출고계근`.

### 3.2 이마트 비정량 (4)
- 비정량 품목(`타입구분 B`, 출고수량 > 0)만 조회. 창고 조건 없음. 바코드타입 조건 없음(2026-06-23 해제).
- 비정량은 같은 바코드가 여러 박스에 있을 수 있어 **같은 바코드 다시 스캔을 허용**한다.
- 라벨: M8·M9 (M9는 18자리 비정량 바코드, M8 디자인). 라벨의 납품일자는 현재 `SD.납기일자` 값이다(04 문서 M4).
- 일괄 전송 → `insert_goods_wet_new.jsp`.
- 메인 버튼 이름에 "생산(production)"이 붙어 있지만 **비정량 출하**다(`btnproductionNonfixedlist`, `btnProdNonfixedWet`).

### 3.3 홈플러스 하이퍼 (2)
- 정량 품목만 조회, 창고 조건 적용.
- 저장 때 박스순번을 **로컬 계근 전체의 최대 박스순번 다음 번호**로 매긴다.
- 라벨: H2·H5 (홈플러스 라벨, 폭 576), 그 외 홈플러스 미등록 라벨.
- 건별 전송 → `insert_goods_wet_homeplus.jsp`.

### 3.4 홈플러스 비정량 (5)
- 창고 조건 없음, 타입구분 조건 없음(매핑값을 품목 타입으로 사용). 바코드정보는 `search_homeplus_nonfixed2.jsp`.
- 같은 바코드 다시 스캔 허용.
- 라벨: 홈플러스 라벨(H2·H5).
- 일괄 전송 → `insert_goods_wet_new.jsp`.

### 3.5 도매 (3)
- 원료육(`원료육여부 1`)이면서 마트사구분이 없는 출고를 조회. 창고 조건 적용.
- 계근 화면이 도매 전용 레이아웃(`activity_shipment_wholesale.xml`)으로 열린다.
- **계근 저장 때 라벨을 출력하지 않는다**(원본과 동일). 계근 상세 [재출력]은 이마트 라벨 출력 경로를 탄다.
- 일괄 전송 → `insert_goods_wet_new.jsp`.

### 3.6 롯데 (6)
- 정량 품목만 조회, 창고 조건 적용.
- **박스순번**: 계근 화면에 들어갈 때 출하대상의 서버 마지막 박스순번(`LAST_BOX_ORDER`, 이력이 없으면 0) + 1부터 시작해 저장마다 1씩 늘린다. 9999 다음은 1.
- 수기 입력 시 **항상** 소비기한(제조일자) 입력 창.
- 라벨: L0 (롯데 라벨, 선·테두리 비트맵), 그 외 롯데 미등록 라벨. 박스순번이 라벨에 들어간다.
- 건별 전송 → `insert_goods_wet_lotte.jsp` (`SM_출고계근.박스순번` 적재).
- 알려진 문제: 회사(업체)코드 미출력(ERP 데이터 대기), 중량칸 높이 확장 미적용 — 04 문서 X1·M3.
