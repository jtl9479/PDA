## 2. 공통 흐름

### 2.1 출하대상 받기 (메인 화면)

```
[작업일자 선택] (메뉴 [날짜설정], 안 고르면 오늘)
  → 마트별 [출하대상받기]
       받기 전 로컬 정리: 출하대상·바코드정보 전체, 계근 중 'Y'(서버에서 받은 분·전송 완료분) 삭제 / 미전송 계근('F')은 유지
       ① 출하대상     search_*.jsp                                       → TB_SHIPMENT
       ② 바코드정보   search_barcode_info*.jsp (5는 search_homeplus_nonfixed2.jsp) → TB_BARCODE_INFO
       ③ 기존 계근분  search_goods_wet.jsp                               → TB_GOODS_WET ('Y')
       → "바코드정보가 없는 상품목록" 팝업
  → 같은 마트의 [계근입력시작]
       다른 마트 목록을 받아 둔 상태거나 목록이 비어 있으면 진입 차단
```

- 바코드정보 없는 상품은 스캔으로 품목을 찾을 수 없다. ERP 품목 마스터(`CO_품목코드`)에 바코드 위치 정보를 넣어야 한다(08 문서 2장).
- ③ 덕분에 이미 전송한 출고를 다시 받아도 계근 수량이 채워진 상태로 나온다.
- 진입 차단은 메모리 값(`Common.searchType`, 기본 "0") 기준이다. 앱을 다시 켜면 다른 마트 목록이 남아 있어도 [이마트 계근입력시작]이 통과된다.

### 2.3 바코드 작업 (작업방식 = 바코드)

스캔한 바코드는 **그때의 상태**에 따라 다르게 처리된다.

| 상태 | 처리 | 화면 |
|------|------|------|
| ① 작업 중인 품목이 없을 때 (첫 스캔) | 바코드에서 품목을 찾아(08 문서 3장) 작업 품목으로 정하고 **작업지점 목록만 불러온다. 계근하지 않는다** | 품목을 못 찾으면 빈 품목으로 조회되어 "바코드 정보(조회결과)가 없습니다." 창 + "조회결과가 없습니다." |
| ② 목록을 불러온 직후 다음 스캔 | **품목 확인 없이** 바로 계근 단계로 간다 | — |
| ③ 계근 후 다음 스캔 | 품목을 확인한다. 같은 품목이면 바코드 중복 확인(정량만) 후 계근 단계. **다른 품목**이면 "상품 변경 — 다른 상품을 계근하시겠습니가?" 확인 후 바꾼다 | 중복이면 "이미 스캔한 바코드입니다. 다른 바코드를 스캔하세요." |

**계근 단계**

| 순서 | 동작 | 막히는 경우 |
|:-:|------|------|
| 1 | 선택된 BL번호와 같은 행 중 **계근이 끝나지 않은 첫 행**을 계근 대상으로 정한다 | 맞는 행이 없으면 **아무 반응 없음**(안내 문구 없이 예외로 끝남, 원본 동일) |
| 2 | 소비기한 정보 검사 — ① 킬코이 패커 + 미트센터 지점 ② 이마트이고 센터명이 `용인TRD`·`대구TRD`·`시화(W)_TRD`·`여주TRD`와 **정확히 같거나** `E/T`·`WET` 포함. 품목 마스터에 소비기한·제조일자 위치가 없으면 계근 불가 | "미트센터 납품 - KILKOY 상품의 경우 소비기한정보가 필수로…" / "트레이더스 납품 상품의 경우 소비기한정보가 필수로…" — 이때 작업 품목이 초기화되어 다음 스캔은 ①부터 |
| 3 | 같은 바코드 + 같은 출고상세·패커상품코드·LOT로 이미 계근했는지 확인 (비정량 4·5는 확인 안 함) | 중복이면 차단 |
| 4 | 바코드에서 중량·제조일자·박스시리얼 추출(2.6) → **저장 → 라벨 출력**(2.7) | 품목에 중량 위치가 `0`이면 경고 창 |

> - **첫 박스는 한 번 더 스캔하거나 [입력]을 눌러야 계근된다.** 첫 스캔 바코드는 입력창에 남아 있다. 실기기에서도 같다(테스트/10 "1차 스캔 — 리스트 로딩, 2차 스캔 — 중량 추출", `테스트/증빙/2026-09-28_롯데계근_EDA51/LT04_scan1.png`). 원본 동일. 테스트/04·07의 "첫 스캔에 계근" 서술은 정정이 필요하다.
> - ②의 스캔은 품목을 확인하지 않으므로, 다른 품목 바코드도 현재 품목의 위치 규칙으로 중량을 잘라 현재 품목으로 저장될 수 있다(원본 동일).
> - "패커상품이 존재하지않거나, 바코드가 정확하지 않습니다."는 품목 규칙의 위치값이 숫자가 아닐 때 등 예외로만 뜬다. 이때는 그날 받은 규칙 하나만 깨져도 **모든 스캔이 실패**한다(08 문서 3장).
> - 같은 바코드가 0.5초(수신)·1초(처리) 안에 다시 들어오면 무시한다(스캐너 중복 입력 방지).
> - TRD 센터 판정은 스캔 검사(위 2)만 이름 4개 일치이고, 수기 입력 소비기한 창(2.4)과 라벨 소비기한 문구는 `TRD` 포함 여부로 본다.

### 2.4 수기(중량) 작업

1. 먼저 바코드·상품코드로 품목을 정해 두거나, **수기 모드에서 BL(이력번호) 바코드를 스캔**해 그 BL의 목록을 불러온다.
2. 작업방식을 **수기(중량)** 로 바꾸면 계근이 끝나지 않은 첫 지점이 자동 선택된다.
3. 중량을 입력하고 [입력](또는 Enter).
   - 입력값 확인 순서: 중량 없음 → "중량을 입력하세요." / 지점 없음 → "작업 중인 지점이 없습니다." / 품목 없음 → "상품패커코드가 없습니다." (품목이 정해지지 않았으면 지점도 없으므로 보통 두 번째 문구가 뜬다)
   - 이마트(0)는 입력 중량을 **소수 첫째 자리까지 남기고 버린다.**
4. 아래 경우 **소비기한 입력 화면**(`ExpiryEnterActivity`)이 떠서 제조일자를 받는다.
   - 킬코이 패커 + 미트센터 지점
   - 이마트이고 센터명에 `TRD`·`WET`·`E/T` 포함
   - 롯데 (항상)
5. 저장 → 라벨 출력.

### 2.5 상품코드 작업

입력한 문자열 **전체**를 품목 규칙의 상품바코드와 비교해 품목을 찾고 목록을 불러온다. 목록을 불러온 직후 박스 스캔 한 번은 바로 계근된다(2.3 ②). 그 뒤 박스 바코드를 스캔하면 전체 문자열 비교라 품목이 맞지 않아 "상품 변경" 확인 창이 뜬다. 현장에서는 상품코드로 품목을 정한 뒤 **수기(중량)** 로 바꿔 쓴다.

### 2.6 중량 추출 (품목 타입별)

| 품목 타입 | 중량 | 비고 |
|------|------|------|
| `W` 바코드 계근, `HW` | 바코드의 중량 위치(품목 마스터 중량시작~끝)에서 읽음 | 단위가 LB면 KG로 환산(× 0.453592) 후 버림. 마지막에 소수 첫째 자리까지 남기고 버림 |
| `S` 저울 계근 | 바코드에서 읽음 | 같은 환산, 소수 둘째 자리 반올림 |
| `J` 지정 중량 | 출하대상의 박스중량(PACKWEIGHT) 사용 | 바코드에서 중량·제조일·박스시리얼을 읽지 않음 |
| `B` 비정량 | 바코드에서 읽음 | 소수 둘째 자리 반올림 |
| 그 외 (빈 값 포함) | **경고 없이 중량 0으로 저장** | 홈플러스 비정량은 품목 타입이 매핑 타입구분이라 ERP 값이 비어 있으면 이렇게 된다 |

> 품목 타입은 출하대상 응답 19번 값이다. 실제로 내려오는 값은 이마트 = 매핑 타입구분(`W`), 이마트 비정량 = `HW`, 홈플러스·도매·롯데 = `S`, 홈플러스 비정량 = 매핑 타입구분이다(06 문서 3.2). 조회 조건의 타입구분과 다르다. 이마트 비정량·홈플러스 비정량은 기준단위가 `KG`로 고정되어 LB 환산이 없다.

### 2.7 저장과 라벨 출력

```
계근 대상 행이 이미 다 찼으면 → "계근이 끝난 지점입니다. 다음 지점을 작업해주세요." (마지막 지점이면 "계근 완료")
  ↓
TB_GOODS_WET 저장 (박스 번호 = 그 행 계근수량 + 1, SAVE_TYPE='F' 미전송)
  ↓
인쇄 스위치 ON이면 마트별 라벨 출력 → 출력한 라벨 값 11개를 같은 행에 다시 저장 (ERP 전송용)
   (인쇄 OFF로 저장한 계근은 이 11개가 빈 값으로 전송된다)
  ↓
화면 수량·중량 갱신. 선택 센터의 현재 품목이 모두 차면 "계근 완료 — 모든 지점 계근 완료" → [확인] 시 [전송] 활성화
```

### 2.8 계근 상세 팝업 (행 선택 → [선택])

| 기능 | 동작 |

| 목록 | 그 출하대상 행의 계근 내역(박스별 중량) |
| [재출력] (행별) | 그 박스의 라벨을 다시 출력 (롯데는 저장된 박스순번 사용) |
| [삭제] | 체크한 박스를 "정말 삭제하시겠습니까?" 확인 후 로컬에서 삭제, 수량·중량 차감, [전송] 비활성 |
| [합산] | "파렛트당 박스 수"(기본 36) 입력 → 파렛트 단위 합산 라벨. 0·공백이면 입력창 다시 표시. [취소] 버튼은 있고, 뒤로가기·바깥 터치로는 닫히지 않음 |

> 바코드 작업 중 팝업을 열었다 닫으면 작업 품목이 비워져 목록이 다시 조회되며 "조회결과가 없습니다."가 뜬다. 다음 스캔은 첫 스캔(2.3 ①)으로 처리된다(원본 동일). 수기·상품코드 작업은 BL로 다시 조회해 목록이 유지된다.

### 2.9 전송

- [전송]은 지금 화면에 불러온 출하대상(선택 센터·현재 품목의 작업지점들)의 **미전송('F') 계근**을 보낸다.
- **건별**(이마트·홈플러스·롯데): 한 박스씩 보내고 성공한 박스마다 'Y' 처리. 실패 응답을 받으면 거기서 멈춘다.
- **일괄**(이마트비정량·홈플러스비정량·도매): 한 번에 모아 보내고, 성공하면 남은 행까지 모두 'Y' 처리(개발/74). 서버는 행마다 바로 저장하므로 중간에 실패하면 앞 행은 서버에 남고 PDA는 'F'로 남아, 다시 보낼 때 중복될 수 있다(06 문서 1장).
- 불러온 모든 행이 요청 수량만큼 전송되면 "전송 완료 — 다른 상품 계근을 시작하세요." 후 [전송] 비활성. 그렇지 않으면 "결과 s, 전송 성공." 토스트만 뜨고 버튼은 그대로다. 목록을 다시 불러온 뒤 전송하면 완료 창이 뜨지 않을 수 있다(원본과 같은 집계 쿼리).
- 실패한 박스는 'F'로 남아 다음에 다시 보낼 수 있다.
- 전송 순서: 출고상세 → 출고 LOT → 박스 번호 순(롯데 박스순번 등록 순서 보장).

## 3. 마트별 차이 상세

### 3.1 이마트 (0)
- 정량 품목(`타입구분 W`)만 조회. 창고 조건 적용.
- **저장 중량을 소수 첫째 자리까지 남기고 버림**(수기·바코드 모두). 누적 계근중량은 소수 첫째 자리 반올림.
- 트레이더스·E/T·WET 센터는 품목 마스터에 소비기한 정보가 있어야 계근된다(스캔 검사의 TRD는 4개 센터명 일치). 수기 입력이면 소비기한 창이 뜬다.
- 라벨: 바코드타입 M0 / M8 / M9 (이마트 라벨), 그 외는 이마트 미등록 라벨. 물류코드가 비어 있으면 `0000000`.
- 건별 전송 → `SM_출고계근`.

### 3.2 이마트 비정량 (4)
- 비정량 품목(`타입구분 B`)만 조회. 창고 조건 없음. 바코드타입 조건 없음(2026-06-23 해제).
- 비정량은 같은 바코드가 여러 박스에 있을 수 있어 **같은 바코드 다시 스캔을 허용**한다.
- 품목 찾기는 받아 둔 규칙 전체를 후보로 삼아 선택 센터의 비정량 출하대상 전 품목이 목록에 올라온다. 계근할 행은 선택 작업지점의 BL로 정해진다(08 문서 3장).
- 라벨: M8·M9 (M9는 18자리 비정량 바코드, M8 디자인). 라벨의 납품일자는 현재 `SD.납기일자` 값이다(04 문서 M4).
- 일괄 전송 → `insert_goods_wet_new.jsp`.
- 메인 버튼 이름에 "생산(production)"이 붙어 있지만 **비정량 출하**다(`btnproductionNonfixedlist`, `btnProdNonfixedWet`).

### 3.3 홈플러스 하이퍼 (2)
- 정량 품목만 조회, 창고 조건 적용.
- 저장 때 박스순번 = **오늘(기기 날짜) 저장한 홈플러스 계근(`CLIENT_TYPE '06'`)의 최대 박스순번 + 1**.
- 라벨: H2·H5 (홈플러스 라벨, 폭 576), 그 외 홈플러스 미등록 라벨.
- 건별 전송 → `insert_goods_wet_homeplus.jsp`.

### 3.4 홈플러스 비정량 (5)
- 매핑 바코드타입 `H5`인 출고만 조회. 창고 조건 없음. 바코드정보는 `search_homeplus_nonfixed2.jsp`.
- 품목 타입은 매핑 타입구분 값을 쓴다(비어 있으면 중량 0 — 2.6).
- 같은 바코드 다시 스캔 허용.
- 라벨: 홈플러스 라벨(H5). 지점코드 칸은 품목 타입이 `B`일 때만 점포코드가 찍힌다(07 문서 3장).
- 일괄 전송 → `insert_goods_wet_new.jsp`.

### 3.5 도매 (3)
- 원료육(`원료육여부 1`)이면서 마트사구분이 없는 출고를 조회. 창고 조건 적용.
- 계근 화면이 도매 전용 레이아웃(`activity_shipment_wholesale.xml`)으로 열린다.
- **계근 저장 때 라벨을 출력하지 않는다**(원본과 동일). 계근 상세 [재출력]은 이마트 출력 경로를 타며, 바코드타입이 `NA`라 **이마트 미등록 라벨에 중량 0.0 KG**로 나간다(원본과 같은 경로).
- 일괄 전송 → `insert_goods_wet_new.jsp`.

### 3.6 롯데 (6)
- 정량 품목만 조회, 창고 조건 적용.
- **박스순번**: 작업지점 목록을 **불러올 때마다** 다시 계산한다.
  - 시작값 = 서버 마지막 박스순번(`LAST_BOX_ORDER` — 패커상품코드 기준 전체 이력의 연속 순번 마지막 값, 없으면 0) + 1 + **불러온 목록의 계근수량 합**. 9999를 넘으면 9999로 나눈 나머지.
  - 저장마다 1씩 늘리고, 9999 다음은 1.
  - 전송 후 출하대상을 다시 받으면 서버 마지막 순번과 다시 받은 계근 수가 겹쳐 번호가 건너뛸 수 있다(원본과 같은 식).
- 수기 입력 시 **항상** 소비기한(제조일자) 입력 창.
- 라벨: L0 (롯데 라벨, 선·테두리 비트맵), 그 외 롯데 미등록 라벨. 박스순번이 라벨 바코드에 들어간다.
- 건별 전송 → `insert_goods_wet_lotte.jsp` (`SM_출고계근.박스순번` 적재).
- 알려진 문제: 회사(업체)코드 미출력(ERP 데이터 대기), 중량칸 높이 확장 미적용 — 04 문서 X1·M3.
