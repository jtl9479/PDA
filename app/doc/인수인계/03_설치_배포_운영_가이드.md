## 2. APK 빌드

### 2.1 스크립트로 빌드
프로젝트 루트의 `build_apk.bat`을 실행한다.

```
1단계: gradlew.bat clean
2단계: gradlew.bat assembleDebug
결과물: app\build\outputs\apk\debug\app-debug.apk
```

### 2.2 명령으로 직접 빌드
```
cd D:\PDA\PDA-INNO
gradlew.bat clean assembleDebug
```

### 2.3 빌드 종류와 서명
- `app/build.gradle`에는 **debug 빌드만** 있다. release 설정(`:30-42`)은 주석 처리돼 있다.
- 따라서 APK는 빌드한 PC의 Android 디버그 키(`C:\Users\user\.android\debug.keystore`, `CN=Android Debug`)로 서명된다.
- **다른 PC에서 빌드하면 키가 달라져** 이미 설치된 PDA에 업데이트 설치가 되지 않는다. 앱을 지우고 다시 깔아야 하며, 이때 PDA의 로컬 데이터(미전송 계근 포함)가 지워진다.
- 키 방식 결정과 백업은 `02_운영_전환_체크리스트` B1·B2 항목에서 처리한다.

### 2.4 버전
배포할 때마다 `app/build.gradle`의 `versionCode`를 올린다(현재 4 / `versionName` 1.00). versionCode가 이전보다 작거나 같으면 업데이트 설치가 거부된다.

## 3. PDA(Honeywell EDA51) 준비와 설치

### 3.1 기기 설정 (기기마다 1회)

| 순서 | 설정 | 방법 |
|:-:|------|------|
| 1 | 개발자 옵션 · USB 디버깅 | 설정 → 휴대전화 정보 → 빌드번호 7회 터치 → 개발자 옵션 → USB 디버깅 ON |
| 2 | **스캐너 Intent 출력** | 설정 → Honeywell Settings → Scan Settings → Internal Scanner → Default profile → Data Processing Settings → **Scan To Intent 활성화** |
| 3 | 블루투스 | ON (꺼져 있으면 계근 화면 진입 시 앱이 켜기 요청) |
| 4 | 날짜·시간 | 자동 설정 확인 (작업일자를 선택하지 않으면 기기 날짜로 조회한다) |

> 2번이 꺼져 있으면 스캔해도 앱이 바코드를 받지 못한다. 앱은 `com.honeywell.intent.action.SCAN_RESULT` 방송을 받아 처리하고, 같은 바코드가 0.5초 안에 다시 들어오면 무시한다(`scanner/HoneywellScannerActivity.java`).

### 3.2 앱 설치

**방법 1 — 스크립트 (빌드 + 설치 + 실행)**
PDA를 USB로 연결하고 루트의 `install_to_pda.bat` 실행 → `adb devices` 확인 → `gradlew clean` → `gradlew installDebug` → 실행 여부 선택.
`adb`가 PATH에 있어야 한다(SDK `platform-tools`).

**방법 2 — APK 직접 설치**
```
C:\Users\user\AppData\Local\Android\Sdk\platform-tools\adb.exe devices
C:\Users\user\AppData\Local\Android\Sdk\platform-tools\adb.exe install -r app-debug.apk
```
- `-r`: 기존 앱을 데이터 유지한 채 덮어쓰기
- 이전 버전으로 되돌릴 때는 `-r -d` (버전 낮추기 허용)

### 3.3 설치 후 확인
1. 앱 이름 "(주)하이랜드이노베이션" 실행 → 로그인 화면에 창고 목록이 나오는지
2. 로그인 → 메인 화면 → 작업일자 표시 확인
3. 스캐너 버튼을 눌러 계근 화면에서 바코드가 들어오는지

## 4. 라벨 프린터(BIXOLON SPP-L3000) 연결

### 4.1 처음 연결
1. 프린터 전원 ON, PDA 블루투스 설정에서 프린터를 **페어링**한다.
2. 앱 메인 화면에서 마트별 [계근입력시작] → 계근 화면에 들어간다.
3. 저장된 프린터 주소가 없으면 **프린터 선택 화면**(`DeviceListActivity`)이 뜬다. 페어링 목록에서 고르거나 [검색]으로 찾는다.
4. 고른 프린터 주소가 저장되고, 다음부터는 계근 화면에 들어갈 때 자동으로 연결한다.

> 이 앱을 처음 설치한 기기는 계근 화면 첫 진입 때 예전(Woosim) 프린터 주소를 한 번 지운다(`bixolon_initialized` 플래그). 그래서 처음에는 반드시 선택 화면이 뜬다.

### 4.2 연결 방식
- 블루투스 SPP(`00001101-0000-1000-8000-00805F9B34FB`)로 소켓을 열고, 실패하면 다른 방식으로 두 번 더 시도한다(`print/BixolonSocketPrinter.java`).
- BIXOLON SDK를 쓰지 않고 **SLCS 명령 문자열을 직접 보낸다.** 글자는 앱이 `assets/Korail.ttf`로 비트맵을 만들어 보낸다(`print/LabelPrintHelper.java`).
- 라벨 크기는 라벨마다 앱이 명령으로 지정한다. 용지·센서 등 프린터 자체 설정은 BIXOLON 유틸리티로 한다(`참고자료/Manual_Windows_BIXOLON_Utility_KOR_V1.09.pdf`, `라벨/Manual_Mobile_LabelPrinter_SLCS_KOR_V1.00[3].pdf`).

### 4.3 프린터 켜고 끄기

| 위치 | 동작 | 유지 범위 |
|------|------|------|
| 메인 메뉴 [프린터설정] → ON/OFF | 프린터 사용 여부 저장. **OFF로 하면 저장된 프린터 주소도 지운다** | 앱을 다시 켜도 유지 |
| 계근 화면 상단 인쇄 스위치 | 라벨 출력만 잠시 끈다. 계근 저장은 그대로 된다 | 다음 로그인 때 [프린터설정] 값으로 돌아감 |

### 4.4 프린터를 바꿀 때
메인 메뉴 [프린터설정]에서 OFF → ON으로 바꾸면 저장된 주소가 지워진다. 새 프린터를 페어링한 뒤 계근 화면에 들어가면 선택 화면이 다시 뜬다.

## 5. 서버 (Tomcat · JSP)

### 5.1 구성

| 항목 | 값 | 위치 |
|------|------|------|
| Tomcat | 8.5.29 | `D:\PDA\apache-tomcat-8.5.29\apache-tomcat-8.5.29` (개발 PC) |
| 포트 | 4040 (HTTP) | `conf/server.xml` |
| 실행 JDK | `JAVA_HOME` = `D:\SUNIN_ERP\jdk-1.8` (개발 PC 환경변수) | |
| JDBC 드라이버 | `lib/mssql-jdbc-10.2.1.jre8.jar` | `ojdbc6.jar`(Oracle)는 원본 시절 파일로 현재 미사용 |
| JSP 위치 | `webapps/ROOT/inno/` — 업무 JSP 20개 + `common/db_connection.jsp` | 모든 JSP가 `<%@ include file="common/db_connection.jsp" %>`로 DB에 접속 |
| 앱에서 부르는 주소 | `http://<서버>:4040/inno/<JSP명>.jsp` | 앱 `Common.BASE_URL` |
| 운영서버 | `175.120.155.125:4040` | 이번 개발에서 접속·확인하지 않음 |

### 5.2 시작·종료
- 시작: `bin\startup.bat`
- 종료: `bin\shutdown.bat`
- JSP만 고친 경우 재시작 없이 파일을 바꾸면 다음 요청 때 다시 컴파일된다. 컴파일된 파일은 `work/` 아래에 생긴다.

### 5.3 JSP 배포 순서
1. JSP 저장소(`github.com/jtl9479/apache8.5`)에 변경을 커밋한다.
2. 대상 서버의 `webapps/ROOT/inno/` 기존 파일을 백업한다.
3. 바뀐 JSP 파일을 같은 경로에 복사한다. `common/db_connection.jsp`는 **서버별 접속 정보가 들어 있으므로** 덮어쓰기 전에 내용을 비교한다.
4. 앱에서 해당 기능을 한 번 실행해 확인한다.

### 5.4 로그
| 로그 | 위치 | 내용 |
|------|------|------|
| JSP 실행 로그 | Tomcat 실행 콘솔 (`startup.bat` 창) | JSP의 `System.out.println` — 예: `##search_shipment query :`, `##manager_login result :` |
| 오류 로그 | `logs/localhost.<날짜>.log`, `logs/catalina.<날짜>.log` | JSP 컴파일 오류, 예외 |

## 6. 앱 일상 운영

### 6.1 작업일자
- 메인 화면 [날짜] 버튼 또는 메뉴 [날짜설정]으로 고른다.
- 고르지 않고 [출하대상받기]를 누르면 오늘(기기 날짜)로 조회한다.

### 6.2 PDA 로컬 데이터

PDA는 받은 데이터와 계근 결과를 앱 내부 SQLite(`HIGHLAND`)에 둔다.

| 상황 | 지워지는 것 | 남는 것 |
|------|------|------|
| [출하대상받기] | 출하대상·바코드정보 전체, 계근 중 서버에서 받은 행(`SAVE_TYPE='Y'`) | **미전송 계근(`'F'`)** |
| [계근대상삭제] 버튼 | 출하대상(`TB_SHIPMENT`)만 | 바코드정보, 계근 전부 |
| 메뉴 [계근내역 삭제] / [프린터설정] 이미지 7회 터치 | **계근 전체 (미전송 포함)** | 출하대상, 바코드정보 |
| 앱 삭제 · 서명 키 변경으로 재설치 | **전부** | 없음 |

> 전송이 성공한 계근은 `'Y'`로 바뀌고 다음 [출하대상받기] 때 정리된다. 따라서 평소에는 따로 지울 필요가 없다.
> **미전송 계근이 지워지는 작업(위 표 굵은 글씨) 전에는 반드시 [전송]을 먼저 한다.**

### 6.3 앱 로그 보기
PDA를 USB로 연결하고:
```
adb logcat | findstr BixolonShipmentActivity
```
`Common.D = true`일 때 조회·스캔·전송 과정이 자세히 찍힌다. 로그인 비밀번호도 평문으로 찍히므로 로그 파일을 외부에 넘기지 않는다.
