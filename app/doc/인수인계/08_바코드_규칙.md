## 2. 품목 바코드 규칙 (`CO_품목코드` → `TB_BARCODE_INFO`)

[출하대상받기] 때 출하대상 품목의 규칙을 받아 둔다(06 문서 4장). 위치는 **1부터 세는 자리 번호, 시작·끝 모두 포함**이다.

| ERP 컬럼 | 앱 필드 | 뜻 |
|------|------|------|
| `상품바코드` | BARCODEGOODS | 박스 바코드 안에 들어 있는 상품 식별 문자열 |
| `바코드상품코드시작` / `끝` | BARCODEGOODS_FROM / TO | 박스 바코드에서 상품 식별 문자열의 자리 |
| `중량시작` / `끝` | WEIGHT_FROM / TO | 중량 숫자의 자리 |
| `소수점` | ZEROPOINT | 중량 숫자의 소수 자릿수 (예: 2면 `01285` → 12.85) |
| `기준단위` | BASEUNIT | `LB`면 KG로 환산 |
| `제조일자시작` / `끝` | MAKINGDATE_FROM / TO | 제조일자(YYMMDD) 자리 |
| `박스시리얼시작` / `끝` | BOXSERIAL_FROM / TO | 박스시리얼 자리 |
| `적용단위`·`적용값` | SHELF_LIFE | 소비기한 일수 (적용단위 1 = 년×365, 2 = 월×30, 그 외 = 일). 비정량(4·5)은 받지 않음 |
| `ppCode` | PACKER_PRODUCT_CODE | 출하대상과 품목을 잇는 키 |

> - `바코드상품코드끝`이 비어 있는 품목은 스캔 매칭 대상에서 빠진다(`selectqueryBarcodeInfo`의 `BARCODEGOODS_TO != ''`).
> - 비정량(4·5) 바코드정보는 `상품바코드`·`ppCode` 자리에 **품목코드**를 넣어 내려준다.
> - [출하대상받기] 뒤 "바코드정보 없는 상품" 팝업에 나온 품목은 규칙이 없어 스캔으로 계근할 수 없다.

## 3. 품목 찾기

| 작업방식 | 방법 |
|------|------|
| **바코드** | 받아 둔 규칙을 하나씩 대보며, 스캔한 바코드의 `바코드상품코드시작~끝` 자리를 잘라 `상품바코드`와 같은지 본다. 바코드가 `끝` 자리보다 짧으면 그 규칙은 건너뛴다 |
| **상품코드** | 입력한 문자열 전체를 `상품바코드`와 비교한다(자르지 않음) |

- 같은 자리에 같은 문자열을 가진 품목이 여럿이면 **모두 후보**가 된다. 앱은 후보 패커상품코드 전체로 출하대상을 다시 조회한다.
- **이마트 비정량(4)은 일치 여부와 관계없이 받아 둔 규칙 전체를 후보로 삼는다**(`acceptsAnyBarcodeInfoRow`, 원본 동작). 그래서 실제 품목 구분은 출하대상 조회 결과로 정해진다. 최신 원본은 품목코드 **앞 6자리 비교**로 바꿨으나 아직 반영하지 않았다(04 문서 M1).
- 아무 품목도 맞지 않으면 "패커상품이 존재하지않거나, 바코드가 정확하지 않습니다."

## 4. 중량·제조일자·박스시리얼 추출

품목 타입(출하대상 응답 19번 ITEM_TYPE)에 따라 다르다. 실제 값은 이마트 = 매핑(`W`), 이마트 비정량 = `HW`, 홈플러스·도매·롯데 = `S`, 홈플러스 비정량 = 매핑값이다(06 문서 3.2).

| 품목 타입 | 중량 | LB일 때 | 마지막 자릿수 |
|------|------|------|------|
| `W` 바코드 계근, `HW` | `중량시작~끝` 숫자 ÷ 10^소수점 | × 0.453592 후 소수점 자릿수로 버림 | **소수 1자리 버림** |
| `S` 저울 계근 | 같음 | × 0.453592 후 버림 (이마트는 소수점 자릿수, 그 외 소수 2자리) | 소수 2자리 반올림 |
| `B` 비정량 | 같음 | `S`와 같음 | 소수 2자리 반올림 |
| `J` 지정 중량 | 바코드를 읽지 않고 박스중량(PACKWEIGHT) 사용 | — | — |

- 제조일자(YYMMDD)·박스시리얼은 위치값으로 잘라 낸다(`J` 제외).
- **위치값이 비어 있거나 `0`이면 자르는 중 예외가 나서 계근되지 않는다.** 화면에 안내 없이 스캔이 무시된 것처럼 보이므로, 이때는 품목 마스터 위치값을 먼저 확인한다. 원본과 같은 코드다.
- 중량 위치가 `0`이면 계근 전에 "중량 위치" 경고 창이 뜬다.
- 수기 입력은 이 규칙을 타지 않는다. 이마트만 입력값을 소수 1자리로 버리고, 나머지는 입력값 그대로 저장한다(05 문서 2.4).

## 5. 같은 바코드 다시 스캔 (중복 확인)

| 시점 | 확인 방법 | 결과 |
|------|------|------|
| 작업 중인 품목이 없을 때 첫 스캔 | 확인 결과를 쓰지 않음 | 그대로 진행 (원본도 주석 처리 — 오류/01, 기능/10) |
| 같은 품목을 다시 스캔 | 로컬 계근에 **같은 바코드**가 있는지 | 있으면 "이미 스캔한 바코드입니다." |
| 계근 직전 | 같은 바코드 + 같은 출고상세·패커상품코드·LOT | 있으면 차단 |

- **비정량(4·5)은 중복 확인을 하지 않는다.** 한 품목의 박스들이 같은 바코드를 쓸 수 있기 때문이다.
- 로컬 계근 기준이라 다른 PDA에서 계근한 박스는 [출하대상받기]로 서버 계근분을 받아 와야 걸린다.
- 스캐너가 같은 바코드를 0.5초(수신)·1초(처리) 안에 두 번 보내면 한 번만 처리한다.

## 6. 바코드타입 (라벨 양식)

ERP `CO_매출처품목코드매핑.바코드타입`을 하위 거래처 → 최상위 거래처 순으로 찾은 값이다.

| 타입 | 마트 | 라벨 | 비고 |
|:-:|------|------|------|
| M0 | 이마트 정량 | 상품 바코드 = 상품코드6 + 중량6 + 회사코드 + 이력번호 | 미트센터 지점이면 추가 라벨 |
| M8 | 이마트 (주로 비정량) | M0와 같은 바코드 | |
| M9 | 이마트 비정량 | 상품코드6 + 중량6 + 회사코드 (18자리) | 2026-04-30 재정의. 정량 M9(30자리) 폐지 |
| H2 | 홈플러스 정량 | 바코드 없음 | |
| H5 | 홈플러스 비정량 | 바코드 없음 (H2와 같은 배치) | |
| L0 | 롯데 | 업체코드 + 제조일자 + 중량4 + 상품코드6 + 박스순번4, 이력번호 바코드 | |

- 위 6종 외 값(M1·M3·M4·E0~E3·P0 등)은 분기를 삭제했다(2026-10-06). 들어오면 마트별 **미등록 라벨**로 출력된다.
- 도매는 `NA`로 내려온다(저장 시 라벨 없음).
- 원본의 "저울센터 + 품목조건이면 M9로 강제 전환"은 쓰지 않는다. 필요하면 매핑에 M9를 직접 등록한다(2026-10-12 결정).
- 라벨 좌표·구성 상세는 07 문서.

## 7. 이력번호(BL)

- 출하대상의 `BL_NO`와 `IMPORT_ID_NO`(수입식별번호)는 모두 ERP **`SM_출고LOT.이력번호`** 다.
- 계근 화면의 BL번호 목록과 작업지점 목록("거래처명 / 수입식별번호")이 이 값으로 만들어진다. 스캔한 박스는 선택된 BL번호의 행 중 계근이 남은 첫 행에 들어간다.
- 라벨: 이마트 M0·M8은 상품 바코드 끝에, 롯데는 별도 바코드로, 홈플러스는 중량 옆에 끝 4자리를 찍는다.

## 8. 현장 문제 해결

| 증상 | 먼저 볼 것 |
|------|------|
| "패커상품이 존재하지않거나…" | ① "바코드정보 없는 상품" 팝업에 있는지 ② `바코드상품코드시작/끝`·`상품바코드` 값 ③ 바코드 길이가 `끝` 자리보다 짧은지 |
| 스캔해도 아무 반응 없음 | ① 스캐너 Intent 출력 설정(03 문서) ② 품목 마스터 제조일자·박스시리얼·중량 위치값 |
| 중량이 10배·100배로 나옴 | `소수점` 값 |
| 중량이 이상하게 작음 | `기준단위`가 `LB`로 되어 있는지 |
| 소비기한 정보 필수 안내 | 품목 마스터 제조일자 위치·소비기한(적용단위·적용값) |
| 다른 품목으로 계근됨 | 같은 자리·같은 문자열을 가진 품목이 여럿인지 (3장) |
