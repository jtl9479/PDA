## 2. 품목 바코드 규칙 (`CO_품목코드` → `TB_BARCODE_INFO`)

[출하대상받기] 때 출하대상 품목의 규칙을 받아 둔다(06 문서 4장). 위치는 **1부터 세는 자리 번호, 시작·끝 모두 포함**이다.

| ERP 컬럼 | 앱 필드 | 뜻 |
|------|------|------|
| `상품바코드` | BARCODEGOODS | 박스 바코드 안에 들어 있는 상품 식별 문자열 |
| `바코드상품코드시작` / `끝` | BARCODEGOODS_FROM / TO | 박스 바코드에서 상품 식별 문자열의 자리 |
| `중량시작` / `끝` | WEIGHT_FROM / TO | 중량 숫자의 자리 |
| `소수점` | ZEROPOINT | 중량 숫자의 소수 자릿수 (예: 2면 `01285` → 12.85) |
| `기준단위` | BASEUNIT | `LB`면 KG로 환산. 비정량(4·5)은 JSP가 `KG`로 고정해 보내 환산이 없다 |
| `제조일자시작` / `끝` | MAKINGDATE_FROM / TO | 제조일자(YYMMDD) 자리 |
| `박스시리얼시작` / `끝` | BOXSERIAL_FROM / TO | 박스시리얼 자리 |
| `적용단위`·`적용값` | SHELF_LIFE | 소비기한 일수 (적용단위 1 = 년×365, 2 = 월×30, 그 외 = 일). 비정량(4·5)은 받지 않음 |
| `ppCode` | PACKER_PRODUCT_CODE | 출하대상과 품목을 잇는 키 |

> - `바코드상품코드끝`이 비어 있는 품목은 스캔 매칭 대상에서 빠진다(`selectqueryBarcodeInfo`의 `BARCODEGOODS_TO != ''`).
> - 비정량(4·5) 바코드정보는 `상품바코드`·`ppCode` 자리에 **품목코드**를 넣어 내려준다.
> - [출하대상받기] 뒤 "바코드정보가 없는 상품목록" 팝업에 나온 품목은 규칙이 없어 스캔으로 계근할 수 없다.
> - 로컬에 저장할 때 빈 값·`null`은 모두 빈 문자열로 바뀐다(`Common.nullCheck`).

## 3. 품목 찾기

| 작업방식 | 방법 |
|------|------|
| **바코드** | 받아 둔 규칙을 하나씩 대본다. 스캔한 바코드가 `끝` 자리보다 길거나 같으면 `바코드상품코드시작~끝` 자리를 잘라, 짧으면 **바코드 전체**를 `상품바코드`와 비교한다 (그래서 바코드 작업에서도 상품바코드 문자열만 넣으면 맞는다) |
| **상품코드** | 입력한 문자열 전체를 `상품바코드`와 비교한다(자르지 않음) |

- 맞은 규칙의 패커상품코드가 작업 품목이 된다. 같은 문자열을 가진 품목이 여럿이면 **모두 후보**가 되어 그 전체로 출하대상을 조회하고, 계근에 쓰는 위치 규칙은 **마지막으로 맞은 품목의 것**이다.
- **이마트 비정량(4)은 일치 여부와 관계없이 받아 둔 규칙 전체를 후보로 삼는다**(`acceptsAnyBarcodeInfoRow`). 그래서 선택 센터의 비정량 출하대상 전 품목이 목록에 올라오고, 계근할 행은 선택 작업지점의 BL로 정해진다. 위치 규칙은 바코드정보의 **마지막 행** 것을 쓰고, 후보가 늘 같아 "상품 변경" 확인 창도 뜨지 않는다. 최신 원본은 패커상품코드(비정량은 품목코드와 같음) **앞 6자리 비교**로 바꿨으나 아직 반영하지 않았다(04 문서 M1).
- 맞는 규칙이 없으면 빈 품목으로 조회되어 "바코드 정보(조회결과)가 없습니다." 창과 "조회결과가 없습니다."가 뜬다. 작업 중인 품목이 있으면 "상품 변경" 확인 창이 뜬다.
- "패커상품이 존재하지않거나, 바코드가 정확하지 않습니다."는 규칙의 위치값이 숫자가 아닌 경우 등 **비교 중 예외**가 날 때만 뜬다. 이때는 그날 받은 규칙 중 하나만 깨져도 **모든 스캔이 실패**한다.

## 4. 중량·제조일자·박스시리얼 추출

품목 타입(출하대상 응답 19번 ITEM_TYPE)에 따라 다르다. 실제 값은 이마트 = 매핑(`W`), 이마트 비정량 = `HW`, 홈플러스·도매·롯데 = `S`, 홈플러스 비정량 = 매핑값이다(06 문서 3.2).

| 품목 타입 | 중량 | LB일 때 | 마지막 자릿수 |
|------|------|------|------|
| `W` 바코드 계근, `HW` | `중량시작~끝` 숫자 ÷ 10^소수점 | × 0.453592 후 소수점 자릿수로 버림 | **소수 첫째 자리까지 남기고 버림** |
| `S` 저울 계근 | 같음 | × 0.453592 후 버림 (이마트는 소수점 자릿수, 그 외 소수 2자리) | 소수 둘째 자리 반올림 |
| `B` 비정량 | 같음 | `S`와 같음 | 소수 둘째 자리 반올림 |
| `J` 지정 중량 | 바코드를 읽지 않고 박스중량(PACKWEIGHT) 사용 | — | — |
| 그 외 (빈 값 포함) | **경고 없이 중량 0** | — | — |

**위치값이 비었거나 잘못됐을 때**

| 위치값 | 결과 |
|------|------|
| 제조일자·박스시리얼 위치가 **빈 값** | 그 값만 건너뛰고 **정상 계근** (제조일자·박스시리얼이 빈 채 저장) |
| 제조일자·박스시리얼 위치가 **`0`** | 자르는 중 예외 → **아무 반응 없음** |
| 중량 위치가 **`0`** | "중량 위치" 경고 창 → 이어서 예외 → 계근 안 됨 |
| 중량 위치가 **빈 값** | 경고 없이 예외 → **아무 반응 없음** |

- 수기 입력은 이 규칙을 타지 않는다. 이마트만 입력값을 소수 첫째 자리까지 남기고 버리고, 나머지는 입력값 그대로 저장한다(05 문서 2.4).

## 5. 같은 바코드 다시 스캔 (중복 확인)

스캔이 어느 상태에서 들어왔는지에 따라 다르다(05 문서 2.3).

| 상태 | 확인 방법 | 결과 |
|------|------|------|
| 작업 중인 품목이 없을 때 첫 스캔 | 확인 안 함 | 목록만 불러옴 (원본도 확인 결과를 주석 처리 — 오류/01, 기능/10) |
| 목록을 불러온 직후 스캔 | 아래 계근 직전 확인만 | |
| 계근 후 같은 품목을 다시 스캔 | 로컬 계근에 **같은 바코드**가 있는지 | 있으면 "이미 스캔한 바코드입니다." |
| 계근 직전 | 같은 바코드 + 같은 출고상세·패커상품코드·LOT | 있으면 차단 |

- **비정량(4·5)은 중복 확인을 하지 않는다.** 한 품목의 박스들이 같은 바코드를 쓸 수 있기 때문이다.
- 로컬 계근 기준이라 다른 PDA에서 계근한 박스는 [출하대상받기]로 서버 계근분을 받아 와야 걸린다.
- 스캐너가 같은 바코드를 0.5초(수신)·1초(처리) 안에 두 번 보내면 한 번만 처리한다.

## 6. 바코드타입 (라벨 양식)

ERP `CO_매출처품목코드매핑.바코드타입`을 출고거래처(M1) → 최상위 거래처(M2) 순으로 찾은 값이다.

| 타입 | 마트 | 라벨 | 비고 |
|:-:|------|------|------|
| M0 | 이마트 정량 | 상품 바코드 = 상품코드6 + 중량6 + 회사코드 + 이력번호 | 미트센터 지점(`9231`)이고 물류코드가 `0000000`이 아니면 추가 라벨 1장 (07 문서 2.4) |
| M8 | 이마트 (주로 비정량) | M0와 같은 바코드 | |
| M9 | 이마트 비정량 | 상품코드6 + 중량6 + 회사코드 (18자리) | 2026-04-30 재정의. 정량 M9(30자리) 폐지 |
| H2 | 홈플러스 정량 | 바코드 없음 | |
| H5 | 홈플러스 비정량 | 바코드 없음 (H2와 같은 배치) | 홈플러스 비정량은 H5만 조회됨 |
| L0 | 롯데 | 업체코드 + 제조일자 + 중량4 + 상품코드6 + 박스순번4, 이력번호 바코드 | |

- 위 6종 외 값(M1·M3·M4·E0~E3·P0 등)은 분기를 삭제했다(2026-10-06). 들어오면 마트별 **미등록 라벨**로 출력된다.
- 도매는 `NA`로 내려온다(저장 시 라벨 없음).
- 원본의 "저울센터 + 품목조건이면 M9로 강제 전환"은 쓰지 않는다. 필요하면 매핑에 M9를 직접 등록한다(2026-10-12 결정).
- 라벨 좌표·구성 상세는 07 문서.

## 7. 이력번호(BL)

- 출하대상의 `BL_NO`와 `IMPORT_ID_NO`(수입식별번호)는 모두 ERP **`SM_출고LOT.이력번호`** 다.
- 작업지점 목록("거래처명 / 수입식별번호")이 이 값으로 만들어지고, BL번호 칸에는 **선택된 작업지점의 BL 1건**이 들어간다. 스캔한 박스는 그 BL의 행 중 계근이 남은 첫 행에 들어간다.
- 수기 작업에서는 BL(이력번호) 바코드를 스캔해 그 BL의 목록을 불러올 수 있다.
- 라벨: 이마트 M0·M8은 상품 바코드 끝에, 롯데는 별도 바코드로, 홈플러스는 중량 옆에 **9~12번째 자리**(12자리면 끝 4자리)를 찍는다. 12자리보다 짧으면 홈플러스 라벨이 출력되지 않는다.

## 8. 현장 문제 해결

| 증상 | 먼저 볼 것 |
|------|------|
| "바코드 정보(조회결과)가 없습니다" / "조회결과가 없습니다" | ① "바코드정보가 없는 상품목록" 팝업에 있는지 ② `바코드상품코드시작/끝`·`상품바코드` 값 ③ 선택한 센터에 그 품목 출하대상이 있는지 |
| "패커상품이 존재하지않거나…" (모든 스캔 실패) | 그날 받은 품목 규칙 중 위치값이 숫자가 아닌 것 |
| 스캔해도 아무 반응 없음 | ① 스캐너 Intent 출력 설정(03 문서) ② 선택 BL에 계근이 남은 행이 있는지 ③ 품목 마스터 제조일자·박스시리얼 위치가 `0`인지, 중량 위치가 비었는지 |
| 첫 박스가 계근되지 않음 | 정상 동작. 첫 스캔은 목록만 불러온다 — 한 번 더 스캔하거나 [입력] (05 문서 2.3) |
| 중량이 10배·100배로 나옴 | `소수점` 값 |
| 중량이 이상하게 작음 | `기준단위`가 `LB`로 되어 있는지 |
| 중량이 0으로 저장됨 | 품목 타입(매핑 타입구분)이 비어 있는지 (홈플러스 비정량) |
| 소비기한 정보 필수 안내 | 품목 마스터 제조일자 위치·소비기한(적용단위·적용값) |
| 다른 품목으로 계근됨 | ① 목록을 불러온 직후 스캔은 품목을 확인하지 않음(05 문서 2.3 ②) ② 같은 자리·같은 문자열을 가진 품목이 여럿인지 (3장) |
