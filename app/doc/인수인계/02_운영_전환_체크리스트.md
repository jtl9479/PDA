## 1. 이 문서의 용도

개발·테스트 환경에서 **운영(현장 사용)으로 넘길 때 해야 할 일**을 순서대로 모았다.
각 항목의 `☐`를 `☑`로 바꾸며 진행하고, 결정이 필요한 항목은 결정 내용과 날짜를 비고에 적는다.

| 상태 표기 | 뜻 |
|------|------|
| **필수** | 운영 전에 반드시 해야 함 |
| **결정** | 담당자가 방향을 정해야 함 |
| **확인** | 현재 값이 맞는지 점검만 하면 됨 |
| **권장** | 하지 않아도 동작하지만 하는 것이 안전함 |

| ☐ | T3 | 계근 1건 | 스캔 → 라벨 출력 → 계근 상세에 1건 표시 |
| ☐ | T4 | 전송 | 전송 성공 후 ERP `SM_출고계근`에 같은 건이 들어가 있다 (ERP PDA출고계근현황 화면 또는 직접 조회) |
| ☐ | T5 | 재다운로드 | 전송 후 [출하대상받기]를 다시 해도 계근 수량이 채워진 상태로 나온다 |
| ☐ | T6 | 합산 라벨 | 계근 상세 [합산] → 파렛트당 박스 수 입력 → 라벨 출력 |

### 3.8 문제가 생겼을 때 되돌리기

| 대상 | 방법 | 주의 |
|------|------|------|
| 앱 | 같은 키로 서명된 이전 버전 APK를 설치한다. versionCode가 낮으면 일반 설치가 안 되므로 `adb install -r -d`로 설치한다(`-d`는 debug 빌드처럼 디버깅 가능한 APK에서만 된다) | 앱을 지우면 미전송 계근이 사라진다. 지우기 전에 전송부터 한다 |
| JSP | S2에서 백업한 운영서버 JSP를 되돌린다 | |
| ERP 데이터 | 잘못 전송된 계근은 ERP에서 정리한다 | 정리 방법은 ERP 담당과 협의 |
