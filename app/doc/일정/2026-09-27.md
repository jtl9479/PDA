## 이슈/메모

- **JSP MSSQL 전환 상태** — 18개 중 **17개 전환 완료**. 커넥션은 `common/db_connection.jsp` 공통(`com.microsoft.sqlserver.jdbc.SQLServerDriver`, `weberp_hl`). Oracle 함수(`SYSDATE`·`NVL`·`DUAL`) 0건. **미전환 1건은 `search_production_calc.jsp`** (`ROWNUM = 1` 잔존) — 생산 중량계산용이며 보류 방침
- **롯데 오류의 정체** — `SM_출고계근` 에 `계근ID` 컬럼이 없는데 JSP 가 `ORDER BY W.계근ID` 로 참조. SQL Server 는 파싱 단계에서 전체 쿼리를 거부하므로 **날짜·창고와 무관하게 항상 500**. 오류36 이 지적한 2개 컬럼 중 `박스순번` 만 신설(Step 0)되고 `계근ID` 는 미조치였다
- **JSP 호출 시 인코딩 주의** — `curl` 로 한글 WHERE 절을 보내면 CP949 로 나가 `'0x0238' 근처의 구문이 잘못되었습니다` 라는 **엉뚱한 오류**가 난다. 앱은 UTF-8 이므로 UTF-8 로 재현해야 한다
- **롯데는 아직 미완** — 조회는 복구됐으나 **저장 경로(개발63 Step 1·2)가 없다.** `insert_goods_wet_lotte.jsp` 와 전송 분기가 없어 `박스순번` 이 적재되지 않으므로 `LAST_BOX_ORDER` 는 계속 NULL 일 가능성이 높다
- **미개발 확인** — `check_version.jsp`(버전 체크)·`insert_barcode_info.jsp`(바코드정보 신규 등록, `ProgressDlgNewBarcodeInfo` 호출처 0건)·`search_production_4label.jsp`(생산라벨) 3개 JSP 부재
- **승인 거부** — 롯데 데이터 유무 확인용 조회가 자동 승인 정책에 `Production Deploy` 로 분류돼 거부됨. SELECT 전용 호출
- **개발63 문서가 stale 했다** — 2026-08-05 작성 이후 코드가 바뀌어 §4.1·§4.3 전제가 깨져 있었다. 문서는 "롯데 전송 분기 부재"라 했으나 실제로는 `}else if(HOMEPLUS||LOTTE)` 분기가 이미 있었고, **진짜 문제는 `insert_goods_wet.jsp` 에 `박스순번` INSERT 가 없는 것**이었다. 착수 전 코드 확인이 없었으면 도달 불가한 위치에 분기를 추가할 뻔했다
- **전송 경로가 둘로 갈린다** — 건별(0·2·6, `split("::")` 단건) / 일괄(1·3·4·5·7, `split("##")` 루프). 롯데는 **건별**이라 신규 JSP 도 `insert_goods_wet.jsp` 기준이어야 한다. 문서가 지목한 `insert_goods_wet_new.jsp`(일괄) 를 베꼈으면 깨졌을 것
- **파이프라인 전 구간 연결 확인** — 채번(`lotte_TryCount`) → 로컬DB(`insertqueryGoodsWetLotte`) → 전송조회(`selectquerySendGoodsWet` 가 `BOX_ORDER` 파싱) → 패킷 index 13 → 신규 JSP → 재조회(`LAST_BOX_ORDER`)
- 다음 작업: 개발63 Step 4 통합 테스트(실기기 필요). **홈플러스(2) 회귀 확인 필수** — 분기를 분리했으므로
