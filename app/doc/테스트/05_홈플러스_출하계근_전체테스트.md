## 홈플러스 정량 특이사항 요약

| 항목 | 내용 |
|------|------|
| 마트사구분 | `'4'` (CO_거래처MASTER B.마트사구분 = '4') |
| 식별 필터 | `COALESCE(M1.타입구분, M2.타입구분) = 'W'` |
| 출하대상 컬럼 | 24개 (index 0~23) |
| ITEM_TYPE | `'S'` AS ITEM_TYPE 하드코딩 고정 |
| 창고코드 조건 | 창고 선택 시 `AND D.창고코드 = '...'` 추가 |
| GI_L_ID (LOT) | 미사용 (빈 문자열 고정) |
| 계근전송 JSP | `insert_goods_wet.jsp` (구로직, 1건씩 전송) |
| 정렬 | `HE.납품처코드 ASC, I.PPCODE ASC, I.품목명 ASC` |
| 행팽창 위험 | SM_수주상세 LEFT JOIN — 마트사SEQ 비유니크 → 중복 가능 (오류22-2) |
| STORE_IN_DATE | SD.납기일자 컬럼 타입 확인 대기 (오류22-1) — datetime이면 substring 오류 가능 |

## 호출 흐름

```
[MainActivity] 홈플러스 출하대상받기 버튼 (searchType=2)
    ↓
① search_shipment_homeplus.jsp (출하대상 조회, 24개 컬럼)
    WHERE H.마트사구분='4' AND D.출고수량>0
    AND COALESCE(M1.타입구분, M2.타입구분)='W'
    LEFT JOIN SM_수주상세 SD ON SD.마트사SEQ = HE.SEQ
    ↓ 자동
② search_barcode_info.jsp (바코드 정보 조회, 정량 공용)
    ↓ 자동
③ search_goods_wet.jsp (계근 내역 조회)
    ↓
[바코드정보 없는 상품 다이얼로그 표시]
    ↓ 사용자 개입
④ 계근입력 (바코드 스캔 / 수기 중량입력)
    → TB_GOODS_WET INSERT (SAVE_TYPE='F')
    → 라벨 출력 (홈플러스 양식)
    ↓ 사용자 개입
⑤ 계근전송 버튼 클릭
    → insert_goods_wet.jsp (1건씩, 구로직)
    → SM_출고계근 INSERT
    → TB_GOODS_WET.SAVE_TYPE 'F'→'Y' UPDATE
```

## 시나리오 2: 출하대상 행 팽창(중복) 검증

**배경**: SM_수주상세 LEFT JOIN 시 동일 마트사SEQ에 N건이 있으면 출하 건이 N배 중복 조회될 수 있음 (오류22-2).

### 절차

```
1. 앱 실행 → 로그인
2. 홈플러스 출고 데이터가 있는 날짜 선택
3. 홈플러스 출하대상받기 버튼 클릭
4. 출하대상 목록 확인 (항목 수 기록)
5. MSSQL에서 동일 날짜 SM_출고상세 건수 직접 조회 (별도 쿼리 실행)
   SELECT COUNT(*) FROM SM_출고상세 D
   INNER JOIN SM_출고머리 H ON ...
   WHERE H.마트사구분='4' AND D.출고일자='[선택일자]'
6. 앱 목록 건수 vs MSSQL 직접 조회 건수 비교
```

### 확인 항목

| # | 확인 항목 | 예상 결과 | 확인 |
|---|----------|----------|:----:|
| 1 | 앱 출하대상 목록 건수 | MSSQL 직접 조회 건수와 동일 | □ |
| 2 | 중복 행 여부 | 동일 GI_D_ID가 2회 이상 표시되지 않음 | □ |
| 3 | SM_수주상세 N건 케이스 | 마트사SEQ에 수주상세 2건 이상인 경우 N배 중복 없음 확인 | □ |
| 4 | 중복 발생 시 | 오류 문서(`app/doc/오류/`) 작성 후 오류22-2 수정 진행 | □ |
| 5 | 앱 비정상 종료 | 없음 | □ |

## 시나리오 3: STORE_IN_DATE 날짜 표시 검증

**배경**: SD.납기일자 컬럼이 MSSQL datetime 타입이면 rs.getString() 시 `"2026-06-23 00:00:00.0"` 형식 반환 → Java substring 오류 가능 (오류22-1).

### 절차

```
1. 앱 실행 → 로그인
2. 홈플러스 출하대상받기 버튼 클릭
3. 출하대상 목록에서 STORE_IN_DATE가 표시되는 항목 확인
4. 라벨 출력 후 라벨상의 납기일자(납품일) 확인
5. Tomcat 서버 로그에서 STORE_IN_DATE 반환값 형식 직접 확인
```

### 확인 항목

| # | 확인 항목 | 예상 결과 | 확인 |
|---|----------|----------|:----:|
| 1 | 서버 로그 STORE_IN_DATE 값 | `"20260623"` 형식 (8자리 문자열) | □ |
| 2 | STORE_IN_DATE 표시 | 앱 화면에 날짜 정상 표시 (비정상 문자열 없음) | □ |
| 3 | 라벨 납기일자 | 라벨에 납기일 정상 출력 (substring 예외 없음) | □ |
| 4 | datetime 형식 반환 시 | `"2026-06-23 00:00:00.0"` 형태 → 오류 문서 작성 및 CONVERT 수정 필요 | □ |
| 5 | 앱 비정상 종료 | 없음 | □ |
