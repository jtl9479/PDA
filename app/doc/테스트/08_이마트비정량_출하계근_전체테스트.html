절차

1. 앱 실행 → 로그인

8. 화면에 상품정보·중량이 그대로(반올림 없이) 표시되는지 확인
9. BARCODE_TYPE에 맞는 라벨이 자동 출력되는지 확인
10. 계근 전송 버튼 클릭

시나리오 7 (엣지케이스) EMARTLOGIS_CODE 빈값 라벨 출력 예외 리스크 — 오류21 재검증

⚠️ 오류21 원인 코드는 M0/M1/M3/M4/E0/P0 case에는 여전히 존재한다 (LabelPrintHelper.java:518~519, 534~535, 551~552, 567~568, 584~585, 644~645 — si.getEMARTLOGIS_CODE().substring(0, 6), null/빈값 방어 없음).
JSP도 미수정 상태 확인됨: search_production_nonfixed.jsp:60 — COALESCE(M1.물류코드, M2.물류코드) AS EMARTLOGIS_CODE (NULLIF/ISNULL 방어 미적용, 빈 문자열 그대로 통과).
2026-06-23 바코드타입 제한(M8/M9 only) 제거로 인해, 이전에는 M8/M9만 나오던 비정량 대상에 M0/M1/M3/M4 등 다른 바코드타입도 포함될 수 있게 되어, 해당 품목의 EMARTLOGIS_CODE가 빈 문자열이면 StringIndexOutOfBoundsException(length=0; index=6) 크래시 위험이 새로 발생할 수 있다.

절차

1. ERP CO_매출처품목코드매핑에서 물류코드가 빈 문자열('')인 비정량 품목을 준비
2. 해당 품목의 바코드타입이 M0 또는 M1이 되도록 CO_매출처품목코드매핑.바코드타입 확인 (M8/M9가 아닌 케이스)
3. 비정량출하대상받기로 해당 품목 조회
4. 해당 품목 바코드 스캔 또는 수기 계근 완료
5. 라벨 출력 단계에서 앱 동작 확인 (정상 출력 vs 예외 발생)
6. logcat에서 StringIndexOutOfBoundsException 발생 여부 확인
--- 대조군 ---
7. 동일 조건에서 물류코드가 정상 입력된(빈값 아님) 품목으로 재시도 → 정상 출력 확인
