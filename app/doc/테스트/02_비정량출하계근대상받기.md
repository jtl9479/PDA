## 시나리오 1: 정상 조회 (비정량 출하대상 데이터 조회)

### 절차

```
1. Tomcat 서버 재시작 (search_production_nonfixed.jsp 변경분 반영 확인)
2. 앱 실행 → 로그인
3. 창고 선택 (Spinner에서 서버 창고 목록 표시 확인)
4. 날짜 선택 (비정량 출고 데이터가 있는 날짜)
5. 비정량 출하대상받기 버튼 클릭 (searchType=4)
6. 로딩 다이얼로그 3단계 확인 (출하대상 → 바코드정보 → 계근정보)
7. 바코드정보 없는 상품 다이얼로그 확인
```

### 확인 항목

| # | 확인 항목 | 예상 결과 | 확인 |
|---|----------|----------|:----:|
| 1 | ① search_production_nonfixed.jsp 호출 | 서버 로그에 MSSQL 직접 JOIN 쿼리 출력 | □ |
| 2 | ① 응답 데이터 | `receiveData`에 31개 컬럼 데이터 ("::" 구분) | □ |
| 3 | ① PACKER_CODE 값 | temp[16] = `0000` (고정값) | □ |
| 4 | ① PACKER_PRODUCT_CODE 값 | temp[17] = 품목코드 (I.품목코드) | □ |
| 5 | ① ITEM_TYPE 값 | temp[19] = `HW` (고정값) | □ |
| 6 | ① BARCODEGOODS 값 | temp[21] = 품목코드 (I.품목코드) | □ |
| 7 | ① BARCODE_TYPE 값 | temp[18] = `M8` (WHERE 조건에 의해 M8만 조회됨) | □ |
| 8 | ① TB_SHIPMENT INSERT | `insertqueryShipment` 로그 출력 | □ |
| 9 | ② search_barcode_info_nonfixed.jsp 호출 | `Barcode Code List` 로그 출력 | □ |
| 10 | ② TB_BARCODE_INFO INSERT | `insertqueryBarcodeInfo` 로그 출력 | □ |
| 11 | ③ search_goods_wet.jsp 호출 | 계근 내역 조회 로그 출력 | □ |
| 12 | ③ 응답 데이터 | 초회 조회 시 0건 (미계근 상태) | □ |
| 13 | 앱 비정상 종료 | 없음 | □ |

### 로그 확인 명령어

```bash
adb logcat -d -s "ProgressDlgShipSearch" "pDlgBarcodeSearch" "pDlgGoodsWetSearch" "DBHandler" | tail -30
```

## 시나리오 2: 바코드 스캔 + 중복 허용 확인

### 절차

```
1. 시나리오 1 완료 후 (TB_SHIPMENT, TB_BARCODE_INFO 데이터 있는 상태)
2. 비정량 상품 목록에서 계근입력 시작
3. M8 바코드 스캔 (품목코드 기반 바코드)
4. 정상 계근 확인 (중량 표시)
5. 동일 바코드 재스캔 → 중복 차단 확인
6. 다른 중량의 바코드 스캔 → 정상 계근 확인
```

### 확인 항목

| # | 확인 항목 | 예상 결과 | 확인 |
|---|----------|----------|:----:|
| 1 | M8 바코드 매칭 | BARCODEGOODS(품목코드) 기준 매칭 성공 | □ |
| 2 | 첫 스캔 계근 | 계근수량 1/N, 중량 표시 정상 | □ |
| 3 | 동일 바코드 재스캔 | 중복 차단 (Toast "이미 스캔한 바코드입니다", 진동) | □ |
| 4 | 다른 바코드 스캔 | 계근수량 2/N, 중량 표시 정상 | □ |
| 5 | ITEM_TYPE = 'HW' 동작 | FLOOR 처리 없이 중량 표시 (소수점 유지) | □ |
| 6 | 앱 비정상 종료 | 없음 | □ |
