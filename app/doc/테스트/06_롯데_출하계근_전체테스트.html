시나리오 4 출하대상 행 팽창(중복) 검증

절차

1. DB에서 SM_수주상세 테이블의 해당 마트사SEQ에 대한 행 수 확인
   (동일 마트사SEQ에 복수 행이 있는지 확인)
2. 앱 실행 → 롯데 출하대상받기 클릭
3. 출하대상 목록 건수를 ERP 발주 건수와 비교

확인 항목

#확인 항목예상 결과확인
1SM_수주상세 LEFT JOIN 행 수SELECT COUNT(*) FROM SM_수주상세 WHERE 마트사SEQ = ? → ERP 기대값과 비교
2출하대상 목록 건수ERP 출고 건수와 동일 (행 팽창 없음 = 정상)
3행 팽창 발생 시동일 GI_D_ID가 복수 행으로 표시됨 → 오류 문서 작성 필요
4STORE_IN_DATE 값납기일자 정상 표시 (datetime 타입이면 오류22-1 해소 필요)
5앱 비정상 종료없음

검증 쿼리 (MSSQL weberp_dev)

-- 행 팽창 확인: 동일 마트사SEQ 기준
SELECT D.SEQ, COUNT(*) AS row_cnt
FROM SM_출고상세 D
INNER JOIN SM_출고머리 H ON H.회사코드 = D.회사코드
    AND H.출고사업장 = D.출고사업장
    AND H.출고일자 = D.출고일자
    AND H.출고일련번호 = D.출고일련번호
JOIN SM_마트사발주롯데마트 LE ON D.마트사SEQ = LE.SEQ
LEFT JOIN SM_수주상세 SD ON SD.마트사SEQ = LE.SEQ
WHERE H.마트사구분 = '6'
  AND D.출고일자 = '20260623'   -- 테스트 날짜로 변경
GROUP BY D.SEQ
HAVING COUNT(*) > 1;

시나리오 9 박스순번 9999 경계 순환 검증

절차

1. DB SM_출고계근에서 해당 출고상세SEQ의 박스순번을 9998 또는 9999로 수동 설정
   (UPDATE SM_출고계근 SET 박스순번 = 9998 WHERE ...)
2. 앱 실행 → 롯데 출하대상받기 클릭
3. LAST_BOX_ORDER = '9998' 수신 확인
4. lotte_TryCount 초기값 확인 (9999)
5. 바코드 스캔 → BOX_ORDER 9999 확인
6. 바코드 스캔 → BOX_ORDER 1 (순환 회귀) 확인

확인 항목

#확인 항목예상 결과확인
1LAST_BOX_ORDER 수신Index 25 = '9998'
2lotte_TryCount 초기값9999 (9998+1)
39999 초과 조건lotte_TryCount(9999) > LOTTE_BOX_ORDER_MAX(9999) = false → 순환 없음
4스캔 후 lotte_TryCount++9999 + 1 = 10000 > 9999 → lotte_TryCount = 1 (순환 회귀)
5두 번째 스캔 BOX_ORDER1 (순환 후 1번대 재시작)
6앱 비정상 종료없음
