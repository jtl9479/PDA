## 호출 흐름

```
[MainActivity] 날짜 선택 → 이마트 출하대상받기 버튼 클릭
    ↓
① search_shipment.jsp (출하대상 조회, 31개 컬럼 0~30, 마트사구분='7', 타입구분='W')
    ↓ 자동 (ProgressDlgShipSearch 완료 후)
② search_barcode_info.jsp (바코드 정보 조회, CO_품목코드 기반, 25개 컬럼)
    ↓ 자동 (ProgressDlgBarcodeSearch 완료 후)
③ search_goods_wet.jsp (계근 내역 조회, SM_출고계근, 14개 컬럼)
    ↓
[완료] 바코드정보 없는 상품 다이얼로그 → BixolonShipmentActivity
    ↓
④ 바코드 스캔 또는 수기 중량입력 (계근 입력)
    ↓ 수입육 등 소비기한 필요 상품의 경우
④-1 ExpiryEnterActivity (소비기한 수기입력 화면)
    ↓
⑤ 라벨 인쇄 (LabelPrintHelper → BixolonSocketPrinter, 이마트 양식)
    ↓
⑥ 계근 전송: insert_goods_wet.jsp (구로직, "::" 15필드, SM_출고계근 INSERT, 1건씩)
```

## 시나리오 1: 정상 E2E (출하대상받기 → 바코드 스캔 계근 → 라벨 → 전송)

### 절차

```
1. 앱 실행
2. 로그인 (ID/PW 입력)
3. 창고 선택 (Spinner에서 서버 창고 목록 표시 확인)
4. 날짜 선택 (이마트 출고 데이터가 있는 날짜)
5. 이마트 출하대상받기 버튼 클릭
6. 로딩 다이얼로그 3단계 확인 (출하대상 → 바코드정보 → 계근정보)
7. 바코드정보 없는 상품 다이얼로그 확인 후 닫기
8. 이마트 계근입력시작 버튼 클릭 → BixolonShipmentActivity 진입
9. 센터 / BL번호 / 지점 스피너에서 계근 대상 선택
10. 첫 번째 상품 이마트 바코드 스캔
11. 계근 중량 표시 확인 (Round 처리 포함)
12. 라벨 자동 인쇄 스위치 ON 상태 확인
13. 계근 완료 시 라벨 자동 출력 확인
14. 계근 전송 버튼 클릭 → insert_goods_wet.jsp 호출 확인
15. 전송 완료 후 계근완료 상태 변경 확인
```

### 확인 항목

| # | 확인 항목 | 예상 결과 | 확인 |

| 1 | ① search_shipment.jsp 호출 | 서버 로그 "=========search_shipment============" 출력 | □ |
| 2 | ① WHERE절 조건 | 마트사구분='7', 출고수량>0, 타입구분='W', 회사코드, 출고일자, 창고코드 포함 | □ |
