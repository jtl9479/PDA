# 계근입력화면 (BixolonShipmentActivity) 프로세스 및 기능

**작성일**: 2026-01-13

---

## 1. 화면 개요

계근입력화면은 출하 대상 상품의 바코드를 스캔하고, 중량을 계근하여 라벨을 출력하는 핵심 화면입니다.

**파일**: `BixolonShipmentActivity.java`

---


#### 스캔순서 초기화 (`btn_init`)

스캔 상태를 초기화하여 **상품 바코드 스캔부터 다시 시작**할 수 있게 합니다.

**동작 원리:**
```java
public void scanFlag_init() {
    if (work_flag == 1)       // 바코드 모드 → 상품 스캔 대기
        scan_flag = true;
    else if (work_flag == 0)  // 수기 모드 → BL 스캔 대기
        scan_flag = false;
    else if (work_flag == 2)  // 상품코드 모드 → 상품 스캔 대기
        scan_flag = true;
}
```

**사용 시점:**
- 스캔 순서가 꼬였을 때
- 다른 상품으로 전환할 때
- 오류 발생 후 처음부터 다시 시작할 때

**토스트 메시지:** `"* 스캔초기화 * 상품바코드를 스캔하세요."`

## 4. 마트사별 분기 처리

### 4.1 searchType 정의

| searchType | 상수 | 마트사 | 라벨 출력 |
|:----------:|------|--------|----------|
| 0 | SEARCH_TYPE_EMART | 이마트 | setPrinting() |
| 1 | SEARCH_TYPE_PRODUCTION | 생산 (이노이천) | 없음 |
| 2 | SEARCH_TYPE_HOMEPLUS | 홈플러스 | setHomeplusPrinting() |
| 3 | SEARCH_TYPE_WHOLESALE | 도매 | setPrinting() |
| 4 | SEARCH_TYPE_NONFIXED | 이마트 비정량 | setPrinting() |
| 5 | SEARCH_TYPE_HOMEPLUS_NONFIXED | 홈플러스 비정량 | setHomeplusPrinting() |
| 6 | SEARCH_TYPE_LOTTE | 롯데 | setPrintingLotte() |
| 7 | SEARCH_TYPE_PRODUCTION_LABEL | 생산 라벨 | setPrinting_prod() |

### 4.2 마트사별 특이사항

| 마트사 | 특이사항 |
|--------|---------|
| 이마트 | 바코드 타입(M0~M9, E0~E3, P0)별 다른 라벨 포맷 |
| 홈플러스 | BOX_ORDER 필드 사용 |
| 롯데 | lotte_TryCount로 박스 순번 관리 (1~9999) |
| 비정량 | 바코드 중복 체크 제외 |
| 생산 | 프린터 비활성화 |

## 5. 상세 프로세스

### 5.1 바코드 스캔 처리

```java
public void setBarcodeMsg(String msg) {
    if (scan_flag) {  // 상품 스캔
        find_ppcode = find_PackerProduct(msg);
        if (!find_ppcode.equals("null")) {
            // 출하 대상 조회
            new ProgressDlgShipSelect(...).execute();
        }
    } else {  // BL 스캔
        // BL번호로 작업 대상 매칭
        // 중복 바코드 검사
    }
}
```

### 5.2 중량 계산 (ITEM_TYPE별)

| ITEM_TYPE | 설명 | 중량 계산 방법 |
|-----------|------|---------------|
| W | 일반 | 바코드에서 추출 (WEIGHT_FROM ~ WEIGHT_TO) |
| HW | 홈플러스 일반 | 바코드에서 추출 |
| S | 저울 계근 | 수기 입력 |
| J | 지정 중량 | PACKWEIGHT 값 사용 |
| B | 박스 계근 | 홈플러스 비정량용 |

**바코드에서 중량 추출:**
```java
// 바코드: 01088012345678900125260113001
//                          ^^^^
//                       WEIGHT (0125 = 1.25kg)

String weight = barcode.substring(WEIGHT_FROM - 1, WEIGHT_TO);
double weightKg = Double.parseDouble(weight) / Math.pow(10, ZEROPOINT);
```

### 5.3 계근 데이터 저장

```java
public void wet_data_insert(String weight_str, double weight_double,
                           String making_date, String box_serial) {
    // 1. Goodswets_Info DTO 생성
    Goodswets_Info gi = new Goodswets_Info();
    gi.setGI_D_ID(...);
    gi.setWEIGHT(weight_str);
    gi.setBARCODE(work_item_fullbarcode);
    // ...

    // 2. 마트사별 DB 저장
    if (홈플러스) {
        DBHandler.insertqueryGoodsWetHomeplus(gi, maxBoxOrder);
    } else if (롯데) {
        DBHandler.insertqueryGoodsWetLotte(gi, lotte_TryCount);
    } else {
        DBHandler.insertqueryGoodsWet(gi);
    }

    // 3. 라벨 인쇄
    if (Common.print_bool) {
        // 마트사별 인쇄 함수 호출
    }

    // 4. 진행 상황 업데이트
    centerWorkCount++;
    centerWorkWeight += weight_double;
}
```

## 6. 서버 전송

### 6.1 전송 프로세스

```
1. 전송 버튼 클릭
   ↓
2. ProgressDlgShipmentSend 실행
   ↓
3. 로컬 DB에서 미전송 데이터 조회 (SAVE_TYPE = 'F')
   ↓
4. 패킷 생성 (:: 구분자)
   ↓
5. HTTP POST 전송
   ↓
6. 성공 시 SAVE_TYPE → 'Y' 업데이트
   ↓
7. 요청수량 완료 시 complete_shipment 호출
```

### 6.2 패킷 구조

```
GI_D_ID :: WEIGHT :: WEIGHT_UNIT :: PACKER_PRODUCT_CODE :: BARCODE ::
PACKER_CLIENT_CODE :: MAKING_DATE :: BOX_SERIAL :: BOX_CNT :: REG_ID ::
ITEM_CODE :: BRAND_CODE :: CLIENT_TYPE :: BOX_ORDER
```

### 6.3 전송 URL

| 마트사 | URL |
|--------|-----|
| 이마트, 도매, 생산 | Common.URL_INSERT_GOODS_WET |
| 홈플러스, 롯데 | Common.URL_INSERT_GOODS_WET_HOMEPLUS |
