## 1. 목적

- 사용자가 내린 명령·작업 이력을 Notion에서 캘린더로 관리한다.
- 기록 방식을 문서로 고정하여 매 작업마다 **동일한 구조**로 정리되도록 한다.

## 3. 구조 — 캘린더 데이터베이스

작업 1건 = DB의 1행(row). 캘린더 뷰에서 날짜 칸에 작업이 표시된다.

```
회사
└── 📱 PDA
    └── 🗓️ 작업 기록 (DB, 캘린더 뷰)
        ├── [작업1]  날짜·분류·상태·요약  + 본문(상세)
        ├── [작업2]  ...
        └── ...
```

### 3.1 행(row) 속성

| 속성 | 타입 | 설명 |
|------|------|------|
| 작업명 | Title | 작업 제목 |
| 날짜 | Date | 작업 수행일 (캘린더 기준). 생성 시 `date:날짜:start` 키 사용 |
| 분류 | Select | `코드수정` / `문서작성` / `오류처리` / `테스트` / `기타` |
| 상태 | Status | `시작 전` / `진행 중` / `완료` |
| 요약 | Text | 작업 요약 1~2줄 |

### 3.2 행 페이지 본문 (상세)

- `## 명령` — 사용자 명령 원문 (인용)
- `## 결과` — 수행 결과 (수정 파일/내용, 검증 결과 등)
- `## 비고` — 특이사항·주의점 (선택)

---

## 4. 기록 기준

| 구분 | 기록 여부 |
|------|:--------:|
| 실제 작업 (코드 수정·문서 작성·오류 처리·테스트 등) | ✅ 기록 |
| 단순 질문·확인·상태 조회 | ❌ 제외 |

- 사용자가 "노션에 기록해줘"라고 명시하면 위 기준과 무관하게 기록한다.

---

## 5. 동작 흐름

1. 실제 작업 수행
2. `작업 기록` DB(데이터소스 `collection://6132122f-...`)에 행 추가
   - 작업명 / `date:날짜:start` / 분류 / 상태 / 요약 입력
3. 행 페이지 본문에 상세(`## 명령` / `## 결과` / `## 비고`) 작성

## 7. 일정 관리 (회사 폴더)

작업 기록과 별개로, **계획(일정)** 은 `회사 > 일정` 캘린더 DB로 관리한다.

| 항목 | 값 |
|------|-----|
| 위치 | `회사` 페이지 직속 (PDA 폴더 아님) |
| 일정 DB | `일정` (database id `7967279c-6c0c-4135-baab-4d61d8a417be`) |
| 데이터소스 | `collection://63d103fb-72d3-40cf-a423-5bb72c4e63a0` |

### 7.1 행 속성

| 속성 | 타입 | 설명 |
|------|------|------|
| 일정명 | Title | 할 일 제목 |
| 기간 | Date | 예정일 (생성 시 `date:기간:start` 키 사용) |
| 구분 | Select | `개발` / `문서` / `테스트` / `회의` / `기타` |
| 완료 | Checkbox | 미체크 → 수행 완료 시 체크 (`__YES__`) |
| 메모 | Text | 비고 |

### 7.2 운영 흐름

1. **아침 등록**: 사용자가 "오늘 ~작업 하겠다"고 하면 → 일정 DB에 오늘 날짜(`기간`)로 항목 추가, `완료` = 미체크.
2. **작업 수행 시**: 해당 작업을 실제로 처리하면 → 그 일정 항목의 `완료` 체크박스를 체크(`완료`=`__YES__`) + 작업 기록 DB에도 1행 기록.
3. 일정명과 작업명을 맞춰 두면 어떤 일정이 어떤 작업으로 완료됐는지 대조하기 쉽다.

## 8. Notion 파일 첨부 (업로드 API)

Notion MCP에는 파일 업로드 도구가 없어, 로컬 파일을 페이지에 첨부하려면 **Notion File Upload API**를 사용한다. (PDA·WEBERP 등 전 프로젝트 공통 방식)

### 8.1 사전 준비 (1회)

- Notion 인테그레이션 생성(https://www.notion.so/my-integrations) → **Internal Integration Secret(토큰)** 발급.
- 첨부 대상 페이지(또는 상위 폴더)를 인테그레이션과 **연결**(`···` → 연결). 상위(회사)에 연결하면 하위 전부 접근 가능.
- ⚠️ 토큰은 비밀값 → 메모리/파일/커밋에 저장하지 않는다. 사용자가 매번 제공하며, 작업 후 재발급/삭제 권장.

### 8.2 업로드 절차 (curl 3단계)

```
# ① 업로드 슬롯 생성 → upload_id
POST https://api.notion.com/v1/file_uploads
  Header: Authorization: Bearer <TOKEN>, Notion-Version: 2022-06-28
  Body:   {"filename":"<파일명>","content_type":"<MIME>"}

# ② 파일 전송 (단일 업로드 ≤20MB)
POST https://api.notion.com/v1/file_uploads/<upload_id>/send
  Header: Authorization, Notion-Version
  Form:   file=@<로컬경로>;type=<MIME>     → status: uploaded

# ③ 페이지에 첨부 블록 추가
PATCH https://api.notion.com/v1/blocks/<page_id>/children
  Body:   {"children":[{"type":"file","file":{"type":"file_upload","file_upload":{"id":"<upload_id>"}}}]}
```

- 20MB 초과 시 multi-part 업로드 필요.
- 접근 확인: `GET /v1/pages/<page_id>` 가 200이면 연결 정상(404면 연결 필요).
- ⚠️ **한글(비ASCII) 파일명 주의**: Windows에서 curl로 보내면 한글 바이트가 손상되어 파일명이 `03___.html`처럼 깨진다. **한글 파일명이 포함되면 curl 대신 Python(urllib, UTF-8 인코딩)으로 업로드**한다. 이미 깨졌으면 `PATCH /v1/blocks/<block_id>` 로 `{"file":{"name":"<원본명>"}}` 를 Python(UTF-8)으로 재설정해 복구. (영문/숫자 파일명만이면 curl 무방)

### 8.3 문서 작성 시 파일 첨부 규칙

- **문서 작성 작업**은 작업 기록 행 등록에 더해, 해당 행 페이지(`<page_id>`)에 **작성한 문서 파일을 첨부**한다.
- 토큰이 없으면 사용자에게 요청하고, 받기 전까지는 행만 등록한 뒤 토큰 확보 시 첨부한다.
- 토큰은 저장하지 않으므로 첨부 작업마다 사용자가 제공한다.
