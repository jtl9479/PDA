# AI 엔지니어링 종합 가이드

**작성일**: 2026-04-08
**목적**: AI 에이전트 활용 엔지니어링 개념 정리 및 현재 프로젝트 적용 현황 분석

---

## 1. 엔지니어링 개념 정의

### 1.1 프롬프트 엔지니어링 (Prompt Engineering)

AI에게 **무엇을 시킬지 지시하는 기술**이다.
한 번의 대화에서 좋은 질문, 좋은 지시를 내려서 원하는 결과를 얻는 것에 초점을 맞춘다.

### 1.2 컨텍스트 엔지니어링 (Context Engineering)

AI가 작업할 때 **어떤 정보를 보고 있는가를 설계하는 것**이다.
AI 모델에는 컨텍스트 윈도우라는 한정된 공간이 있으며, 이 공간에 무엇을 넣고, 무엇을 빼고, 어떤 순서로 배치하느냐에 따라 결과 품질이 달라진다. 아무리 좋은 질문을 해도 AI가 잘못된 정보를 보고 있으면 잘못된 결과가 나온다.

### 1.3 컴파운드 엔지니어링 (Compound Engineering)

AI 에이전트의 작업 루프에 **"종합(Compound)" 단계를 추가**하는 것이다.

기존 워크플로우:
```
Plan → Work → Review (루프) → 완료
```

컴파운드 엔지니어링 적용:
```
Plan → Work → Review (루프) → Compound → 완료
```

Compound 단계에서는 실행/검토 루프 중 발생했던 모든 에러와 문제점을 종합해서 `.claude.md` 같은 시스템 프롬프트 파일에 기록한다. 다음 작업 시 AI가 그 기록을 참고하여 **동일한 실수를 반복하지 않게** 된다.

핵심 원칙: **AI의 실수는 한 번으로 족하다.**

### 1.4 하네스 엔지니어링 (Harness Engineering)

AI 에이전트를 효과적으로 제어하고 활용하기 위한 **전체적인 체계를 설계하는 것**이다.
"Harness"는 원래 말에 채우는 마구(馬具)로, AI의 능력을 원하는 방향으로 정확하게 쓰이도록 제어하는 모든 것을 의미한다.

프롬프트 엔지니어링, 컨텍스트 엔지니어링, 컴파운드 엔지니어링을 모두 포괄하는 상위 개념이다.

### 1.5 개념 간 관계

```
하네스 엔지니어링 (전체 제어 체계)
    ├── 컨텍스트 엔지니어링 (AI에게 무엇을 보여줄지 설계)
    ├── 프롬프트 엔지니어링 (AI에게 무엇을 시킬지 지시)
    └── 컴파운드 엔지니어링 (에러 패턴을 컨텍스트에 자동 누적)
```

## 2. 현재 프로젝트 적용 현황

### 2.1 컨텍스트 엔지니어링 — 적용됨

| 구현 항목 | 설명 |
|----------|------|
| CLAUDE.md | Claude Code가 세션 시작 시 가장 먼저 읽는 파일. 프로젝트 원칙, 문서 규칙, 외부 경로 등 정의 |
| 문서 폴더 체계 | 오류/, 개발/, 소스분석/, 기능/ 등 11개 폴더로 정보를 구조화. AI가 필요한 정보를 정확히 찾아서 컨텍스트에 로드 가능 |
| 참조 관계 | 폴더 간 참조/참조받음 관계를 명확히 정의하여 문서 추적성 확보 |

### 2.2 프롬프트 엔지니어링 — 적용됨

| 구현 항목 | 설명 |
|----------|------|
| AI 제약 조건 | 개발 템플릿마다 "문서에 명시된 step만 진행", "문서에 없는 개선/리팩토링을 임의로 수행하지 않는다" 등 명시 |
| 개발 템플릿 Step 구조 | Step별 분석 → 변환 계획 → 수행 → 컴파일 → 단위테스트 → 회귀테스트 단계 정의 |
| 커밋 메시지 규칙 | "문서명 : step명", "문서 : 문서 주제" 등 패턴화된 커밋 규칙 |
| 문서명 네이밍 컨벤션 | 순번_개발명[오류명], YYYY-MM-DD 등 일관된 명명 규칙 |

### 2.3 컴파운드 엔지니어링 — 부분 적용

| 항목 | 상태 | 설명 |
|------|:----:|------|
| 에러 기록 | ✅ | 오류/ 폴더에 20건의 에러 문서화 완료 |
| 에러 패턴 반영 | ❌ | CLAUDE.md "알려진 버그" 섹션에 2건만 반영. 나머지 18건의 패턴 미반영 |
| 자동 종합 | ❌ | Compound 단계가 자동화되지 않음. 수동 반영에 의존 |

### 2.4 현황 요약

```
Plan → Work → Review → Compound
  ✅       ✅      ✅       ❌ (수동/미완)
```

**앞의 세 단계(Plan/Work/Review)는 문서 체계와 템플릿으로 잘 구현되어 있으나, 마지막 Compound 단계가 자동화되지 않아 에러 패턴 누적의 선순환이 끊겨 있는 상태이다.**

## 3. 개선 방안: 서브에이전트 도입

### 3.1 서브에이전트란

Claude Code에서 사용자가 직접 만들 수 있는 특화된 AI 어시스턴트이다.
각 서브에이전트는 자체 컨텍스트 윈도우에서 실행되며, 사용자 정의 시스템 프롬프트, 특정 도구 액세스, 독립적인 권한, 지속적 메모리를 가진다.

생성 방법:
- Claude Code에서 `/agents` 명령어 실행 (대화형 인터페이스)
- `.claude/agents/` 폴더에 마크다운 파일 직접 생성

참고 문서: https://code.claude.com/docs/ko/sub-agents

### 3.2 제안 서브에이전트 구성

#### 에이전트 1: compound (컴파운드 에이전트)

**목적**: Compound 단계 자동화. 에러 패턴을 분석하고 CLAUDE.md에 반영.

**해결하는 문제**: 오류/ 폴더에 20건의 에러가 쌓여 있지만, CLAUDE.md에는 2건만 반영되어 있다. 이 격차를 자동으로 해소한다.

**동작 방식**:
1. 오류/ 폴더의 전체 에러 문서를 스캔
2. 반복되는 패턴을 분석 (예: 이마트출하대상받기 관련 에러 3건, ID 컬럼 관련 에러 2건)
3. CLAUDE.md의 "알려진 버그" 섹션에 패턴 추가
4. 지속적 메모리(memory: project)에 에러 패턴 지식 누적

**기대 효과**: 다음 세션에서 Claude Code가 동일 유형 코드를 수정할 때 사전에 주의하여 같은 실수를 반복하지 않음.

**설정**:
- 도구: Read, Grep, Glob, Edit (CLAUDE.md 수정용)
- 메모리: project (세션 간 에러 패턴 누적)
- 모델: inherit

#### 에이전트 2: source-verifier (원본 비교 에이전트)

**목적**: "기존 기능과 100% 동일하게 동작" 원칙의 자동 검증.

**해결하는 문제**: 개발 33건이 진행된 상태에서 원본(`D:\PDA\PDA-INNO(원본)`)과의 기능 차이를 수동으로 추적하기 어려워지고 있다.

**동작 방식**:
1. 수정된 파일과 원본 파일을 비교
2. 기능 로직의 차이점을 분석
3. 의도된 변경(DB전환, 하드코딩 변경)과 비의도적 차이를 구분
4. 결과를 보고

**기대 효과**: 코드 수정 후 원본과의 기능 동일성을 자동으로 검증하여, 비의도적 기능 변경을 사전에 감지.

**설정**:
- 도구: Read, Grep, Glob, Bash (읽기 전용)
- 메모리: 없음
- 모델: inherit

#### 에이전트 3: doc-writer (문서 작성 에이전트)

**목적**: 문서 생성의 일관성 보장 및 수작업 절감.

**해결하는 문제**: 매번 마지막 순번 확인 → 템플릿 복사 → 참조 관계 기입을 수동으로 수행해야 한다.

**동작 방식**:
1. 대상 폴더(오류/, 개발/ 등)의 마지막 순번 확인
2. 해당 폴더의 `00_*_템플릿.md` 형식대로 새 문서 생성
3. 관련 문서 섹션에 참조 경로 자동 기입
4. 문서명 네이밍 컨벤션 준수

**기대 효과**: 문서 생성 시 순번 오류, 템플릿 형식 불일치, 참조 누락 방지.

**설정**:
- 도구: Read, Write, Glob, Grep
- 메모리: 없음
- 모델: haiku (단순 작업이므로 빠르고 저렴한 모델)

### 3.3 서브에이전트 적용 후 워크플로우

```
[작업 시작]
    ↓
Plan: 개발/ 문서 작성 (doc-writer 에이전트 활용)
    ↓
Work: 코드 수정 (AI 제약 조건에 따라 Step별 진행)
    ↓
Review: 원본 비교 검증 (source-verifier 에이전트 활용)
    ↓
오류 발생 시 → 오류/ 문서 작성 (doc-writer 에이전트 활용) → Work로 복귀
    ↓
Compound: 에러 패턴 종합 및 CLAUDE.md 반영 (compound 에이전트 활용)
    ↓
[작업 완료]
```

### 3.4 서브에이전트 파일 위치

```
D:\PDA\PDA-INNO\
    └── .claude/
        └── agents/
            ├── compound.md
            ├── source-verifier.md
            └── doc-writer.md
```

## 4. 현재 프로젝트 강점 정리

### 4.1 문서 체계

| 항목 | 현황 |
|------|------|
| 오류 문서 | 20건 (템플릿 기반, 원인/영향범위/수정방안 포함) |
| 개발 문서 | 33건 (Step별 체크리스트, AI 제약 조건 포함) |
| 소스분석 문서 | 39건 (호출 관계, 원본 비교 포함) |
| 기능 문서 | 12건 (전체 흐름, 분기별 동작 포함) |
| 일정 문서 | 일별 관리 (커밋 해시 기록, 상태값 관리) |

### 4.2 핵심 강점

- **오류 선문서화 원칙**: 오류 발생 시 바로 수정하지 않고 먼저 문서화 → 컴파운드 엔지니어링의 기본 철학과 일치
- **AI 제약 조건 명시**: 개발 템플릿에 AI가 지켜야 할 규칙을 직접 심어놓음 → 컨텍스트 엔지니어링의 실현
- **폴더 간 참조 체계**: 문서 추적성 확보 → 정보 구조화
- **Git 기반 이력 관리**: 커밋 메시지 규칙 + 커밋 해시 기록 → 별도 변경이력 문서 불필요
- **실제 운용**: 템플릿만 만들어놓은 것이 아니라 문서가 실제로 쌓이며 운용되고 있음

### 4.3 개선 필요 사항

| 항목 | 현황 | 개선 방향 |
|------|------|----------|
| Compound 단계 | 수동/미완 | compound 서브에이전트로 자동화 |
| CLAUDE.md 에러 반영 | 20건 중 2건만 반영 | 에러 패턴 자동 분석 및 반영 |
| 테스트 문서 | 1건 (테스트 단계 미본격 진입) | 테스트 본격화 시 템플릿 추가 필요 |
| 테스트/테스트데이터 템플릿 | 미작성 | 공식 템플릿 파일 추가 |
