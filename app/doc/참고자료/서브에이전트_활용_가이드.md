**작성일**: 2026-04-09

## 1. 에이전트 호출 방법

### 1.1 @멘션 호출 (권장)

대화 중 `@"에이전트명"` 으로 직접 호출한다.

```
@"error-doc" SM_출고계근.회사코드에 ITEM_CODE 10자리가 저장되어 잘림 에러 발생
```

```
@"schedule-commit" 커밋하라
```

```
@"code-verifier" search_shipment.jsp 인덱스+파라미터+컴파일 검증하라
```

### 1.2 메인 에이전트에 위임 요청

에이전트명을 언급하지 않아도, 작업 내용에 따라 메인 에이전트가 적합한 서브 에이전트를 자동 위임한다.

```
사용자: 오류 문서 작성해라
→ 메인 에이전트가 ② error-doc 에이전트에 위임
```

```
사용자: 컴파일 확인해라
→ 메인 에이전트가 ⑤ code-verifier 에이전트에 위임
```

### 1.3 CLI 직접 실행

터미널에서 특정 에이전트를 세션 기본으로 실행한다.

```bash
claude --agent schedule-commit
claude --agent error-doc
claude --agent code-verifier
```

## 2. 워크플로우별 호출 예시

### WF-1. 오류 발견 → 수정 → 커밋 (풀 사이클)

```
사용자: 바코드 스캔 후 전송 시 W_GOODS_ID 테이블 미존재 에러 발생

① @"error-doc" W_GOODS_ID 테이블 미존재 에러 문서화해라
   → 오류/21_XX.md 생성

② @"schedule-commit" 오류 문서 커밋하라
   → 커밋 + 푸시 + 일정 반영

③ @"dev-guide" 오류21 기반으로 update_shipment 호출 제거 개발 가이드 작성해라
   → 개발/35_XX.md 생성

④ @"doc-consistency" 오류 문서와 개발 가이드 정합성 검증하라
   → 참조 경로, 번호, 관련 문서 일치 확인

⑤ @"schedule-commit" 개발 가이드 커밋하라
   → 커밋 + 푸시 + 일정 반영

⑥ 사용자: Step 1 진행하라
   → 메인 에이전트가 코드 수정

⑦ @"code-verifier" 인덱스+파라미터+컴파일 검증하라
   @"original-comparator" 원본 비교하라
   → 2개 병렬 실행

⑧ @"schedule-commit" Step 1 완료 커밋하라
   → 커밋 + 푸시 + 체크리스트 + 일정 반영

⑨ @"test-manager" 테스트 시나리오 작성+실행하라
   → 성공: ① 커밋 / 실패: ② 오류 문서 (사이클 반복)
```

### WF-2. 기능/소스분석 문서 → 커밋

```
사용자: 계근상세정보 팝업 기능 문서화해라

① @"analysis-doc" 계근상세정보 팝업 기능 문서 작성해라
   → 기능/14_XX.md 생성

② @"schedule-commit" 기능 문서 커밋하라
   → 커밋 + 푸시 + 일정 반영
```

### WF-3. 단순 코드 수정 → 검증 → 커밋

```
사용자: 창고코드 하드코딩 변경 개발 가이드 작성해라

① @"dev-guide" 창고코드 하드코딩 변경 개발 가이드 작성해라
   → 개발/35_XX.md 생성

② @"schedule-commit" 커밋하라

③ 사용자: Step 1 진행하라
   → 메인 에이전트가 코드 수정

④ @"code-verifier" 인덱스+파라미터+컴파일 검증하라
   @"original-comparator" 원본 비교하라

⑤ @"schedule-commit" 커밋하라
```

### WF-4. JSP 수정 → 코드 검증 → 커밋

```
사용자: search_shipment.jsp에 컬럼 추가했다. 검증하라

① @"code-verifier" search_shipment.jsp 인덱스+파라미터+컴파일 검증하라
   → JSP out.println ↔ Java temp[] 일치 + 컴파일 확인

② @"schedule-commit" 커밋하라
```

### WF-5. 하루 시작/종료

```
[하루 시작]
사용자: 오늘 일정 확인하라
① @"schedule-commit" 오늘 일정 문서 확인해라
   → 2026-04-09.md 내용 표시

[하루 종료]
사용자: 오늘 일정 마무리하라
① @"schedule-commit" 오늘 완료 작업 반영 + 내일 일정 생성해라
   → 2026-04-09.md 완료 반영 + 2026-04-10.md 생성
```

### WF-6. 테스트 중 오류 재발

```
사용자: 테스트 중 또 에러 발생. GI_REQ_PKG parseInt 오류

→ WF-1 반복 (오류 문서 → 개발 가이드 → 코드 수정 → 검증 → 커밋)
```

## 3. 병렬 호출

검증 그룹 B (⑤⑥)는 동시에 호출 가능하다.

```
사용자: 검증하라

→ 메인 에이전트가 2개 병렬 실행:
  @"code-verifier" 인덱스+파라미터+컴파일 검증
  @"original-comparator" 원본 비교

→ 2개 전부 통과 후 커밋 진행
```

**주의**: 병렬 실행 상한 10개. 검증 2개는 문제없음.

## 4. 결과물 확인 방법

### 4.1 문서 생성 에이전트 (②③④)

```
결과물: app/doc/오류/XX.md, app/doc/개발/XX.md, app/doc/기능/XX.md
확인: 생성된 파일을 열어 템플릿 형식 + 내용 확인
```

### 4.2 검증 에이전트 (⑤⑥)

```
결과물: 검증 리포트 (대화 내 텍스트 출력)
확인: 통과/실패 판정 + 불일치 항목 확인
```

- **통과**: "검증 통과. 불일치 없음" → 커밋 진행
- **실패**: "불일치 발견: XX줄 파라미터 수 불일치" → 코드 재수정 후 재검증

### 4.3 일정+커밋 에이전트 (①)

```
결과물: 커밋 + 푸시 + 일정 문서 업데이트
확인:
  - git log --oneline -1 → 커밋 메시지 규칙 준수
  - app/doc/일정/YYYY-MM-DD.md → "오늘 완료된 작업"에 행 추가됨
  - 개발 문서 → 체크리스트 [x] 처리됨
```

## 5. 에이전트 프롬프트 수정

### 5.1 파일 위치

```
.claude/agents/
  ├── schedule-commit.md       # ① 일정+커밋
  ├── error-doc.md             # ② 오류 문서
  ├── dev-guide.md             # ③ 개발 가이드
  ├── analysis-doc.md          # ④ 기능/소스분석 문서
  ├── code-verifier.md         # ⑤ 코드 검증 (통합)
  ├── original-comparator.md   # ⑥ 원본 비교
  ├── test-manager.md          # ⑦ 테스트
  └── doc-consistency.md       # ⑧ 문서 정합성
```

### 5.2 수정 방법

1. 해당 에이전트 `.md` 파일을 직접 편집
2. frontmatter (name, description, tools, model) 또는 프롬프트 본문 수정
3. 저장 즉시 반영 (재시작 불필요)

### 5.3 수정 예시

```markdown
---
name: error-doc
description: 오류 발견 시 템플릿 기반 오류 문서 생성
tools: Read, Write, Glob, Grep
model: sonnet
---

(여기에 프롬프트 본문 수정)
```

## 6. 주의사항

- **코드 수정은 서브 에이전트가 하지 않는다** → 메인 에이전트 + 사용자 지시
- **검증 2종(⑤⑥) 전부 통과 후 커밋** → 하나라도 실패 시 코드 재수정
- **커밋은 반드시 ① 에이전트를 통해** → 일정 반영 누락 방지
- **순번 자동 부여 시 기존 파일 확인** → 중복 번호 방지
- **테스트 결과물은 실제 파일로 생성되지 않도록 주의** → 테스트 시 dry-run 또는 생성 후 삭제
