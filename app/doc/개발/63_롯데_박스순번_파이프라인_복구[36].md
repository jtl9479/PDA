## AI 제약 조건

- 기존 WHERE 조건, 로직을 임의로 제거/추가/변경하지 않는다
- 문서에 명시된 step만 진행하고, 다음 step은 지시를 기다린다
- step 완료 후 체크리스트 + 진행 현황을 반드시 업데이트한다
- 문서에 없는 개선/리팩토링을 임의로 수행하지 않는다
- 기존 기능과 100% 동일하게 동작해야 한다

### 추가 제약 조건 (이 가이드 한정)

### 4.4 search_shipment_lotte.jsp — LAST_BOX_ORDER

**변경 전** (`:63~67`):
```sql
, (SELECT TOP 1 W.박스순번
     FROM SM_출고계근 W
    WHERE W.출고상세SEQ = D.SEQ
      AND W.박스순번 IS NOT NULL
    ORDER BY W.계근ID DESC) AS LAST_BOX_ORDER
```

**변경 후**:
```sql
, ISNULL((SELECT TOP 1 t.curr_order
            FROM (SELECT W.박스순번 AS curr_order
                       , LEAD(W.박스순번) OVER (ORDER BY W.SEQ DESC) AS next_order
                    FROM SM_출고계근 W
                   WHERE W.회사코드 = D.회사코드
                     AND W.박스순번 <> 0
                     AND W.ppCode  = I.PPCODE) t
           WHERE (t.curr_order = t.next_order + 1)
              OR (t.curr_order = 1 AND t.next_order = 9999)), 0) AS LAST_BOX_ORDER
```

**Oracle → MSSQL 대응**

| 원본 | 변경 후 | 근거 |
|---|---|---|
| `W_GOODS_WET` | `SM_출고계근` | 계근 테이블 |
| `W.BOX_ORDER` | `W.박스순번` | 2026-08-05 신설 컬럼 |
| `NVL(W.BOX_ORDER, 0)` | `W.박스순번` | `NOT NULL DEFAULT 0` 이라 NVL 불필요 |
| `W.BOX_ORDER IS NOT NULL` | `W.박스순번 <> 0` | 기본값 0 = 미부여. 롯데 외 마트 건 제외 |
| `ORDER BY W.GOODS_WET_ID DESC` | `ORDER BY W.SEQ DESC` | PK. `계근ID` 는 미존재 |
| `W.PACKER_PRODUCT_CODE = BD.PACKER_PRODUCT_CODE` | `W.ppCode = I.PPCODE` | 품목 기준 전역 매칭 |
| `W.GI_D_ID IN (…W_MART_ORDER_ITEM…)` | **제거** | 롯데 발주 테이블 미대응. `회사코드` 로 대체 |
| `FETCH FIRST 1 ROW ONLY` | `SELECT TOP 1` | MSSQL 문법 |
| `NVL(…, 0)` | `ISNULL(…, 0)` | MSSQL 문법 |

**핵심** — 매칭 기준이 `출고상세SEQ`(대상별)에서 `ppCode`(품목별 전역)로 바뀐다. 원본이 전역 순환 카운터이므로 이것이 맞다.

**주의** — `I.PPCODE` 별칭은 JSP 의 실제 `CO_품목코드` 별칭을 확인 후 확정한다(Step 4 Part 1).

| 3 | 롯데 테스트 데이터 없음 | 마트사구분 롯데 값 확인 필요 | JSP WHERE 조건에서 롯데 판별 기준 확인 후 데이터 유무 조사 |
