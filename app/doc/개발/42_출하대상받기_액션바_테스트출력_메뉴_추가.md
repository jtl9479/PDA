# 출하대상받기 액션바 테스트출력 메뉴 추가

**작성일**: 2026-04-27
**목적**: BixolonShipmentActivity(출하대상받기) 액션바에 "테스트 출력" 메뉴를 추가하여, 출하 작업 중 이미 연결된 프린터로 테스트 라벨 1장을 즉시 출력함으로써 프린터 정상 동작을 확인할 수 있게 한다. 동시에 기존 개발42에서 잘못 추가된 SettingActivity의 테스트 출력 버튼 관련 코드를 모두 롤백한다.

## 변경 배경

기존 개발42는 SettingActivity에 "테스트 출력" 버튼을 추가하는 방식으로 구현되었으나, 다음 문제가 있었다.

1. SettingActivity 자체 BixolonSocketPrinter 인스턴스를 새로 생성·연결하면서 버튼 클릭 시마다 "프린터 연결중..." 다이얼로그가 노출됨
2. 사용자 의도는 "이미 연결된 프린터에 라벨 1장 출력만"이지 "연결 + 출력"이 아님
3. 별도 인스턴스 생성은 인스턴스 공유 구조 변경이 필요하여 사이드 이펙트가 큼

따라서 위치를 BixolonShipmentActivity(출하대상받기) 액션바 메뉴로 변경한다. 이 화면은 이미 자체 mBixolonPrinter를 connect한 상태이므로 "연결 없이 출력만"이 자연스럽게 가능하다.

## 5. 사이드이펙트

### 5.1 mBixolonPrinter 인스턴스 영향

- 기존 mBixolonPrinter는 BixolonShipmentActivity 생명주기에 귀속됨
- `printTestLabel()` 은 `write()` 메서드를 통해 ConnectedThread로 데이터를 전송하므로, 라벨 출력 중 다른 출력(라벨 인쇄)이 동시에 요청되면 데이터 순서 꼬임 가능
- 대응: 사용자가 출하 작업 중 테스트 출력을 남발하지 않도록 메뉴 위치를 "오버플로우(never)" 로 배치하여 접근성 낮춤

### 5.2 기존 라벨 출력 회귀 위험

- `onCreateOptionsMenu`, `onOptionsItemSelected` 추가 시 기존 메뉴 동작(프린터설정/출하대상/바코드정보/계근데이터/날짜설정)에 영향이 없도록 `super.onOptionsItemSelected(item)` 를 반드시 호출해야 함
- BixolonShipmentActivity의 부모 클래스인 `HoneywellScannerActivity`에서 onOptionsItemSelected를 구현하고 있다면 super 호출이 필수임

### 5.3 SettingActivity 롤백 영향

- SettingActivity에서 BluetoothAdapter, ProgressDialog import가 제거되면 다른 코드에서 이를 사용하지 않아야 함
- `onDestroy()`의 프린터 설정 저장 로직(ON/OFF SharedPreferences 저장)은 반드시 유지

### 5.4 메뉴 XML 신규 생성 사유

- `main.xml`은 `MainActivity.java:114`에서도 `R.menu.main`으로 inflate하고 있으므로, main.xml에 action_test_print를 추가할 경우 MainActivity 액션바에도 "테스트 출력" 항목이 노출됨
- 이를 방지하기 위해 BixolonShipmentActivity 전용 메뉴 XML(`bixolon_shipment_menu.xml`)을 신규 생성하여 inflate한다
- main.xml은 변경하지 않으므로 MainActivity 동작에 영향 없음
