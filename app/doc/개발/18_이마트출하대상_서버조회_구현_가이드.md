## 1. 현재 구조

### search_shipment.jsp (외부 Tomcat)

```sql
WHERE D.회사코드 = '20'
  AND D.출고일자 > '20260316'
  AND D.창고코드 = '1'
  AND H.마트사구분 = '1'
  AND D.출고수량 > 0
  AND M.타입구분 = 'W'
ORDER BY GI_D_ID ASC
```

- WHERE 조건이 개발/테스트용으로 하드코딩
- `qry_where`(앱에서 보내는 파라미터) 미사용 (16행에서 수신하나 쿼리에 미적용)

### ProgressDlgShipSearch.java (앱)

```java
String data = " WHERE GI_REQ_DATE = '" + Common.selectDay + "'";
if (!Common.selectWarehouseCode.isEmpty()) {
    data += " AND 창고코드 = '" + Common.selectWarehouseCode + "'";
}
receiveData = HttpHelper.getInstance().sendDataDb(data, "inno", "search_shipment", Common.URL_SEARCH_SHIPMENT);
```

- 앱에서 보내는 컬럼명: `GI_REQ_DATE`, `창고코드`
- JSP에서 사용하는 컬럼명: `D.출고일자`, `D.창고코드`

### MainActivity.java (앱)

```java
if (TestDataHelper.TEST_MODE) {
    // 테스트 데이터 로컬 삽입 → 서버 미호출
} else {
    downloadShipmentList(SEARCH_TYPE_EMART, "출하대상받기");
}
```

- `TEST_MODE = true`로 설정되어 서버 조회 미실행

### 문제점

1. `TEST_MODE = true` → 서버 조회를 하지 않음
2. JSP에서 `qry_where`를 수신하나 쿼리에 미적용 → 앱 파라미터 무시
3. 컬럼명 불일치 → 앱은 `GI_REQ_DATE`, JSP는 `D.출고일자`
4. JSP WHERE 조건 하드코딩 → 날짜/창고 고정, 원료육만 조회

### WHERE 조건 구분

| WHERE 조건 | 앱에서 전달 | 앱 변수 | JSP 고정 |
|---|:---:|---|:---:|
| `D.회사코드 = '20'` | **O** | `Common.selectCompanyCode` | |
| `D.출고일자 = '...'` | **O** | `Common.selectDay` | |
| `D.창고코드 = '...'` | **O** | `Common.selectWarehouseCode` | |
| `H.마트사구분 = '1'` | | | **O** |
| `D.출고수량 > 0` | | | **O** |
| `M.타입구분 = 'W'` | | | **O** |
| `PACKING_QTY = 0` | | | **추후 추가** |

> **참고**: `PACKING_QTY = 0` (미계근 건만 조회) 조건은 원본 VIEW(VW_PDA_WID_LIST)에 존재하나, MSSQL 전환 시 해당 컬럼의 테이블/사용 방식에 대해 문의 중. 확인 후 추가 예정.
