**작성일**: 2026-10-08
**목적**: PDA 출하대상받기 조회 JSP 6개의 WHERE 절 직후에 `H.거래명세발행여부 = 'N'` 조건을 추가하여, 거래명세서가 발행되지 않은 출고만 PDA 에서 조회되게 한다.

> **원본 동일 원칙의 사용자 승인 예외**: 원본(Oracle 뷰)에는 없는 신규 조건이다. 사용자가 승인한 변경이며, 이 조건 1줄 외의 WHERE/SELECT/JOIN 은 변경하지 않는다.
> **대상 제외**: `search_production.jsp`(생산, SM_출고머리 미사용), 앱(Java) 전체, 바코드정보/계근전송 JSP(SM_출고머리 미사용).

## 5. 사이드이펙트

### 5.1 조회 건수 감소 (운영 weberp_hl, 2026-10-08 조회, 회사 20)

- 컬럼 `거래명세발행여부`: varchar(1) NOT NULL DEFAULT ''. 현재 값은 N / Y 만 존재.
- 마트사구분별 Y 건수(조건 추가 후 조회에서 제외되는 건):

| 마트사구분 | 마트 | Y 건수 | 비고 |
|:---:|------|:---:|------|
| 7 | 이마트 | 23 | 최근 출고일자 20260708 |
| 4 | 홈플러스 | 1 | 출고일자 20260930 — **2026-10-06 H2 실기기 테스트 데이터. 조건 추가 후 조회되지 않음** |
| '' | 도매 | 29 | 최근 출고일자 20261001 |
| 6 | 롯데 | 0 | 영향 없음 |

- 홈플러스 테스트 데이터(20260930)는 조회에서 빠지므로, 홈플러스 재테스트 시 `거래명세발행여부 = 'N'` 인 데이터가 필요하다(테스트 데이터 갱신은 별도 판단, 본 문서 범위 외).

### 5.2 기본값 '' 위험 (중요)

- 컬럼 기본값이 `''` 이다. ERP 에서 출고 생성 시 `거래명세발행여부` 를 'N' 으로 세팅하지 않으면(기본값 '' 로 남으면) 조건 `= 'N'` 에 걸려 **PDA 에서 조회되지 않는다**.
- 현재 조회 시점에는 N/Y 값만 존재하나, 신규 출고 생성 경로(ERP 화면/배치/인터페이스)가 'N' 을 세팅하는지는 **미확인**. Step 2 에서 `''` 값 건수를 반드시 재확인하고, ERP 담당 확인을 받는다.
- 대응: `''` 가 발견되면 (a) ERP 가 'N' 세팅하도록 조치 또는 (b) 사용자 재결정(`<> 'Y'` 로 변경 여부). (b)는 사용자 결정 사항이며 임의 변경 금지.

### 5.3 이미 내려받은 로컬 데이터

- 이미 PDA 로컬 `TB_SHIPMENT` 에 저장된 출고는 조건과 무관하게 남는다. 이후 ERP 에서 거래명세서가 발행되어도 PDA 가 재조회하기 전까지 로컬 목록에는 계속 표시된다(재조회 시 제외).

### 5.4 다른 JSP / 앱 영향 확인 (grep 결과)

- `inno/` 폴더 grep(`SM_출고머리|거래명세발행여부`): `SM_출고머리` 는 위 6개 JSP 에서만 사용(JOIN 63/69/69/63/76/69행). 바코드정보조회·계근전송·생산·`search_homeplus_nonfixed2.jsp` 등 다른 JSP 에는 SM_출고머리 참조가 없어 영향 없음.
- 앱: `Common.java` 21~24, 42~43 의 URL 상수가 6개 JSP 를 가리키며 `ProgressDlgShipSearch.java`(133~169, 180)에서만 호출한다. 응답 컬럼 수·순서가 불변이므로 파싱(`temp[]`) 인덱스 영향 없음.
- 출하대상 팝업(개발/24, 27): 서버 JSP 가 아닌 **로컬 DB(TB_SHIPMENT LEFT JOIN TB_GOODS_WET)** 를 조회하므로 직접 영향 없음. 단 다운로드되는 TB_SHIPMENT 행이 줄어들어 팝업 표시 건수가 간접적으로 감소한다.
- 계근 전송(SM_출고계근 INSERT) 경로는 SM_출고머리 조건을 사용하지 않으므로 영향 없음.

## 9. 테스트 시나리오

### 시나리오 1: 이마트 출하대상받기

```
1. EDA51 로그인 → 이마트 출하 화면
2. 출고일자 지정(예: Y 가 존재하는 20260708 포함 범위) 후 출하대상받기
3. 거래명세발행여부 = 'Y' 인 출고가 목록에 없고 'N' 만 표시되는지 확인
4. Tomcat 로그 쿼리에 AND H.거래명세발행여부 = 'N' 포함 확인
```

### 시나리오 2: 홈플러스 테스트 데이터 제외

```
1. 홈플러스 출하 화면에서 출고일자 20260930 으로 출하대상받기
2. 조회 0건(Y 1건 제외) 확인
3. Step 2 DB 쿼리 결과와 일치 확인
```

### 시나리오 3: 도매·롯데·비정량

```
1. 도매: 20261001 조회 시 Y 건 제외 확인
2. 롯데: 전/후 동일 건수 확인
3. 이마트 비정량·홈플러스 비정량: N 건만 조회 확인
```

### 시나리오 4: '' 기본값 출고

```
1. DB 에서 거래명세발행여부 = '' 인 출고 존재 여부 조회
2. 존재 시 PDA 미조회 확인 및 ERP 세팅 경로 확인(사용자 보고)
```

## 10. 예상 문제점 및 해결 방안

| # | 문제점 | 원인 | 해결 방안 |
|---|--------|------|----------|
| 1 | 신규 출고가 PDA 에서 조회되지 않음 | ERP 출고 생성 시 거래명세발행여부 미세팅(기본값 '') | ERP 'N' 세팅 확인. 불가 시 사용자 재결정(`<> 'Y'`) — 임의 변경 금지 |
| 2 | 홈플러스 테스트 재현 불가 | 20260930 테스트 데이터가 Y | 'N' 인 테스트 데이터 준비(별도 판단) |
| 3 | 출하 도중 명세서 발행된 출고가 PDA 로컬에 잔존 | 로컬 TB_SHIPMENT 는 재조회 전까지 유지 | 재조회 시 제외됨. 운영 절차 안내 |
| 4 | JSP 500 오류 | 문자열 연결 `+` 누락/오타 | diff 로 1줄 추가만 확인, 쿼리 로그 확인 |
| 5 | 조회 건수 감소를 오류로 오인 | 의도된 변경(Y 제외) | Step 2 전/후 건수 근거 제시 |
