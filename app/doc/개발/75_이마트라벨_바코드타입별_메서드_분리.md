# 이마트 라벨 바코드 타입별 메서드 분리 (setPrinting M0·M8·M9)

**작성일**: 2026-10-07
**목적**: `LabelPrintHelper.setPrinting()` 한 메서드 안에 switch/if(||)로 엮여 있는 이마트 바코드 타입(M0·M8·M9)의 문자열 조립, 위치·숫자 출력 분기, 미트센터 2차 라벨을 타입별 private 메서드로 분리한다. 신규 바코드 타입 추가 시 수정 위치를 한곳(디스패처·위치·숫자 메서드)으로 모으는 것이 목적이다 (프로젝트 목적 4 "소스 정리", 수정 리스트 70 xlsx C3 후속). **출력 바이트는 변경 전과 완전히 동일**해야 한다 (동작 불변 구조 변경).

> **사용자 요청(2026-10-07)**: 바코드 타입 디자인을 타입별 메서드로 나누는 리팩터링.
> **변경 대상 제외**: 롯데 `setPrintingLotte`(L0), 홈플러스 `setHomeplusPrinting`(H2·H5), 생산 `setPrinting_prod`는 이미 메서드 분리되어 있어 수정하지 않는다. `ShipmentActivity.java`(구버전)도 제외. 호출부(`BixolonShipmentActivity`) 시그니처 불변.

**신규 메서드 (setPrinting 아래에 추가):**

```java
/** 이마트 바코드 타입별 문자열 조립 디스패처. 반환: {pBarcode, pBarcodeStr, pBarcode2, pBarcodeStr2} */
private String[] buildEmartBarcode(Shipments_Info si, String print_weight_str, String pCompCode) {
    switch (si.getBARCODE_TYPE()) {
        case "M0":
            return buildBarcodeM0(si, print_weight_str, pCompCode);
        case "M9":
            return buildBarcodeM9(si, print_weight_str, pCompCode);
        case "M8":
            return buildBarcodeM8(si, print_weight_str, pCompCode);
    }
    return new String[]{"", "", "", ""};   // default: 변경 전 switch default 없음과 동일
}

private String[] buildBarcodeM0(Shipments_Info si, String print_weight_str, String pCompCode) {
    // 기존 case "M0" 의 Common.D 로그 블록 그대로 (상품코드 full / 중량 6자리 / 회사코드 / 수입식별번호)
    String pBarcode = si.getEMARTITEM_CODE().substring(0, 6) + print_weight_str + pCompCode + si.getIMPORT_ID_NO();
    String pBarcodeStr = si.getEMARTITEM_CODE().substring(0, 6) + " " + print_weight_str + " " + pCompCode + " " + si.getIMPORT_ID_NO();
    String pBarcode2 = si.getEMARTLOGIS_CODE().substring(0, 6) + print_weight_str + pCompCode + si.getIMPORT_ID_NO();
```

## 10. 예상 문제점 및 해결 방안

| # | 문제점 | 원인 | 해결 방안 |
|---|--------|------|----------|

| 3 | 미트센터 라벨 pCompName 누락 | reprint "  *" 반영 전 값을 전달하면 출력 달라짐 | 메인 라벨 블록 이후 시점의 pCompName 전달 |
| 4 | 이동 중 문자열/좌표 오타 | 수작업 복사 | diff 검토 + 바이트 비교(Step 5) |
