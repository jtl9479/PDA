# 생산(searchType=1) 계근대상 지시일자 이후 조회

**작성일**: 2026-08-05
**목적**: 생산 계근대상 조회 조건을 선택일자 **당일(`=`)** 에서 **선택일자 이후(`>=`)** 로 변경한다. Oracle 원본이 `A.GI_REQ_DATE >= TO_CHAR(SYSDATE,'YYYYMMDD')`로 오늘 이후 전부를 조회하던 동작에 가깝게 되돌린다.

---

## AI 제약 조건

- 기존 WHERE 조건, 로직을 임의로 제거/추가/변경하지 않는다
- 문서에 명시된 step만 진행하고, 다음 step은 지시를 기다린다
- step 완료 후 체크리스트 + 진행 현황을 반드시 업데이트한다
- 문서에 없는 개선/리팩토링을 임의로 수행하지 않는다
- 기존 기능과 100% 동일하게 동작해야 한다

### 추가 제약 조건 (이 가이드 한정)

- 본 작업 범위는 **생산(searchType=1)** 에 한정한다.
- `DBHandler.selectqueryShipment()`는 8개 searchType 공용이므로, **조건 자체를 제거하지 않고 searchType 분기로 우회**한다.
- 다른 searchType(0·2·3·4·5·6·7)의 날짜 필터 동작을 변경하지 않는다.

### 1.3 문제점

| # | 문제 | 영향 |
|:-:|------|------|
| 1 | 서버 조회가 선택일자 당일로 한정 | 지시일자를 정확히 알아야 대상이 조회됨 |
| 2 | **JSP만 `>=`로 바꾸면 계근 불가** | `DBHandler:99`가 `GI_REQ_DATE = selectDay`로 다시 걸러냄 |

**2번 상세** — 서버에서 `20260807` 건을 받아 `TB_SHIPMENT`에 저장해도, 계근 화면에서 `selectqueryShipment()`가 `GI_REQ_DATE = '20260805'` 조건으로 조회하므로 해당 건이 나오지 않는다. 목록에는 담기지만 스캔 시 "조회결과가 없습니다"가 표시된다.

### 1.4 Oracle 원본

`VW_PDA_WID_PRO_LIST`
```sql
AND A.GI_REQ_DATE >= TO_CHAR(SYSDATE,'YYYYMMDD')
```

원본은 **오늘 이후 전부**를 조회했다. MSSQL 전환 시 다른 searchType과 형식을 맞추느라 `=`가 되었다(개발59 §4.2).

## 5. 사이드이펙트

### 5.1 다른 searchType 영향

**없음.** `DBHandler:99` 조건을 제거하지 않고 `searchType == "1"`일 때만 건너뛴다.

| searchType | 날짜 조건 |
|:--:|---|
| 0·2·3·4·5·6·7 | `AND GI_REQ_DATE = selectDay` (기존 유지) |
| **1** | **조건 없음** |

### 5.2 생산 조회 범위 확대

선택일자 이후 지시가 모두 조회되므로 목록이 길어질 수 있다.

| | 변경 전 | 변경 후 |
|---|---|---|
| 서버 | `H.지시일자 = 선택일자` | `H.지시일자 >= 선택일자` |
| 로컬 | `GI_REQ_DATE = 선택일자` | 조건 없음 |

미계근 건만 조회되므로(`NOT EXISTS PD_생산계근`, 개발59 §4.2) 누적되지는 않는다.

### 5.3 원본 대비 동작

Oracle 원본 `GI_REQ_DATE >= SYSDATE`(오늘 이후)에 가까워진다. 다만 기준이 `SYSDATE`가 아니라 **앱에서 선택한 일자**다.

- **어떻게**: 앱 코드는 손대지 않고 JSP 치환 문자열만 수정했다. 다른 searchType 은 각자의 JSP 를 사용하므로 영향이 없다.
  - 검증: Tomcat 로그 `##search_production query :` 에서 `H.지시일자 >= '20260701'` 확인

## 9. 예상 문제점 및 해결 방안

| # | 문제점 | 원인 | 해결 방안 |
|:-:|--------|------|----------|
| 1 | 치환 후에도 `=`가 남음 | 컬럼명만 치환 | `"D.출고일자 = "` 전체를 치환 (§4.1) |
| 2 | 목록이 과도하게 길어짐 | 오래된 지시가 미계근 상태로 누적 | ERP에서 미완료 지시 정리 또는 조회 상한 검토 |
| 3 | 다른 searchType 날짜 필터 해제 | `DBHandler:99` 조건 제거 | 조건 제거가 아닌 분기 처리 (§4.2) |
| 4 | 앱 재빌드 누락 | Step 2가 앱 수정 | APK 재빌드·설치 필요 |
