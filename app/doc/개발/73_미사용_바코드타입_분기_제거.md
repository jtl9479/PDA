### 4.2 switch case 삭제 (Step 1) — 571~714행

**변경 전:** `case "M0"` -> `case "M1"` -> `"M3"` -> `"M4"` -> `"E0"` -> `"E1"` -> `"E2"` -> `"E3"` -> `"P0"` -> `case "M9"` -> `case "M8"`

**변경 후:** `case "M0"`(572~588행 그대로) -> `case "M9"`(716~729 그대로) -> `case "M8"`(731~744 그대로). 589~714행(M1~P0 case 전체, 714행 `break;` 및 715행 빈 줄 포함) 삭제.

**switch default 동작 (증명):**

| 입력 타입 | 변경 전 | 변경 후 | 유지 타입 동일? |
|-----------|---------|---------|:---------------:|
| M0 | case M0 | case M0 | 동일 |
| M9 | case M9 | case M9 | 동일 |
| M8 | case M8 | case M8 | 동일 |
| M1/M3/M4/E0~E3/P0 | 각 case 실행 | case 없음 -> default 없음 -> pBarcode*, pBarcodeStr* 모두 `""` 유지 | 해당 없음 (제거 대상) |

Java switch는 case 간 독립(각 case가 `break`로 종료)하므로 case를 삭제해도 인접 case의 실행에 영향이 없다. 삭제 구간 내 case는 모두 `break;`로 끝나고 fall-through 없음(확인함: 589~714행 각 case 마지막 `break;`).

## 9. 테스트 시나리오

### 시나리오 1: 이마트 M0 정량 라벨 변경 전후 비교

```
1. 변경 전 앱: 이마트(searchType=0) M0 출하건 다운로드 -> 계근 -> 출력 (hex/SHA 기록)
2. 변경 후 앱 설치 -> 동일 출하건 계근 -> 출력
3. 두 출력의 바이트/육안 비교 -> 일치 확인
```

### 시나리오 2: 비정량 M9, M8

```
1. 비정량(searchType=4) M9 출하건 계근/출력 (pBarcode2 미설정, 숫자 텍스트 75,240,20)
2. M8 (미등록이면 테스트 데이터 구성 또는 코드 경로 비교로 대체)
3. 변경 전후 비교
```

### 시나리오 3: 롯데 L0 / 홈플러스 H2·H5

```
1. 롯데(searchType=6) L0 계근/출력, 홈플러스(2,5) H2·H5 계근/출력
2. 변경 전후 비교 (코드 변경 없음 확인용 회귀)
```

### 시나리오 4: 미트센터·소비기한 경로

```
1. 패커코드 30228 + 스토어 9231 건: 소비기한 계산 문구 `/소비기한 : ` 동일 확인
2. 트레이더스/수입육 센터: `/소비기한: ` 동일 확인
3. M0 + 9231 + LOGIS/PLANT 조건별 추가 라벨 (917, 973행) 동일 확인
```

## 10. 예상 문제점 및 해결 방안

| # | 문제점 | 원인 | 해결 방안 |
|---|--------|------|----------|
| 1 | 제거 타입이 향후 매핑되면 빈 바코드 라벨 출력 | switch default 없음 -> pBarcode `""` | ERP 매핑 변경 시 타입 확인. 현 시점 E2(J1)는 JSP가 W/B만 조회하여 유입 불가 |
| 2 | 876행 정리 후 `tempDate` 중복 선언 컴파일 오류 | else 중괄호 제거 시 변수가 바깥 try 스코프로 이동, 950행 중첩 블록과 충돌 | else 본문을 단독 블록 `{ }`으로 유지 |
| 3 | 462/502행 소비기한 문구 혼동 | 두 else 문자열이 다름(`" : "` vs `": "`) | 각 위치의 기존 else 문자열 그대로 유지, diff로 확인 |
| 4 | 상수 먼저 삭제 시 컴파일 실패 | if 분기가 상수 참조 | Step 2 말미에 참조 0건 확인 후 삭제 |
| 5 | 845행 OR에서 M9 누락 | 제거 타입 정리 중 실수 | 변경 후 `M0 \|\| M8 \|\| M9` 확인, M9 비교 테스트 |
| 6 | 912행 조건 삭제 후 P0 데이터 출력 | P0는 기존 미출력 | 생산 투입 미사용, 유입 불가 |
| 7 | 임시 비교 로그가 커밋에 포함 | Step 3 임시 코드 | 비교 후 제거, git diff로 확인 |
| 8 | 미사용 파라미터 `currentWorkItem`, 변수 `pBarcode2` 경고 | 분기 제거 부산물 | 시그니처/변수 삭제 금지(범위 외), 경고만 허용 |
