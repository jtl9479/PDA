# 비정량 이마트 M9 바코드 신규 추가

**작성일**: 2026-04-27
**목적**: 비정량 이마트(searchType=4) 전용 신규 BARCODE_TYPE 'M9' 라벨 출력을 지원한다. 기존 M9 case는 정량 이마트(searchType=0)의 우육 센터납 용도이므로, 비정량 전용 분기를 기존 case 내부에 `if(Common.searchType.equals("4"))` 조건으로 추가한다. JSP WHERE 조건을 `IN ('M8', 'M9')`로 확장하여 M9 품목이 출하대상 조회 결과에 포함되도록 한다.

---

## AI 제약 조건

- 기존 WHERE 조건, 로직을 임의로 제거/추가/변경하지 않는다
- 문서에 명시된 step만 진행하고, 다음 step은 지시를 기다린다
- step 완료 후 체크리스트 + 진행 현황을 반드시 업데이트한다
- 문서에 없는 개선/리팩토링을 임의로 수행하지 않는다
- 기존 기능과 100% 동일하게 동작해야 한다

## 5. 사이드이펙트

### 5.1 기존 M9 case(정량 이마트 우육 센터납) 영향

기존 M9 case는 searchType=0(이마트), searchType=7(생산라벨) 등에서 사용된다. 변경 후에도 `else` 분기로 완전히 유지되므로 영향 없다.

- **대응 방안**: `else` 블록에 기존 코드 100% 동일 유지. 로그 문자열만 변경 없음.

### 5.2 라벨 인쇄 영역 분기 (M9 관련 L732~893)

비정량 M9도 BARCODE_TYPE='M9'를 반환하므로, `si.getBARCODE_TYPE().equals(BARCODE_TYPE_M9)` 조건이 적용되는 라벨 출력 영역(업체명, 지점명, 바코드 좌표, pBarcode2 인쇄, 가로선 등) 전체가 비정량 M9에도 동일하게 적용된다.

| 라벨 영역 | 현재 동작 (M9) | 비정량 M9 적용 여부 | 의도 부합 |
|----------|:-------------:|:-----------------:|:--------:|
| 업체명 `[회사명]` 출력 (L732~746) | M9 전용 표시 | 동일 적용 | 확인 필요 |
| 상품명 위치 (L766~768, itemX=15, itemY=70) | M9 전용 위치 | 동일 적용 | 확인 필요 |
| sBarcode 미출력 (L779) | M9 제외 | 동일 적용 | 확인 필요 |
| pBarcode 좌표 (L808~810, x=90, y=125) | M9 전용 좌표 | 동일 적용 | 확인 필요 |
| pBarcodeStr 위치 (L827~829, x=90, y=192) | M9 전용 위치 | 동일 적용 | 확인 필요 |
| pBarcode2 인쇄 (L836~843) | M9 인쇄 | 동일 적용됨 | **주의** |
| pBarcodeStr3 출력 (L841) | M9 전용 | 동일 적용됨 | **주의** |
| 납품일자 형식 (L865~869) | M9 전용 위치 | 동일 적용 | 확인 필요 |
| 가로선 (L891~893) | M9 전용 | 동일 적용 | 확인 필요 |

> **pBarcode2 인쇄 주의**: 사용자 명시 "pBarcode2 사용 여부: M8과 동일하게 변수 생성만 + 인쇄 안 함"이므로, 현재 M9 라벨 출력 분기(L836~843)에서 pBarcode2가 인쇄되는 것이 문제가 된다.
>
> **해결 방안**: L836 조건 `si.getBARCODE_TYPE().equals(BARCODE_TYPE_M9)` 블록 내에 `if (!Common.searchType.equals("4"))` 가드를 추가하여 비정량 M9에서는 pBarcode2 인쇄 생략. 이는 Step 2에서 함께 처리한다.

```
        if(Common.searchType.equals("4"))   ← Step 2 추가
            pBarcode = 상품코드(6)+중량(6)+회사코드(6)   ← 18자리
        else
            기존 정량 우육 센터납 로직
    ↓ 라벨 인쇄 (M8 라벨 디자인 동일 위치/폼)
    ★ pBarcode2 인쇄 분기(L836) 비정량 가드 처리 포함
```

### Step 1: search_production_nonfixed.jsp WHERE 조건 확장

**Part 1. 분석**
- 파일: `search_production_nonfixed.jsp`
- 범위: L128 (WHERE BARCODE_TYPE 조건 1줄)
- 용도: 비정량 출하대상 조회 시 M8 뿐만 아니라 M9 품목도 포함되도록 조건 확장
- 주의할 점: L127의 `COALESCE(M1.타입구분, M2.타입구분) IN ('J', 'B')` 조건은 건드리지 않는다. L128만 수정한다.

| 2 | 변경 조건 | L128 | `IN ('M8', 'M9')` — IN 절로 확장 |
| 3 | 인접 조건 | L127 | `IN ('J', 'B')` — 변경 없음 |

**Part 2. 변환 계획**
- 변환 방식: `= 'M8'` → `IN ('M8', 'M9')` 단순 문자열 치환
- 주의사항: Java String concatenation 형식(`+ "   AND COALESCE(...) IN ('M8', 'M9')"`) 유지. 들여쓰기/공백 기존과 동일하게 유지.

### Step 2: LabelPrintHelper M9 case에 비정량 분기 추가

**Part 1. 분석**
- 메서드: `LabelPrintHelper.setPrinting()`
- 범위: L648~669 (case "M9" 블록), L836~843 (M9 pBarcode2 인쇄 블록)
- 용도: searchType=4(비정량)일 때 M9 바코드를 18자리 형식(`상품코드6+중량6+회사코드6`)으로 생성. searchType=0(정량)은 기존 로직 100% 유지.
- 주의할 점:
  - `else` 블록에 기존 코드를 완전히 복사하여 정량 동작 변화 없음을 보장한다.
  - pBarcode2 인쇄 분기(L836)에 비정량 M9 가드(`if (!Common.searchType.equals("4"))`) 추가 필요 — 비정량 M9는 pBarcode2 미인쇄(M8과 동일 정책).
  - pBarcodeStr3도 비정량 M9에서는 불필요하므로 `else` 블록에만 유지.

| # | 항목 | 위치 | 내용 |
|---|------|------|------|
| 1 | case "M9" 분기 시작 | L648 | `if(Common.searchType.equals("4"))` 추가 |
| 2 | 비정량 pBarcode 형식 | 신규 | `EMARTITEM_CODE(6) + print_weight_str + pCompCode` (18자리) |
| 3 | 비정량 pBarcode2 | 신규 | M8과 동일 방식으로 변수 생성만, 인쇄 안 함 |
| 4 | 정량 M9 로직 | L648~669 else | 기존 코드 그대로 유지 |
| 5 | pBarcode2 인쇄 분기 | L836~843 | 비정량 M9 가드 조건 추가 |

**Part 2. 변환 계획**
- 변환 방식:
  1. case "M9" 블록 전체를 `if(Common.searchType.equals("4")) { ... } else { 기존코드 }` 구조로 변환
  2. L836~843 블록: `else if(si.getBARCODE_TYPE().equals(BARCODE_TYPE_M9))` 내에 `if (!Common.searchType.equals("4"))` 가드 추가
- 주의사항:
  - `Common.searchType`은 `Common.java`의 static 필드, null 여부 확인 불필요 (기존 코드에서도 동일하게 사용)
  - 비정량 M9 라벨 출력 영역(L732~893)에서 `BARCODE_TYPE_M9` 비교 분기는 그대로 적용되므로 라벨 디자인은 M9 폼 동일 → 사이드이펙트 섹션 참조하여 의도 확인 후 진행

## 9. 테스트 시나리오

### 시나리오 1: 비정량 M9 품목 출하대상 조회 확인

```
1. PDA 앱 실행 → searchType=4(비정량 이마트) 선택
2. 날짜 설정 → 출하대상 조회 실행
3. 조회 결과 목록에서 BARCODE_TYPE='M9' 품목 존재 여부 확인
4. 기존 M8 품목도 함께 조회되는지 확인
```

### 시나리오 2: 비정량 M9 라벨 인쇄 형식 확인

```
1. searchType=4 비정량 이마트 출하대상 조회
2. BARCODE_TYPE='M9' 품목 선택
3. 바코드 스캔 (계근)
4. 라벨 인쇄 실행
5. 인쇄된 라벨의 pBarcode가 18자리인지 확인
6. 바코드 구성: 상품코드(6) + 중량(6) + 회사코드(6) 확인
7. pBarcode2가 인쇄되지 않는지 확인 (M8 동일)
```

### 시나리오 3: 정량 M9 기존 동작 회귀 확인

```
1. PDA 앱 실행 → searchType=0(이마트) 선택
2. 출하대상 조회 → BARCODE_TYPE='M9' 품목 선택
3. 계근 → 라벨 인쇄
4. pBarcode = 상품코드(6) + 중량(6) + 회사코드 + 수입식별번호(12) 형식 확인
5. pBarcode2 인쇄 여부 확인 (기존: 인쇄됨, 변경 후도 동일해야 함)
```
