# 비정량 이마트 M9 바코드 신규 추가

**작성일**: 2026-04-27
**목적**: 비정량 이마트(searchType=4) 전용 BARCODE_TYPE 'M9' 라벨 출력을 지원한다. 문의사항 05 답변(2026-04-30)에 따라 기존 M9(정량 이마트 우육 센터납)은 임시 사용으로 종료되었으므로, 정량 M9 분기를 제거하고 M9 case 전체를 비정량 이마트 단독으로 재정의한다. JSP WHERE 조건을 `IN ('M8', 'M9')`로 확장하여 M9 품목이 비정량 출하대상 조회 결과에 포함되도록 한다.

---

## AI 제약 조건

- 기존 WHERE 조건, 로직을 임의로 제거/추가/변경하지 않는다
- 문서에 명시된 step만 진행하고, 다음 step은 지시를 기다린다
- step 완료 후 체크리스트 + 진행 현황을 반드시 업데이트한다
- 문서에 없는 개선/리팩토링을 임의로 수행하지 않는다
- 정량 이마트(searchType=0)의 M9 분기를 임의로 유지하거나 복구하지 않는다 — 문의사항 05 답변에 따라 정량 M9는 운영 종료 확정

### 문제점

- BARCODE_TYPE='M9' 품목이 CO_매출처품목코드매핑에 등록되어 있어도, search_production_nonfixed.jsp의 WHERE 조건이 `= 'M8'`이므로 비정량 출하대상 조회에서 누락됨

## 2. 변경 구조

### 데이터 흐름

#### 변경 전 (M9 비정량 — 불가)

```
[비정량 출하대상 조회]
    ↓ search_production_nonfixed.jsp
    ↓ WHERE BARCODE_TYPE = 'M8'   ← M9 품목 제외됨 (조회 불가)
```

#### 변경 후 (M9 비정량 — 가능)

```
[비정량 출하대상 조회]
    ↓ search_production_nonfixed.jsp
    ↓ WHERE BARCODE_TYPE IN ('M8', 'M9')   ← M9 품목 포함
    ↓ 출하대상 목록에 BARCODE_TYPE='M9' 항목 반환
    ↓
[라벨 인쇄 — LabelPrintHelper.setPrinting()]
    ↓ switch(si.getBARCODE_TYPE())
    ↓ case "M9":
        // 비정량 이마트 M9 단독 (정량 분기 제거)
        pBarcode = 상품코드(6) + 중량(6) + 회사코드(6)   ← 18자리
        pBarcode2 = 변수 생성만 (인쇄 안 함 — M8 동일)
    ↓
[라벨 빌드 영역 — M9 분기]
    ↓ M9 전용 분기 → M8 라벨 디자인으로 변경
    ↓ (업체명/저울스캔용/pBarcode2 인쇄/가로선 등 정량 M9 전용 요소 제거)
    ↓ 라벨 출력 → M8과 동일한 위치/폼 사용
```

#### 신규 M9 pBarcode 형식 (18자리)

```
상품코드(6) + 중량(6) + 회사코드(6)
   EMARTITEM_CODE.substring(0,6) + print_weight_str + pCompCode
```

#### 회사코드 6자리 출처 (확정)

`pCompCode = COMPANY_CODE = "610933"` (LabelPrintHelper.java:55 기존 상수, 6자리)
모든 이마트 BARCODE_TYPE(M0/M1/M3/M4/M8 등)이 동일 상수를 사용 중.

#### 정량 M9 종료 근거

문의사항 05 답변(2026-04-30): "기존에 M9은 임시적으로 했던 바코드 타입일 것 같습니다. 현재 비정량으로 기존타입 제거하고 추가하는게 맞다고 판단됩니다."
→ 정량 이마트(searchType=0)에서 M9 사용 종료. case "M9" 전체를 비정량 단독으로 재정의.

### 시나리오 1: 비정량 M9 품목 출하대상 조회 확인

```
1. PDA 앱 실행 → searchType=4(비정량 이마트) 선택
2. 날짜 설정 → 출하대상 조회 실행
3. 조회 결과 목록에서 BARCODE_TYPE='M9' 품목 존재 여부 확인
4. 기존 M8 품목도 함께 조회되는지 확인
```

### 시나리오 2: 비정량 M9 라벨 인쇄 형식 확인

```
1. searchType=4 비정량 이마트 출하대상 조회
2. BARCODE_TYPE='M9' 품목 선택
3. 바코드 스캔 (계근)
4. 라벨 인쇄 실행
5. 인쇄된 라벨의 pBarcode가 18자리인지 확인
6. 바코드 구성: 상품코드(6) + 중량(6) + 회사코드(6) 확인
7. pBarcode2가 인쇄되지 않는지 확인 (M8 동일)
8. 저울스캔용 텍스트, 가로선 미표시 확인
9. sBarcode 표시 확인 (기존 정량 M9는 미표시였으나 비정량 M9는 기본 흐름으로 표시)
```

### 시나리오 3: 비정량 M8 기존 동작 회귀 확인

```
1. PDA 앱 실행 → searchType=4(비정량 이마트) 선택
2. 출하대상 조회 → BARCODE_TYPE='M8' 품목 선택
3. 계근 → 라벨 인쇄
4. pBarcode 형식 기존과 동일한지 확인 (상품코드6+중량6+회사코드+수입식별번호12)
5. 라벨 디자인 기존 M8과 동일한지 확인
```

## 10. 예상 문제점 및 해결 방안

| # | 문제점 | 원인 | 해결 방안 |
|---|--------|------|----------|
| 1 | 비정량 M9 라벨에 sBarcode가 표시되어 의도와 다를 수 있음 | 기존 M9는 sBarcode 미출력이었으나 분기 제거 후 기본 흐름으로 표시됨 | 사용자 명시 "M8과 동일한 폼"을 기준으로 M8도 sBarcode 표시되므로 의도에 부합. 테스트 시 확인 |
| 2 | 비정량 M9 납품일자 영역 변경에 따른 라벨 레이아웃 차이 | 기존 M9는 별도 위치(y=220), 변경 후 M8 기본 영역(중량+납품일자+업체정보) | M8과 동일한 라벨 디자인이 목표이므로 의도에 부합. 테스트 시 실물 확인 |
| 3 | search_production_nonfixed.jsp WHERE 확장 후 M9 품목의 타입구분 조건 부합 여부 불명확 | M9 품목의 `COALESCE(M1.타입구분, M2.타입구분) = 'B'` 해당 여부 | ERP CO_매출처품목코드매핑에서 M9 품목의 타입구분 값 사전 확인 필요 |
| 4 | pBarcodeStr 위치 분기(L814) M9 추가 누락 | L827~829 M9 분기 제거 시 L814 조건 수정 미누락 가능 | Step 3 체크리스트 항목 5에서 L814 조건 M9 추가를 명시적으로 처리 |
| 5 | 정량 이마트에서 M9 품목이 아직 ERP에 남아 있는 경우 18자리 바코드로 처리됨 | case "M9" 정량 분기 제거 | 운영팀 답변에 따라 정량 M9 운영 종료 확정. ERP 매핑 테이블 정리 여부 운영팀 확인 권장 |
