# 비정량 이마트 타입구분 J 제외 B만 사용

**작성일**: 2026-04-27
**목적**: 비정량 이마트(searchType=4) 출하대상 조회 WHERE 조건에서 'J'(가공육)를 제외하고 'B'(비정량)만 사용하도록 JSP 1줄 수정

---

## AI 제약 조건

- 기존 WHERE 조건, 로직을 임의로 제거/추가/변경하지 않는다
- 문서에 명시된 step만 진행하고, 다음 step은 지시를 기다린다
- step 완료 후 체크리스트 + 진행 현황을 반드시 업데이트한다
- 문서에 없는 개선/리팩토링을 임의로 수행하지 않는다
- 이 변경은 비정량 이마트(searchType=4) 한정이며, 다른 searchType·다른 BARCODE_TYPE에 임의 확장 금지

---

## 1. 현재 구조

### search_production_nonfixed.jsp:127

```jsp
+ "   AND COALESCE(M1.타입구분, M2.타입구분) IN ('J', 'B')"
```

- 비정량 이마트(searchType=4) 출하대상 조회 시 타입구분이 'J'(가공육) 또는 'B'(비정량)인 품목을 모두 조회함
- 원본 Oracle VIEW(`VW_PDA_WID_LIST_NONFIXED`)에도 동일하게 `EB.ITEM_TYPE IN ('J', 'B')` 조건이 존재하여 이 상태로 전환됨

### 문제점

- 'J'(가공육)는 비정량과 다른 카테고리이나, 비정량 출하대상 조회에 함께 포함되고 있음
- 문의사항 Q01 답변에 따라 비정량 출하대상이라면 'B'(비정량)만 사용해도 무방함이 확인됨

---

## 2. 변경 구조

### 데이터 흐름

```
변경 전:
COALESCE(M1.타입구분, M2.타입구분) IN ('J', 'B')
    → 가공육(J) + 비정량(B) 모두 출하대상에 포함

변경 후:
COALESCE(M1.타입구분, M2.타입구분) = 'B'
    → 비정량(B)만 출하대상에 포함
    → 가공육(J) 타입구분 품목은 조회 결과에서 제외됨
```

## 5. 사이드이펙트

### 조회 결과 변화 (비정량 이마트 searchType=4)

- `CO_매출처품목코드매핑.타입구분` 값이 'J'(가공육)로 등록된 품목은 비정량 이마트 출하대상 조회에서 제외됨
- 기존에 'J' 타입구분 품목이 출하대상 목록에 표시되던 케이스가 있다면 해당 품목이 사라짐
- 문의사항 Q01 답변 근거: 비정량 출하대상이라면 'B'만 사용해도 무방

### 영향 없음 (변경 범위 외)

| 항목 | 이유 |
|------|------|
| 이마트 정량(searchType=0) | `= 'W'` 조건 사용, 별도 JSP(`search_shipment.jsp`) |
| 홈플러스 정량(searchType=2) | `ITEM_TYPE = 'W'` 조건 사용, 별도 JSP |
| 도매(searchType=3) | 타입구분 J/B 조건 자체 없음, 별도 JSP |
| 비정량 홈플러스(searchType=5) | `BARCODE_TYPE = 'H5'` 조건 사용, 별도 JSP(`search_homeplus_nonfixed.jsp`) |
| 생산(searchType=1/7) | 별도 JSP(`search_production.jsp` 등) |
| 롯데(searchType=6) | `BARCODE_TYPE LIKE 'L%'` 조건 사용, 별도 JSP |
| BixolonShipmentActivity 흐름 | JSP 응답 파싱 로직 변경 없음 |
| ProgressDlgShipSearch 파싱 | 인덱스 구조 변경 없음, 조회 결과 건수만 달라질 수 있음 |

## 10. 예상 문제점 및 해결 방안

| # | 문제점 | 원인 | 해결 방안 |
