# 이마트 출하대상 통합 테스트

**작성일**: 2026-04-02
**목적**: 이마트 출하대상받기 버튼 클릭 시 전체 서버 조회 흐름 검증 및 JSP 불일치 수정

---

## AI 제약 조건

- 기존 WHERE 조건, 로직을 임의로 제거/추가/변경하지 않는다
- 문서에 명시된 step만 진행하고, 다음 step은 지시를 기다린다
- step 완료 후 체크리스트 + 진행 현황을 반드시 업데이트한다
- 문서에 없는 개선/리팩토링을 임의로 수행하지 않는다
- 기존 기능과 100% 동일하게 동작해야 한다

## 1. 현재 구조

### 전체 호출 흐름

이마트 출하대상받기 버튼 클릭 시 3개의 AsyncTask가 순차 실행됩니다.

```
[MainActivity] 이마트 출하대상받기 버튼
    ↓
① ProgressDlgShipSearch (출하대상 조회)
    → search_shipment.jsp 호출
    → 응답 파싱 → SQLite TB_SHIPMENT 저장
    ↓ onPostExecute에서 자동 실행
② ProgressDlgBarcodeSearch (바코드 정보 조회)
    → search_barcode_info.jsp 호출
    → 응답 파싱 → SQLite TB_BARCODE_INFO 저장
    ↓ onPostExecute에서 자동 실행
③ ProgressDlgGoodsWetSearch (계근 내역 조회)
    → search_goods_wet.jsp 호출
    → 응답 파싱 → SQLite TB_GOODS_WET 저장
    ↓ onPostExecute
[완료] 바코드정보 없는 상품 다이얼로그 표시
```

### 각 JSP 현재 상태

| JSP | 현재 상태 | 문제점 |
|-----|----------|--------|
| search_shipment.jsp | ✅ 수정 완료 | 없음 (18번 문서 기반) |
| search_barcode_info.jsp | ⚠️ 수정 필요 | 테이블 별칭 누락, 앱 WHERE 컬럼명 불일치 |
| search_goods_wet.jsp | ⚠️ 수정 필요 | WHERE 별칭 사용 불가, BOX_ORDER 컬럼 누락 |

### 문제점

1. search_barcode_info.jsp — `CO_품목코드` 테이블에 `SBI` 별칭 없음, 앱에서 `SBI.PACKER_PRODUCT_CODE`(SELECT 별칭)로 WHERE 조건 전달하지만 실제 컬럼명은 `PPCODE`
2. search_goods_wet.jsp — 앱에서 `GI_D_ID`(SELECT 별칭)로 WHERE 조건 전달하지만 실제 컬럼명은 `출고상세SEQ`
3. search_goods_wet.jsp — JSP 12개 컬럼 출력, 앱 13개 파싱 (BOX_ORDER 누락)

## 5. 사이드이펙트

### ProgressDlgBarcodeSearch.java — 비정량(searchType 4, 5) 영향

```java
// searchType 4, 5는 SBI.ITEM_CODE로 조회 (별도 분기)
// searchType 0만 SBI.PPCODE로 변경하므로 영향 없음
```

- searchType 0, 1, 2, 3, 6, 7: `SBI.PPCODE` 사용 → 모두 동일 JSP(`search_barcode_info.jsp`) 호출하므로 별칭 SBI 추가 영향 받음
- searchType 4, 5: `SBI.ITEM_CODE` 사용 → 별도 JSP 호출이므로 영향 없음

### ProgressDlgGoodsWetSearch.java — 모든 searchType 공통

- `출고상세SEQ`로 변경은 모든 searchType에서 동일하게 `search_goods_wet.jsp`를 호출하므로 공통 영향
- SM_출고계근 테이블의 실제 컬럼명이 `출고상세SEQ`이므로 정상

### search_goods_wet.jsp — BOX_ORDER 빈값

- 원본 Oracle에서는 `W_GOODS_WET.BOX_ORDER` 컬럼이 존재했으나 MSSQL `SM_출고계근`에는 없음
- 빈값(`''`)으로 대체하므로 앱에서 `setBOX_ORDER("")` → 기능에 영향 확인 필요

```
2. 앱 실행 → 로그인
3. 날짜 선택 (출고 데이터가 있는 날짜)

5. 이마트 출하대상받기 버튼 클릭
6. 로딩 다이얼로그 3단계 (출하대상 → 바코드정보 → 계근정보) 확인
7. 바코드정보 없는 상품 다이얼로그 확인
8. 이마트 계근입력시작 → 출하대상 리스트 확인
```
