# 비정량(searchType=4) 출하대상 WHERE 조건 `IN ('J', 'B')` 중 'J' 포함 여부


---

## 1. 질문 요지 (한 줄)

비정량 출하대상 조회 쿼리의 `타입구분 IN ('J', 'B')` 조건에서 **'J'(가공육)가 '비정량'과 다른 카테고리임에도 왜 비정량 출하대상 조회에 함께 포함되는가?**

---

## 2. 발견 경위

- `search_production_nonfixed.jsp`의 WHERE 조건 분석 과정에서 정량(`'W'`) vs 비정량(`IN ('J', 'B')`) 차이 확인
- 사용자 확인 결과: `B = 비정량`(확정), `J = 가공육` (비정량과 다른 카테고리)

---

## 3. 기술적 사실 (확정)

| 항목 | 내용 | 근거 위치 |
|------|------|----------|
| 1 | MSSQL JSP에 `IN ('J', 'B')` 조건 존재 | `search_production_nonfixed.jsp:127` |
| 2 | 원본 Oracle VIEW에도 동일 `IN ('J', 'B')` 조건 존재 | `app/doc/view/VW_PDA_WID_LIST_NONFIXED:127` |
| 3 | MSSQL 전환 과정에서 조건을 새로 추가한 것이 아니라 원본 그대로 이관됨 | 개발35 (비정량 출하대상 전환) |
| 4 | CLAUDE.md 제1원칙(원본과 100% 동일 동작) 준수 상태 | 자동 검증 (소스분석44·⑤ code-verifier PASS) |
| 5 | 정량(이마트) JSP는 `= 'W'` 조건만 사용 (가공육 포함 안 함) | `search_shipment.jsp:116` |

## 4. 확인 요청 사항

### 🔑 핵심 질문

**비정량 진행 시 타입구분 J + B 둘 다 포함하면 되는가?**

- 즉 `COALESCE(M1.타입구분, M2.타입구분) IN ('J', 'B')` 조건을 **현 상태 그대로 유지**해도 업무상 문제없는가?
- 아니면 **'J'(가공육)를 제외하고 'B'만 사용**해야 하는가?
