## 1. 질문 요지 (한 줄)

비정량 출하대상 조회 쿼리의 `타입구분 IN ('J', 'B')` 조건에서 **'J'(가공육)가 '비정량'과 다른 카테고리임에도 왜 비정량 출하대상 조회에 함께 포함되는가?**

---

## 2. 발견 경위

- 2026-04-22 비정량 JSP MSSQL 전환(개발35/36) 검토 중 발견
- `search_production_nonfixed.jsp`의 WHERE 조건 분석 과정에서 정량(`'W'`) vs 비정량(`IN ('J', 'B')`) 차이 확인
- 사용자 확인 결과: `B = 비정량`(확정), `J = 가공육` (비정량과 다른 카테고리)

## 4. 비즈니스 의문점

- 'J' = 가공육은 정량/비정량과 별개의 상품 카테고리로 이해됨
- 가공육(J)은 자체적으로 별도 출하대상 라인을 가져야 하는 것 아닌가?
- 비정량 출하대상 조회 시 'J'가 함께 조회되면 **현장에서 혼동 발생 가능성** 존재
- 원본 Oracle VIEW 설계 당시 '비정량 계근 대상' 정의가 'B 전용'이었는지, 'J+B 통합 대상'이었는지 불확실

## 5. 가능한 해석

| 해석 | 내용 | 가능성 |

| A | 원본 설계 의도: 이마트 비정량 라인에서 가공육(J)도 현장 계근 대상으로 취급하는 업무 규칙이 있었음 | 중간 |
| B | 원본 설계 오류: J가 실수로 포함됐으나 수년간 운영되면서 고착화됨 | 중간 |
| C | 운영 환경 차이: 과거에는 J/B 모두 조회되었으나 현재는 J 데이터가 생성되지 않아 실질 영향 없음 | 낮음 |

## 6. 확인 요청 사항

1. 이마트 비정량 출하대상 조회 시 가공육(J) 항목이 현장에서 실제로 표시·계근 처리되는가?
2. 원본 VIEW(`VW_PDA_WID_LIST_NONFIXED`) 설계 당시 'J+B 통합'이 의도된 업무 규칙이었는가?
3. 만약 'J' 제외가 필요하다면, 과거 데이터·연관 프로세스에 대한 영향 범위는?
4. 제외 결정 시 원본 프로그램도 함께 수정 대상인가, 아니면 MSSQL 버전만 수정하는가?
