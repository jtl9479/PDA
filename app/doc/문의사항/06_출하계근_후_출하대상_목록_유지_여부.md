## 1. 질문 요지 (한 줄)

원본 시스템에서 출하 계근 시 `PACKING_QTY` UPDATE가 주석 처리되어 있어, **계근해도 출하대상 목록에 계속 표시되는 동작이 원본의 실제 동작**임이 확인되었습니다. MSSQL 전환 시 (1) 원본 동작 유지 vs (2) NOT EXISTS 신규 추가로 미계근만 표시 vs (3) 부분 계근 정책 — 어느 동작이 운영상 올바른지 확인 필요합니다.

---

## 2. 발견 경위

- 04번 문서(`출하대상받기 4유형 조회조건 종합정리`) 검증 중 정량/비정량 이마트 JSP의 WHERE 절에 미계근 조건 누락 발견
- 미계근 조건 추가 가이드(개발46) 작성 + 사전 커밋 완료
- ⑥ `original-comparator` 사전 검증 단계에서 **원본 `insert_goods_wet.jsp`의 PACKING_QTY 갱신 UPDATE가 주석 처리(`/* ... */`)되어 있음** 발견
- 즉 원본 Oracle 시스템도 실질적으로는 미계근 필터가 작동하지 않았음
- 04번 문서가 원본 VIEW의 텍스트(WHERE 본문에 `PACKING_QTY = 0` 존재)만 보고 작성되어, 실제 갱신 부재 사실은 누락 상태

## 4. 비즈니스 의문점

- 의문 1: 원본 시스템에서 `PACKING_QTY` UPDATE를 주석 처리한 것은 **의도된 운영 결정**인가, 아니면 **미완성/미적용 코드**인가?
- 의문 2: PDA 사용자(현장 작업자)가 출하 계근 완료 후 **동일 출하 건이 목록에 계속 표시되는 게 정상**인가? (중복 계근 위험 가능성)
- 의문 3: 부분 계근(예: 박스 3개 중 1개만 계근) 케이스에서 출하대상 유지 vs 제외 정책은 어느 쪽이 운영상 올바른가?
- 의문 4: 롯데/원앤원 전용 `insert_goods_wet_ono.jsp`만 PACKING_QTY 갱신이 살아있는 이유는? (마트사별로 다른 정책인가?)

## 5. 가능한 해석

| 해석 | 내용 | 가능성 |
|:----:|------|:----:|
| **A** | 원본 동작 그대로 유지 — 계근해도 목록에 계속 표시 (별도 화면/필드로 계근 진행 상황 파악) | 낮음 (PDA 운영 비효율 가능성) |
| **B** | NOT EXISTS 신규 추가 — 미계근 건만 표시 (계근 완료 시 즉시 목록에서 제외) | 높음 (운영상 자연스러움) |
| **C** | 부분 계근 시 정책: 1건이라도 계근 시 목록에서 제외 (NOT EXISTS) | 중간 (부분 계근 운영 빈도에 따라) |
| **D** | 부분 계근 시 정책: 전량 계근 후에만 제외 (LEFT JOIN + SUM 카운트 = 0) | 중간 (운영상 정확) |
| **E** | 마트사별로 다른 정책 (예: 이마트=NOT EXISTS, 롯데=PACKING_QTY 갱신, 도매=원본 동작 유지 등) | 낮음 (복잡도 증가) |

## 6. 확인 요청 사항

1. **원본 시스템에서 `PACKING_QTY` 갱신 UPDATE를 주석 처리한 이유**는 무엇입니까? (의도된 결정 vs 미완성 코드)
2. **PDA 출하대상 조회에서 계근 완료된 건**이 목록에 계속 표시되는 게 정상 동작입니까? 아니면 목록에서 사라지는 게 운영 의도입니까?
3. **부분 계근 케이스**(여러 박스 중 일부만 계근)에서 해당 출하 건은 출하대상 목록에 유지되어야 합니까, 아니면 제외되어야 합니까? (전량 계근 후 제외 vs 1건이라도 계근 시 제외)
4. NOT EXISTS 추가가 옳다면, **정량/비정량/홈플 정량/홈플 비정량/도매/롯데** 6개 JSP에 동일하게 적용해야 합니까? (롯데 VIEW는 원본부터 PACKING_QTY 조건 자체가 주석 처리됨 — 롯데는 별도 정책일 가능성)
5. 롯데/원앤원 전용 `insert_goods_wet_ono.jsp`만 PACKING_QTY 갱신이 살아있는 이유와, MSSQL 전환 시 어떻게 처리해야 하는지?

## 7. 조치 방향 (답변 전까지)

- **답변 수신 전**: 가이드 46(NOT EXISTS 추가) 작성·사전 커밋 완료(`78e5d31`/`d2c5e4a`)되었으나 **코드 수정 보류**. 답변 수신 후 진행 결정.
- **답변 수신 후 예상 조치**:
  - 해석 A 채택 시: 가이드 46 폐기, 코드 수정 안 함, 04번 명세 정정
  - 해석 B + C 채택 시: 가이드 46 그대로 진행, 단 가이드 전제("원본 복원")를 "신규 운영 개선 기능 추가"로 재작성
  - 해석 B + D 채택 시: 가이드 46 재작성, NOT EXISTS 대신 `LEFT JOIN + SUM` 방식으로 변경
  - 해석 E 채택 시: 마트사별 별도 정책 가이드 다수 작성
