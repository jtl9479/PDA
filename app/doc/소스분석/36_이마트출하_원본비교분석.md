## 1. 기능에 영향 있는 차이점

### 1.1 파싱 인덱스 구조 변경 (ProgressDlgShipSearch)

| 항목 | 원본 | 현재 |
|------|------|------|
| 총 컬럼 수 | 38개 (기본 32 + searchType별 추가) | 30개 (기본 24 + searchType별 추가) |
| 시작 컬럼 | temp[0]=GI_H_ID, temp[1]=GI_D_ID, temp[2]=EOI_ID | temp[0]=GI_D_ID, temp[1]=ITEM_CODE |
| 제거된 컬럼 | - | GI_H_ID, EOI_ID, AMOUNT, GOODS_R_ID, GR_REF_NO, BRANDNAME, PACKERNAME, EMARTLOGIS_NAME |

**원인**: MSSQL 전환 시 Oracle VIEW 전용 컬럼(GI_H_ID, EOI_ID 등) 제거

### 1.2 WHERE 조건 컬럼명 변경

| 파일 | 원본 | 현재 |
|------|------|------|
| ProgressDlgShipSearch (출하대상) | `WHERE GI_REQ_DATE = '...'` | `AND D.출고일자 = '...'` |
| ProgressDlgShipSearch (창고) | `AND GR_WAREHOUSE_CODE = 'IN10273'` | `AND D.창고코드 = '...'` |
| ProgressDlgBarcodeSearch (바코드) | `SBI.PACKER_PRODUCT_CODE = '...'` | `SBI.PPCODE = '...'` |
| ProgressDlgGoodsWetSearch (계근) | `GI_D_ID = '...'` | `출고상세SEQ = '...'` |

**원인**: Oracle VIEW 별칭 → MSSQL 실제 컬럼명

### 1.3 WHERE 조건 구조 변경

| 항목 | 원본 | 현재 |
|------|------|------|
| 시작 키워드 | `WHERE` (앱에서 WHERE 시작) | `AND` (JSP에 WHERE 이미 있음) |
| 회사코드 | 없음 (VIEW에서 처리) | `AND D.회사코드 = '20'` (앱에서 전달) |

### 1.4 창고 조건 처리

| 항목 | 원본 | 현재 |
|------|------|------|
| 방식 | 창고명 하드코딩 if-else 20개 | `Common.selectWarehouseCode` 1줄 |
| 예시 | `if(Common.selectWarehouse.equals("삼일냉장")) data += " AND GR_WAREHOUSE_CODE = 'IN10273'"` | `if (!Common.selectWarehouseCode.isEmpty()) data += " AND D.창고코드 = '" + Common.selectWarehouseCode + "'"` |

**원인**: 15번 문서(창고목록 서버조회) 구현

### 1.5 split 처리

| 항목 | 원본 | 현재 |
|------|------|------|
| 코드 | `temp = s.split("::")` | `temp = s.split("::", -1)` |
| trailing 빈값 | 제거됨 → 마지막 컬럼 빈값 시 에러 | 유지됨 → 정상 파싱 |

**원인**: 05번 오류문서(JSP 마지막컬럼 빈값 파싱오류) 해결
