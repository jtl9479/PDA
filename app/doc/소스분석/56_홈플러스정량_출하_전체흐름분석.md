### 2.3 MSSQL 전환 목표 (search_shipment_homeplus.jsp)

Oracle VIEW → **MSSQL 직접 JOIN 쿼리**로 교체. 홈플러스 고유 컬럼 구조 유지.

- 출력 컬럼 수: 32개 → **24개** (Java 미파싱 8개 제거, 추가 없음)
- 제거 기준: Java(ProgressDlgShipSearch)에서 파싱하지 않는 컬럼
- 제거 컬럼 (8개): GI_H_ID, EOI_ID, AMOUNT, GOODS_R_ID, GR_REF_NO, BRANDNAME, PACKERNAME, EMARTLOGIS_NAME
- 홈플러스 전용 마트사구분 조건 (ERP 기준 확인 필요)
- ORDER BY: `HOMPLUS_STORE_CODE ASC, PACKER_PRODUCT_CODE ASC, ITEM_NAME ASC, EOI_ID ASC` 유지

### 2.4 Oracle VIEW 분석 (VW_PDA_WID_HOMEPLUS_LIST)

Oracle VIEW가 제공하는 26개 컬럼:
`GI_D_ID, ITEM_CODE, ITEM_NAME, EMARTITEM_CODE, EMARTITEM, GI_REQ_PKG, GI_REQ_QTY, GI_REQ_DATE, BL_NO, BRAND_CODE, CLIENT_CODE, CLIENTNAME, CENTERNAME, ITEM_SPEC, CT_CODE, PACKER_CODE, IMPORT_ID_NO, PACKER_PRODUCT_CODE, BARCODE_TYPE, ITEM_TYPE, PACKWEIGHT, BARCODEGOODS, STORE_IN_DATE, GR_WAREHOUSE_CODE, EMARTLOGIS_CODE, HOMPLUS_STORE_CODE`

JSP에서 출력하는 32개 중 VIEW에 없는 8개 (Oracle 직접 조회):
`GI_H_ID, EOI_ID, AMOUNT, GOODS_R_ID, GR_REF_NO, BRANDNAME, PACKERNAME, EMARTLOGIS_NAME`

→ 이 8개는 MSSQL 전환 시 **제거 대상**.

Oracle VIEW 내부 JOIN 구조 (MSSQL 전환 시 참조):
- `W_GOODS_IH` → SM_출고머리 (H)
- `W_GOODS_ID` → SM_출고상세 (D)
- `W_GOODS_R` → SM_수주상세 (SD)
- `I_BL_D` / `I_OFFER_D` → SM_출고LOT (L)
- `W_E_ORDER_ITEM` → SM_마트사발주홈플러스 (HE) — ERP 확인 필요
- `B_EMART_BARCODE` → CO_매출처품목코드매핑 (M)
- `B_COMMON_CODE` → CO_각종소분류코드 (BCC)
- ITEM_TYPE: Oracle에서 `'S'` 하드코딩 → MSSQL 전환 시 검토 필요
