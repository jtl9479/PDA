# 이마트 출하 조회 → 계근 → 서버 전송 → ERP 확인 전체 흐름

**작성일**: 2026-04-06
**현재 작업 범위**: search_shipment.jsp 조회 → SM_출고계근 INSERT → ERP 데이터 확인

**원칙**: 회사코드 및 하드코딩 변경을 제외한 나머지는 원본과 100% 동일해야 한다. (CLAUDE.md)

---

## 1. 전체 흐름도

```
[1단계] 출하대상 조회
  PDA (ProgressDlgShipSearch)
    → search_shipment.jsp (MSSQL 15개 테이블 JOIN)
    → 응답 파싱 (temp[0]~temp[29])
    → TB_SHIPMENT INSERT (로컬 SQLite)

[1-1단계] 바코드 정보 조회 (1단계 완료 후 자동 실행)
  PDA (ProgressDlgBarcodeSearch)
    → search_barcode_info.jsp (CO_품목코드 등 MSSQL)
    → 응답 파싱 (temp[0]~temp[24])
    → TB_BARCODE_INFO INSERT (로컬 SQLite)
    ※ 바코드 파싱 규칙이 없으면 2단계 계근 불가

[2단계] 바코드 스캔 → 계근
  PDA (BixolonShipmentActivity)
    → 1차 스캔 (상품 바코드) → TB_BARCODE_INFO에서 패커상품코드 매칭
    → 2차 스캔 (BL번호) → 중량 추출
    → TB_GOODS_WET INSERT (로컬 SQLite, SAVE_TYPE='F')
    → 라벨 출력

[3단계] 서버 전송
  PDA (ProgressDlgShipmentSend)
    → TB_GOODS_WET에서 SAVE_TYPE='F' SELECT
    → packet 조립 (::구분자, 14개 필드)
    → insert_goods_wet.jsp 호출
    → SM_출고계근 INSERT (MSSQL)
    → 성공 시 SAVE_TYPE='F'→'Y' UPDATE

[4단계] ERP 데이터 확인
  PDA (ProgressDlgGoodsWetSearch)
    → search_goods_wet.jsp 호출
    → SM_출고계근 SELECT (13개 컬럼)
    → 결과 표시
```

### 2.4 PDA 파싱 (ProgressDlgShipSearch.java:194-285)

**응답 형식**: `컬럼1::컬럼2::...::컬럼N;;` (row는 `;;`구분, column은 `::`구분)

```java
String[] result = receiveData.split(";;");
for (String s : result) {
    temp = s.split("::", -1);
    si = new Shipments_Info();
    si.setGI_D_ID(temp[0]);              // index 0~23: 공통
    si.setITEM_CODE(temp[1]);
    // ... (temp[2]~temp[23])
    si.setEMARTLOGIS_CODE(temp[23]);
    
    // 이마트(0) 추가 필드: temp[24]~temp[29]
    si.setWH_AREA(temp[24]);
    si.setUSE_NAME(temp[25]);
    si.setUSE_CODE(temp[26]);
    si.setCT_NAME(temp[27]);
    si.setSTORE_CODE(temp[28]);
    si.setEMART_PLANT_CODE(temp[29]);
    
    si.setSAVE_TYPE("F");
    DBHandler.insertqueryShipment(mContext, si, "N");
}
```

**특이사항**: temp[6] (GI_REQ_QTY) 소수점 4자리 이상이면 1자리로 절사

```sql
SELECT 출고상세SEQ AS GI_D_ID
     , 계근중량 AS WEIGHT
     , 계근중량단위 AS WEIGHT_UNIT

     , 계근순번 AS BOX_CNT
     , 등록사원 AS REG_ID
     , 등록일자 AS REG_DATE
     , 등록시간 AS REG_TIME
     , 제조일자 AS MAKINGDATE
     , 박스시리얼 AS BOXSERIAL
     , '' AS BOX_ORDER
FROM SM_출고계근
WHERE [qry_where]
ORDER BY GI_D_ID ASC
```

## 8. 주의사항

### 8.1 splitData[10] 회사코드 문제

PDA packet[10]은 `ITEM_CODE`(품목코드)이지만, JSP에서 `SM_출고계근.회사코드`에 저장한다.
**원본(ShipmentActivity)도 동일한 구조**이므로 원칙에 따라 변경하지 않는다.

```
PDA: packet[10] = getITEM_CODE()         ← 품목코드
JSP: pstmt.setString(13, splitData[10])  ← SM_출고계근.회사코드에 저장
```

### 8.2 바코드 정보 데이터 필수 확인

CO_품목코드에 PPCODE, 상품바코드, WEIGHT_FROM/TO, BASEUNIT, ZEROPOINT 등
바코드 파싱 필수 값이 실제 존재해야 2단계 계근이 가능하다.
데이터 미존재 시 "바코드 정보가 없습니다" 오류 발생.

### 8.3 1-1단계 바코드 정보 조회 누락 시

ProgressDlgBarcodeSearch가 실패하거나 TB_BARCODE_INFO에 데이터가 없으면
`find_PackerProduct()` → `find_work_info()`에서 매칭 실패 → 계근 진행 불가.
