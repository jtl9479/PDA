# 롯데 라벨 제조일자 8자리 절사 (CO_품목코드 제조일자 위치값 6~13)

## 발견일
2026-10-06

## 에러 발생 시나리오

```
1. 롯데(searchType=6) 출하대상 09-29 다운로드 (바코드정보 포함)
2. 계근 바코드 `00631 20260929 1110100681` (중량 1~5 / 제조일 YYYYMMDD 6~13 / 품목 14~23) 스캔
3. 앱이 바코드정보의 제조일자 위치(6~13)로 절사 → 제조일 `20260929` (8자리)
4. L0 라벨 출력 → 제조일자 `2020년 26월 09일`, 바코드 22자리 `2026092906318809790012` (2자리 증가)
```

---

## 현상
- 롯데 L0 라벨 제조일자가 `2020년 26월 09일`로 출력됨
- 롯데 라벨 바코드에 제조일이 8자리로 들어가 바코드 길이가 2자리 늘어남 (`2026092906318809790012`)
- **SM_출고계근.제조일자에도 스캔 건은 `20260928` 8자리로 저장됨 (10건), 수기 입력 건(SEQ 242)만 `260928` 6자리**

## 원래부터 있던 버그인가?

**NO(코드 기준 원본과 동일, 데이터 문제) - 앱/JSP 코드는 원본과 동일하며, ERP 품목 마스터의 제조일자 위치값이 6자리(YYMMDD) 전제와 맞지 않아 발생**

```java
// 원본 ShipmentActivity.java:961 과 동일한 절사 방식 (현행 BixolonShipmentActivity.java:1351~1353)
item_making_date = work_item_fullbarcode.substring(
        Integer.parseInt(work_item_bi_info.getMAKINGDATE_FROM()) - 1,
        Integer.parseInt(work_item_bi_info.getMAKINGDATE_TO()));
```

## 원인

### 문제 1 (주요): CO_품목코드 1110100681 제조일자시작/끝이 6~13 (8자리 구간)

#### 코드 위치
- `search_barcode_info.jsp:50~51` : `제조일자시작 AS MAKINGDATE_FROM`, `제조일자끝 AS MAKINGDATE_TO` (CO_품목코드 값을 그대로 전달)
- `ProgressDlgBarcodeSearch.java:127~128` : temp[15]/temp[16] 파싱
- `BixolonShipmentActivity.java:1351~1353` (Type W), `:1402~1404`, `:1464~1466`, `:1725~1727` : 위치값으로 바코드 substring 절사

#### 현재 문제 코드
```java
// BixolonShipmentActivity.java:1351~1353
if (work_item_bi_info.getMAKINGDATE_FROM() != "" && work_item_bi_info.getMAKINGDATE_TO() != "") {
    item_making_date = work_item_fullbarcode.substring(
            Integer.parseInt(work_item_bi_info.getMAKINGDATE_FROM()) - 1, Integer.parseInt(work_item_bi_info.getMAKINGDATE_TO()));
// ★ 시작=6, 끝=13 → substring(5, 13) = 8자리 (YYYYMMDD)
```

ERP 데이터: `CO_품목코드` 품목코드 1110100681(돼지고기캠핑모둠팩) 제조일자시작=6, 제조일자끝=13. 6자리(YYMMDD) 전제라면 시작=8, 끝=13이어야 함.

#### 발생 시나리오
계근 바코드 `00631 20260929 1110100681`에서 6~13자리를 절사하면 `20260929`(8자리)가 된다.

### 문제 2 (보조): 라벨 출력부가 제조일자 6자리(YYMMDD)를 전제로 조립

#### 코드 위치
- `LabelPrintHelper.java:1312` (setPrintingLotte 제조일자 표기)
- `LabelPrintHelper.java:1209`, `:1211` (롯데 바코드 조립: 회사코드 + making_date + 중량4자리 + 품목6자리 + 박스번호)

#### 문제 코드
```java
// LabelPrintHelper.java:1312
String tempDate = "20" + making_date.substring(0, 2) + "년 " + making_date.substring(2, 4) + "월 " + making_date.substring(4, 6) + "일";
// ★ 8자리 20260929 입력 시 "20" + "20" + "년 " + "26" + "월 " + "09" + "일" = 2020년 26월 09일

// LabelPrintHelper.java:1209
pBarcode = pCompCode_lotte+making_date+print_weight_str.substring(...)+si.getEMARTITEM_CODE().substring(0, 6)+boxserial_cnt;
// ★ making_date가 8자리면 바코드가 2자리 증가
```

## 상세 흐름

1. **출하대상 다운로드** (롯데)
   - `search_barcode_info.jsp`가 CO_품목코드의 제조일자시작/끝을 MAKINGDATE_FROM/TO로 전송 → 앱 TB_BARCODE_INFO 저장
2. **바코드 스캔** (`00631202609291110100681`)
   - `BixolonShipmentActivity.java:1351~1353`에서 FROM-1 ~ TO 구간 substring
   - 위치값 6~13 → `20260929` (8자리)
3. **라벨 출력 / 저장** (setPrintingLotte, SM_출고계근 INSERT)
   - **경로 A (스캔)**: 8자리 그대로 라벨·바코드·SM_출고계근에 반영 → 오류 출력
   - **경로 B (수기 입력)**: 소비기한 입력 화면에서 6자리 입력 → 정상 (SEQ 242만 `260928`)

## 영향 범위
- 롯데(searchType=6) 중 CO_품목코드 제조일자 위치 구간이 6자리가 아닌 품목 (확인된 품목: 1110100681)
- 품목은 마트사 간 공유하지 않으므로 롯데만 영향 (이마트·홈플러스 등 타 마트 무영향)
- 파일: `BixolonShipmentActivity.java`, `LabelPrintHelper.java`, `search_barcode_info.jsp`는 코드 변경 없음 (원본 동일)
- 데이터: `SM_출고계근.제조일자` 8자리 저장 10건 (조치 전 계근분)

## 수정 방안

### 수정 1: ERP 품목 마스터 제조일자시작 보정 (데이터 수정, 코드 변경 없음)

```sql
UPDATE CO_품목코드
   SET 제조일자시작 = '8'
 WHERE 회사코드 = '20'
   AND 품목코드 = '1110100681'
   AND 제조일자시작 = '6';
-- 결과: 제조일자시작 8, 제조일자끝 13 (YYMMDD 6자리)
```

> ERP 품목코드관리 화면 저장은 규격 필수값 공백으로 불가하여 weberp_hl DB 직접 수정으로 진행.
> 앱 코드를 8자리 대응으로 바꾸지 않는다 (원본과 100% 동일 유지 원칙).
> 위치값 변경 후 앱에서 출하대상(바코드정보)을 재다운로드해야 반영된다.
