# M0 라벨 텍스트 품질 저하 — 비트맵 렌더링

## 발견일
2026-04-03

## 현상
- M0 라벨의 한글 텍스트가 원본 대비 흐릿하게 출력
- 바코드, 선 등 비텍스트 요소는 정상
- **원본 라벨은 선명하나 현재 라벨은 글씨가 뚜렷하지 않음**

## 원래부터 있던 버그인가?

**NO — 프린터 변경(Woosim → Bixolon)으로 텍스트 렌더링 방식이 변경되면서 발생.**

## 원인

### 문제 1 (주요): 텍스트 렌더링 방식 차이

#### 원본 (Woosim 프린터)

```java
// ShipmentActivity.java:1631~1641
byteStream.write(WoosimCmd.selectTTF("HYWULM.TTF"));   // 프린터 내장 TTF 폰트 선택
byteStream.write(WoosimCmd.getTTFcode(35, 35, text));   // 프린터가 직접 렌더링
```

- **렌더링 주체**: 프린터
- **방식**: 프린터 내장 TTF 폰트(HYWULM.TTF)를 프린터 해상도로 직접 렌더링
- **결과**: 선명

#### 현재 (Bixolon 프린터)

```java
// LabelPrintHelper.java:251~291
private byte[] slcsBitmapText(int x, int y, int size, String text, boolean bold) {
    Paint paint = new Paint();
    paint.setAntiAlias(false);  // 안티앨리어싱 OFF
    paint.setTextSize(size);

    Bitmap bitmap = Bitmap.createBitmap(textWidth, textHeight, Bitmap.Config.ARGB_8888);
    Canvas canvas = new Canvas(bitmap);
    canvas.drawText(text, 0, -fm.ascent, paint);

    // 비트맵을 1bpp 흑백 변환
    for (int row = 0; row < textHeight; row++) {
        for (int col = 0; col < textWidth; col++) {
            int pixel = bitmap.getPixel(col, row);
            int gray = (Color.red(pixel) + Color.green(pixel) + Color.blue(pixel)) / 3;
            if (gray < 128) { bitmapData[byteIndex] |= (1 << bitIndex); }
        }
    }
    // LD 명령으로 비트맵 이미지 전송
}
```

- **렌더링 주체**: 앱 (Android)
- **방식**: Android Canvas에서 비트맵 렌더링 → 1bpp 흑백 변환 → LD 명령으로 이미지 전송
- **결과**: 비트맵 변환 과정에서 품질 저하

### 비교

| 항목 | 원본 (Woosim) | 현재 (Bixolon) |
|------|--------------|---------------|
| 렌더링 주체 | 프린터 | 앱 (Android) |
| 폰트 | 프린터 내장 TTF (HYWULM.TTF) | 앱 로드 폰트 → 비트맵 변환 |
| 명령어 | `getTTFcode` (벡터) | `LD` (비트맵 이미지) |
| 안티앨리어싱 | 프린터 자체 처리 | OFF (1bpp 흑백이므로) |
| 품질 | 프린터 해상도 직접 출력 → **선명** | 비트맵 1bpp 변환 → **품질 저하** |

## 상세 흐름

1. **앱**: `slcsBitmapText()` 호출
2. **앱**: Android Paint로 텍스트를 Bitmap에 렌더링 (ARGB_8888)
3. **앱**: Bitmap 픽셀을 1bpp 흑백으로 변환 (gray < 128 → 검정)
4. **앱**: SLCS `LD` 명령으로 비트맵 데이터를 프린터에 전송
5. **프린터**: 비트맵 이미지를 그대로 인쇄

→ 3번 단계에서 안티앨리어싱이 없는 상태에서 1bpp 변환 시 글씨 가장자리가 계단현상(jagging) 발생

## 영향 범위
- `slcsBitmapText()`를 사용하는 모든 한글 텍스트 출력
- LabelPrintHelper.java: 720~863행 (M0 라벨 전체 한글 텍스트)
- 다른 바코드 타입(M1, E0~E3 등) 라벨도 동일

## 수정 방안

### 방법 1: 비트맵 2배 렌더링 후 축소 (난이도 낮음)

```java
// slcsBitmapText() 변경
// 2배 크기로 렌더링 후 축소 → 계단현상 감소
paint.setTextSize(size * 2);
Bitmap bigBitmap = Bitmap.createBitmap(textWidth * 2, textHeight * 2, ...);
Bitmap bitmap = Bitmap.createScaledBitmap(bigBitmap, textWidth, textHeight, true);
```

| 장점 | 단점 |
|------|------|
| 수정 1곳 | 비트맵 방식 유지 (근본 해결 아님) |

### 방법 2: SLCS V 명령어 벡터 폰트 사용 (난이도 중)

```java
// slcsBitmapText() → slcsText()로 교체
// V 명령어: 프린터 내장 벡터 폰트 사용
return "V" + x + "," + y + ",K," + width + "," + height + ",0,N,B,N,0,L,0,'" + text + "'\r\n";
```

| 장점 | 단점 |
|------|------|
| 프린터 자체 렌더링 → 선명 | 프린터 한글 벡터 폰트(K) 지원 확인 필요 |

### 방법 3: 프린터에 TTF 폰트 다운로드 (난이도 높음)

SLCS `TD` 명령으로 TTF 폰트를 프린터에 다운로드 후 사용.

| 장점 | 단점 |
|------|------|
| 원본과 동일한 방식 | 프린터 초기화 + TD 명령 구현 필요 |

### 권장 순서

```
방법 2 (V 명령어) 테스트
    ↓ 프린터 한글 지원 확인
지원 O → 방법 2 적용
지원 X → 방법 1 적용
```
