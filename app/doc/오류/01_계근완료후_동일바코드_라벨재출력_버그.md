# 계근 완료 후 동일 바코드 라벨 재출력 버그

## 발견일
2026-03-09

## 현상
- 계근수량이 4인 상품에서 동일 바코드를 반복 스캔할 경우
- 1~4번째까지는 중복 체크에 의해 정상적으로 차단됨
- **5번째 스캔 시 라벨이 다시 출력됨**

## 원래부터 있던 버그인가?

**YES - 원본부터 존재하는 버그이다.**

최초 커밋(`29626e5`)의 `ShipmentActivity.java` 651줄을 보면, `if (dup)` 분기가 **의도적으로 주석 처리(`/* */`)**되어 있었다:

```java
// 최초 커밋 원본 (29626e5) - 651줄
boolean dup = DBHandler.duplicatequeryGoodsWet_check(getApplicationContext(), msg);
/*                          ← 의도적으로 주석 처리!
if (dup) {
    Toast.makeText(..., "이미 스캔한 바코드입니다...");
    vibrator.vibrate(1000);
    work_item_fullbarcode = "";
    work_item_barcodegoods = "";
    return;
}
else {*/
// 최초 스캔일 경우
work_ppcode = find_ppcode;
work_item_fullbarcode = msg;
new ProgressDlgShipSelect(...).execute();
```

이후 리팩토링 과정에서 주석이 정리되면서 `dup` 결과를 사용하지 않는 코드만 남게 되었다.

## 원인

### 문제 1 (주요): 최초 스캔 분기에서 중복 체크 결과 미사용

#### 코드 위치
- `BixolonShipmentActivity.java` : 1198~1205줄
- `ShipmentActivity.java` (원본) : 984~991줄
- `ShipmentActivity.java` (최초 커밋) : 651줄 - **주석 처리로 비활성화**

#### 현재 문제 코드 (양쪽 동일)
```java
if (work_ppcode.equals("")) {
    boolean dup = DBHandler.duplicatequeryGoodsWet_check(getApplicationContext(), msg);
    // ★ dup 결과를 전혀 사용하지 않음! if(dup) 분기 없음
    work_ppcode = find_ppcode;
    work_item_fullbarcode = msg;
    new ProgressDlgShipSelect(...).execute();  // 중복이어도 그대로 진행
}
```

#### 발생 시나리오
4번째 계근 완료 후 `work_ppcode = ""`로 초기화되면, 5번째 스캔 시 최초 스캔 분기(1198줄)로 진입한다. 이 분기에서는 `duplicatequeryGoodsWet_check()` 결과를 **변수에만 담고 체크하지 않으므로** 중복 바코드여도 `ProgressDlgShipSelect`가 다시 실행되어 라벨 출력까지 이어진다.

### 문제 2 (보조): 계근 완료 후 return 누락

#### 코드 위치
- `BixolonShipmentActivity.java` : 1228~1231줄
- `ShipmentActivity.java` (원본) : 1014~1017줄

#### 문제 코드 (양쪽 동일)
```java
// 같은 상품 재스캔 분기 (work_ppcode == find_ppcode, dup == false)
if ((centerTotalCount > 0) && (centerTotalCount == centerWorkCount)) {
    show_wetFinishDialog();  // 완료 다이얼로그 표시
    // ★ return이 없어서 아래로 계속 진행
}
setBarcodeMsg(msg);  // 재귀호출 발생
```

## 상세 흐름

1. **1~3번째 스캔** (BL스캔 단계, `scan_flag = false`)
   - BL스캔 분기 진입
   - `duplicatequeryGoodsWet(바코드, GI_D_ID, PACKER_PRODUCT_CODE)`로 중복 체크
   - DB에 이미 존재하므로 **차단됨** ("이미 스캔한 바코드입니다")

2. **4번째 계근 완료 시**
   - `wet_data_insert()` 실행 → DB 저장, 라벨 출력
   - `PACKING_QTY`가 `GI_REQ_PKG`(4)와 같아짐
   - `set_scanFlag(true)` → **상품스캔 모드로 전환**

3. **5번째 스캔** (상품스캔 단계, `scan_flag = true`)
   - **경로 A**: `work_ppcode`가 초기화된 경우 → 최초 스캔 분기(1198줄) 진입 → `dup` 결과 무시 → 재조회/라벨 출력
   - **경로 B**: `work_ppcode`가 유지된 경우 → 같은 상품 분기(1206줄) 진입 → 계근완료 체크 후 `return` 없이 `setBarcodeMsg()` 재귀호출 → 라벨 출력

## 영향 범위
- **원본 버그**: 최초 커밋부터 존재 (개발자가 의도적으로 주석 처리한 코드)
- 정량 상품에서만 발생 (비정량은 `dup = false` 처리)
- `BixolonShipmentActivity`, `ShipmentActivity` 양쪽 동일
