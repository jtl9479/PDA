# 바코드 매칭 실패 — BARCODEGOODS 위치 설정 불일치

## 발견일
2026-04-03

## 현상
- 이마트 계근입력시작 후 M0 바코드 스캔 시 "조회결과가 없다" 표시
- **바코드 데이터는 정상이나 매칭 로직에서 불일치**

## 원래부터 있던 버그인가?

**NO — 테스트 데이터 입력 시 CO_품목코드의 바코드 위치 설정(BARCODEGOODS_FROM/TO)이 BARCODEGOODS 값의 자릿수와 맞지 않게 입력되어 발생.**

## 원인

### 문제 1 (주요): BARCODEGOODS 자릿수와 위치 설정 불일치

#### 코드 위치
- `BixolonShipmentActivity.java` : 1834~1835행

#### 현재 매칭 로직
```java
// 스캔 바코드에서 BARCODEGOODS_FROM ~ BARCODEGOODS_TO 위치 추출
temp_bg = req.substring(Integer.parseInt(bg_from) - 1, Integer.parseInt(bg_to));
// 추출한 값과 TB_BARCODE_INFO의 BARCODEGOODS 비교
if (temp_bg.equals(bg))  // barcodegoods find success
```

#### 발생 시나리오

| 항목 | 값 |
|------|------|
| TB_BARCODE_INFO.BARCODEGOODS | `11101006941234` (14자리) |
| CO_품목코드.바코드상품코드시작 | `1` |
| CO_품목코드.바코드상품코드끝 | `6` |
| 스캔 바코드에서 추출 | `substring(0, 6)` = `111010` (6자리) |
| 비교 | `111010` ≠ `11101006941234` → **매칭 실패** |

## 상세 흐름

1. **바코드 스캔** → `req = "111010012300610933202604020001"` (30자리)
2. **TB_BARCODE_INFO 조회** → BARCODEGOODS = `11101006941234`, FROM=1, TO=6
3. **추출** → `req.substring(0, 6)` = `111010`
4. **비교** → `111010`.equals(`11101006941234`) → **false** → 매칭 실패

## 영향 범위
- 테스트 데이터 설정 오류 (코드 문제 아님)
- CO_품목코드의 바코드 위치 설정이 BARCODEGOODS 값과 일치하면 정상 동작

## 수정 방안

### CO_품목코드 테이블 데이터 수정

BARCODEGOODS가 14자리이므로 위치 설정도 14자리에 맞춤:

| 컬럼 | 변경 전 | 변경 후 |
|------|---------|---------|
| 바코드상품코드시작 | 1 | 1 |
| 바코드상품코드끝 | 6 | 14 |
| 중량시작 | 7 | 15 |
| 중량끝 | 12 | 20 |

> WHERE 조건: `회사코드 = '20' AND 품목코드 = '1110100694'`

### 수정 후 테스트 바코드

```
11101006941234012300610933202604020001
```

| 위치 | 값 | 의미 |
|:----:|------|------|
| 1~14 | `11101006941234` | 상품코드 (BARCODEGOODS 매칭) |
| 15~20 | `012300` | 중량 12300g (ZEROPOINT=0) |
| 21~26 | `610933` | 회사코드 |
| 27~38 | `202604020001` | 수입식별번호 |
