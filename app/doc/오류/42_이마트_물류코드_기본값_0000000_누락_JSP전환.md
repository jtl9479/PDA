# 이마트 출하대상 물류코드(EMARTLOGIS_CODE) 기본값 '0000000' 누락 (JSP 전환)

## 발견일
2026-10-12

## 에러 발생 시나리오

```
1. 이마트 매출처품목코드매핑(CO_매출처품목코드매핑)에 물류코드가 비어 있는 품목 (바코드타입 M0/M8/M9 중 4건)
2. 이마트(searchType 0) 또는 이마트 비정량(4) 출하대상 받기
3. EMARTLOGIS_CODE = '' 로 내려옴 (원본은 '0000000')
4. M0 라벨 출력 시 si.getEMARTLOGIS_CODE().substring(0, 6) → StringIndexOutOfBoundsException → 라벨 미출력
   미트센터(9231) 분기도 '0000000' 비교가 원본과 달라짐
```

---

## 현상
- 물류코드가 없는 이마트 품목의 EMARTLOGIS_CODE 가 원본 '0000000' 이 아니라 '' 로 내려온다
- **M0 라벨은 물류코드 앞 6자리를 항상 잘라 쓰므로(`LabelM0.java` 44줄) 빈 값이면 예외로 라벨이 출력되지 않는다**
- 미트센터(점포코드 9231) 라벨 분기(`LabelM0.java` 136·141줄)가 `'0000000'` 일치 여부로 갈리는데, '' 는 "물류코드 있음"으로 판정된다

## 원래부터 있던 버그인가?

**NO - Oracle 뷰 → MSSQL JSP 전환 시 기본값 처리 누락**

```sql
-- 원본 app/doc/view/VW_PDA_WID_LIST 90·227줄, VW_PDA_WID_LIST_NONFIXED 89줄
DECODE(EO.EMARTLOGIS_CODE, NULL, '0000000', EO.EMARTLOGIS_CODE) AS EMARTLOGIS_CODE
-- Oracle 은 '' 도 NULL 로 취급 → 빈 값이면 '0000000'
```

## 원인

### 문제 1 (주요): JSP 기본값 없음

#### 코드 위치
- `search_shipment.jsp` : 60줄 (이마트)
- `search_production_nonfixed.jsp` : 60줄 (이마트 비정량)

#### 현재 문제 코드
```java
+ ", COALESCE(M1.물류코드, M2.물류코드) AS EMARTLOGIS_CODE"
// ★ NULL·'' 일 때 '0000000' 기본값 없음
```

### 데이터 (운영 weberp_hl, 회사코드 20, 바코드타입 M0/M8/M9 매핑)

| 물류코드 | 건수 |
|---|:-:|
| 빈 값('') | 4 |
| 13자리 | 7 |

## 영향 범위
- 이마트·이마트 비정량 출하대상 (EMARTLOGIS_CODE index 23)
- `LabelM0.java` 44줄(pBarcode2 조립), 136·141줄(미트센터 분기), 182·243줄(미트센터 바코드)
- 홈플러스·롯데·도매 JSP는 원본도 기본값 방식이 달라 대상 아님

## 수정 방안

### 수정 1: 원본과 같이 NULL·'' 이면 '0000000'

```java
+ ", ISNULL(NULLIF(COALESCE(M1.물류코드, M2.물류코드), ''), '0000000') AS EMARTLOGIS_CODE"
```

> M1(출고거래처 매핑) → M2(상위 거래처 매핑) 우선순위는 변경하지 않는다
