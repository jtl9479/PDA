# 이마트 수기 중량입력 "반올림" 주석/문서 표기가 실제 동작(버림)과 불일치

## 발견일
2026-07-15

## 확정 판정 (사용자 확인)
- **동작(버림)이 정상이다.** 이마트 수기 중량은 소수점 첫째자리 버림(`Math.floor`)이 맞는 사양이며, 이는 원본과 100% 동일하다.
- 따라서 **연산 로직은 수정하지 않는다.** 오직 실제 동작과 어긋난 표기(javadoc "반올림")만 정정 대상이다.
- 즉 이 문서는 "기능 오류"가 아니라 "문서/주석 표기 오류" 건이다.

## 에러 발생 시나리오

```
1. EDA51 실기기에서 이마트(searchType=0) 출하계근 화면 진입
2. 계근입력시작 후 수기 중량입력 모드(work_flag=0)에서 12.34 입력 → 입력 버튼 클릭
3. inputBtnListener에서 Math.floor(12.34*10)/10.0 연산 → 결과 12.3
4. 12.36 입력 → 동일 연산 → 결과 12.3 (반올림이면 12.4가 되어야 함)
5. 코드 주석과 javadoc은 "반올림"으로 표기되어 있으나 실제 동작은 "버림(절사)"
```

## 현상
- 이마트(searchType=0) 수기 중량입력 시 `12.34 → 12.3`, `12.36 → 12.3`으로 처리됨
- 반올림이라면 `12.36 → 12.4`가 되어야 하나 실제로는 `12.3` → **버림(floor) 동작이 확정적으로 실측됨**
- logcat 실측:
  ```
  weight_double 1==12.36
  weight_double 1-1==123.0
  weight_double 1-2==12.3
  ```
- 코드 내 javadoc/주석은 "반올림"으로 표기되어 있어 실제 동작(버림)과 표기가 불일치
- **핵심 현상: 코드 동작 자체는 원본과 100% 동일하여 결함이 아니며, 표기(주석/javadoc)만 실제 동작과 다르다**

## 원래부터 있던 버그인가?

**YES — 원본부터 존재하던 표기(주석) 문제이며, 동작 자체는 원본과 100% 동일. 코드 결함이 아니므로 수정 대상이 아니다.**


원본 324~330줄이 현재 코드(BixolonShipmentActivity.java 656~662줄)와 연산/주석 모두 동일하다. 원본 시점부터 이미 "반올림"이라는 주석이 실제 `Math.floor` 동작과 불일치한 상태로 존재했으며, 전환 과정에서 발생한 신규 문제가 아니다.

#### 발생 시나리오
1. 코드 작성자가 최초 구현 시 "반올림"을 의도했으나 `Math.round` 대신 `Math.floor`를 사용함(원본 시점의 표기 오류로 추정)
2. 이후 유지보수 과정에서 실제 동작(버림)을 확인했지만, 동작을 바꾸지 않고 "의미는 없는 코드이나 일단 남겨놓음"이라는 주석만 추가하여 "반올림" 단어 자체는 정정되지 않은 채 남음
3. 전환 프로젝트(PDA-INNO)에서도 원본 로직/주석을 100% 동일 유지 원칙에 따라 그대로 이식하여 javadoc(621줄, 1556줄)까지 "반올림"으로 표기됨

## 상세 흐름

1. **수기 중량입력** (work_flag == 0)
   - 사용자가 EditText에 중량값(예: 12.36) 입력 후 입력 버튼 클릭

2. **이마트(searchType=0) 분기** (BixolonShipmentActivity.java:656)
   - `Math.floor(weight_double * 10)` → `123.0` (12.36*10=123.6 → floor → 123.0)
   - `123.0 / 10.0` → `12.3`
   - `String.format("%.1f", 12.3)` → `"12.3"`

3. **문제 발생 단계 (표기 불일치)**
   - **경로 A (실제 동작)**: `Math.floor` 기반 버림 연산 → `12.36 → 12.3` (정상, 원본과 100% 동일)
   - **경로 B (문서/주석 표기)**: javadoc·주석은 "반올림"으로 서술 → 코드를 읽는 개발자가 반올림으로 오해할 가능성

4. **결과**
   - 실제 계근 데이터/DB 저장/라벨 출력 값은 모두 정상(원본과 동일)이므로 **기능적 영향 없음**
   - 표기만 실제와 달라 향후 유지보수 시 오해를 유발할 잠재적 위험 존재
