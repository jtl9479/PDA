## MSSQL 전환 신규 오류 4건

### 오류 1: STORE_IN_DATE datetime 형식 변환 누락
- **코드 위치**: `search_shipment_homeplus.jsp:59`, `search_homeplus_nonfixed.jsp:60`, `search_shipment_lotte.jsp:60`
- **현상**: MSSQL datetime 타입 `SD.납기일자`를 `rs.getString()`으로 읽으면 `"2026-05-04 00:00:00.0"` 형식 반환 → Java substring 파싱 오류
- **수정 방안**: `CONVERT(VARCHAR(8), SD.납기일자, 112) AS STORE_IN_DATE`
- **영향**: searchType 2/5/6

### 오류 2: SM_수주상세 LEFT JOIN 다중 행 팽창
- **코드 위치**: `search_shipment_homeplus.jsp:99~100`, `search_homeplus_nonfixed.jsp:105~106`, `search_shipment_lotte.jsp:102~103`
- **현상**: 동일 마트사SEQ에 SM_수주상세 행이 N건이면 Cartesian product → 출하 건 N배 중복 표시
- **수정 방안**: `LEFT JOIN SM_수주상세` → `(SELECT TOP 1 납기일자 FROM SM_수주상세 WHERE 마트사SEQ = HE.SEQ ORDER BY SEQ DESC)` 서브쿼리
- **영향**: searchType 2/5/6

### 오류 3: GI_REQ_PKG null 값 parseDouble 예외
- **코드 위치**: `ProgressDlgShipSearch.java:216`
- **현상**: `SM_출고LOT.박스수량` NULL 시 `Double.parseDouble("null")` → `NumberFormatException` 앱 크래시
- **현재 코드**: `si.setGI_REQ_PKG(String.valueOf((int) Double.parseDouble(temp[5])));`
- **수정 방안**: temp[5] null/"null"/빈값 방어 후 parseDouble 호출
- **영향**: 전체 searchType

### 오류 4: PPCODE 컬럼명 대소문자 불일치
- **코드 위치**: 출하 조회 JSP 다수 `I.PPCODE`
- **현상**: MSSQL CS 콜레이션 환경에서 실제 컬럼명과 불일치 시 `Invalid column name` 오류
- **수정 방안**: ERP DDL에서 실제 컬럼명 확인 후 JSP 통일
- **영향**: 전체 searchType
