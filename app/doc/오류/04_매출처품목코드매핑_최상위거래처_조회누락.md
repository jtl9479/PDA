# 매출처품목코드매핑 최상위거래처 조회 누락

## 발견일
2026-03-31

## 현상
- search_shipment.jsp에서 CO_매출처품목코드매핑 JOIN 시 출고거래처(H.출고거래처)로만 매칭
- CO_매출처품목코드매핑에 출고거래처(Z11730)가 아닌 최상위 거래처(A00549)로 등록된 경우 조회 누락
- **출하대상 데이터가 있음에도 앱에서 조회되지 않음**

## 원래부터 있던 버그인가?

**NO - 기존 VIEW(VW_PDA_WID_LIST)에서는 B_EMART_BARCODE 테이블을 사용했으므로 이 문제가 없었음. MSSQL 전환 시 CO_매출처품목코드매핑 테이블로 변경하면서 발생.**

## 원인

### 문제 1 (주요): JOIN 조건이 출고거래처 직접 매칭만 지원

#### 코드 위치
- `search_shipment.jsp` : 93~96행

#### 현재 문제 코드
```sql
JOIN CO_매출처품목코드매핑 M
  ON D.회사코드 = M.회사코드
 AND D.출고품목코드 = M.품목코드
 AND H.출고거래처 = M.거래처코드
-- ★ 출고거래처(Z11730)로만 매칭, 최상위 거래처(A00549) 매핑은 찾지 못함
```

#### 발생 시나리오
1. CO_매출처품목코드매핑에 최상위 거래처(A00549)로 바코드타입/타입구분/물류코드 등록
2. 출고 데이터의 출고거래처는 하위 거래처(Z11730)
3. JOIN 시 Z11730 = A00549 불일치 → 해당 출고 데이터 누락

## 상세 흐름

### CO_거래처MASTER 계층코드 구조

```
최상위: A0054          (5자리)  → 거래처코드: A00549
상위:   A0054B0012     (10자리) → 거래처코드: B00123 (중간)
하위:   A0054B0012Z117 (15자리) → 거래처코드: Z11730 (출고거래처)
```

- `LEFT(계층코드, 5)` → 최상위 거래처의 계층코드 추출
- 중간 상위 거래처는 고려하지 않음 (ERP 동일)

### ERP 처리 방식 (S0101MartCmpny_SQL.xml 참고)

1. TEMP_B에 하위 거래처(계층 0) + 최상위 거래처(계층 1)를 UNION ALL
2. CO_매출처품목코드매핑과 JOIN
3. `ROW_NUMBER() PARTITION BY 상품코드 ORDER BY 계층 ASC` → RN = 1 (하위 우선, 계층 0이 먼저)

### PDA 적용 방식 (하위 우선)

1. 출고거래처의 계층코드에서 `LEFT(계층코드, 5)`로 최상위 거래처 추출
2. 하위 거래처(출고거래처) 매핑을 먼저 찾음
3. 없으면 최상위 거래처 매핑 사용

## 영향 범위
- `search_shipment.jsp` : CO_매출처품목코드매핑 JOIN 부분
- CO_매출처품목코드매핑을 사용하는 다른 JSP도 동일 문제 가능성 있음

## 수정 방안

### ~~방안 1: COALESCE 서브쿼리 방식 (기각 — 성능 이슈)~~

행마다 상관 서브쿼리 2회 실행 → 데이터 많으면 느려짐

### 방안 2: LEFT JOIN 방식 (채택 — 성능 우수)

서브쿼리 없이 LEFT JOIN으로 하위/최상위 매핑을 동시에 조회 후 SELECT에서 COALESCE로 우선순위 적용

```sql
-- 변경 전
JOIN CO_매출처품목코드매핑 M
  ON D.회사코드 = M.회사코드
 AND D.출고품목코드 = M.품목코드
 AND H.출고거래처 = M.거래처코드

-- 변경 후
-- 1. 출고거래처의 계층코드 조회
JOIN CO_거래처MASTER G
  ON G.회사코드 = D.회사코드
 AND G.거래처코드 = H.출고거래처

-- 2. 하위 거래처(출고거래처) 매핑 조회
LEFT JOIN CO_매출처품목코드매핑 M1
  ON M1.회사코드 = D.회사코드
 AND M1.품목코드 = D.출고품목코드
 AND M1.거래처코드 = H.출고거래처

-- 3. 최상위 거래처 조회 (계층코드 앞 5자리)
LEFT JOIN CO_거래처MASTER G2
  ON G2.회사코드 = D.회사코드
 AND G2.계층코드 = LEFT(G.계층코드, 5)
 AND G2.거래처코드 != H.출고거래처

-- 4. 최상위 거래처 매핑 조회
LEFT JOIN CO_매출처품목코드매핑 M2
  ON M2.회사코드 = D.회사코드
 AND M2.품목코드 = D.출고품목코드
 AND M2.거래처코드 = G2.거래처코드
```

SELECT 절에서 COALESCE로 하위 우선:
```sql
COALESCE(M1.바코드타입, M2.바코드타입) AS BARCODE_TYPE
COALESCE(M1.타입구분, M2.타입구분)     AS ITEM_TYPE
COALESCE(M1.물류코드, M2.물류코드)     AS EMARTLOGIS_CODE
```

#### 성능 비교

| 비교 | COALESCE 서브쿼리 | LEFT JOIN 방식 |
|------|-----------------|---------------|
| 서브쿼리 | 행마다 2회 | **없음** |
| JOIN 횟수 | 2회 | 4회 (단순 JOIN) |
| 인덱스 활용 | 제한적 | **효율적** |
| 속도 | 데이터 많으면 느림 | **일정** |

#### 우선순위 동작

| 상황 | 매핑 결과 |
|---|---|
| 하위(출고거래처)에 매핑 있음 | 하위 매핑 사용 (M1) |
| 최상위에만 매핑 있음 | 최상위 매핑 사용 (M2) |
| 둘 다 매핑 있음 | 하위 매핑 우선 (COALESCE) |
| 둘 다 없음 | NULL (LEFT JOIN이므로 데이터 누락 안됨) |

> ERP와 동일하게 하위(출고거래처) 우선 (2026-03-31 확인)

#### WHERE 조건 영향
- 기존 `M.타입구분 = 'W'` 조건 → `COALESCE(M1.타입구분, M2.타입구분) = 'W'`로 변경 필요
