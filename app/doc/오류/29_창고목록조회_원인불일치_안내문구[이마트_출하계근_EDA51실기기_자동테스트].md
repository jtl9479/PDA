# 창고 목록 조회 0건/통신실패 시 원인과 다른 안내 문구 표시

## 발견일
2026-07-15

## 에러 발생 시나리오

```
1. 서버(weberp_dev, http://183.101.157.205:4040)가 기동되지 않은 상태
2. EDA51 실기기에서 PDA 앱 최초 실행
3. LoginActivity 진입 → WarehouseSearchTask 실행
4. search_warehouse.jsp 호출 실패(서버 미기동 → 연결 불가)
5. WarehouseSearchTask.doInBackground()가 예외를 잡고 빈 문자열("") 반환
6. onPostExecute()에서 Common.warehouseNames가 비어있음을 확인
7. "창고 목록 없음 / 등록된 PDA 사용 창고가 없습니다.\nERP 창고관리(C0114)에서 PDA여부를 설정하세요." 다이얼로그 표시 → 로그인 불가(Spinner 미구성)
8. 서버 기동 후 앱 재시작 → 동일 조건(회사코드 20)에서 창고 "(테스트) 부산센터"(코드 W301)가 정상 조회됨
```

> **실제 발생 원인 확정 (2026-07-15)**: 이 건의 트리거는 **서버 미기동(서버가 열려 있지 않은 상태)** 이었음이 확인되었다. 즉 실제 원인은 "연결 실패"인데 앱은 "ERP 창고관리 설정 미비"라는 **전혀 다른 원인**을 단정해 안내했다. 조회 결과가 실제로 0건이었던 것이 아니다.

---

## 현상
- **서버가 기동되지 않아 연결 자체가 실패한 상황**인데도, "ERP 창고관리(C0114)에서 PDA여부를 설정하라"는 **원인이 확정된 것처럼** 안내하는 문구가 표시됨
- 실제 원인은 서버 미기동이며 ERP 설정과 완전히 무관했다 — 서버 기동 후 동일 조건에서 정상 조회됨(W301)
- 사용자가 문구를 그대로 믿고 ERP 창고관리(C0114) 설정을 확인/변경하는 등 **원인과 무관한 잘못된 조치**를 시도하게 된다. 정작 필요한 조치(서버 기동 확인)는 안내되지 않는다
- 로그인이 완전히 차단되며, 화면 내 복구 수단(재시도 버튼 등)이 없어 **앱 강제 종료 후 재시작만이 유일한 복구 방법**
- **핵심 현상: 연결 실패(서버 미기동)와 "ERP 설정 미비로 인한 조회 0건"이 화면상 완전히 동일한 문구로 안내되어 사용자가 실제 원인을 구분할 수 없음**

## 원래부터 있던 버그인가?

**NO - 오류 24번 수정(개발/53, 하드코딩 fallback 제거) 이후 새로 도입된 코드에서 발생한 신규 문제**

```java
// LoginActivity.java:96-105 (WarehouseSearchTask.doInBackground)
protected String doInBackground(Void... params) {
    try {
        String data = " WHERE 회사코드 = '" + Common.selectCompanyCode + "'";
        return HttpHelper.getInstance().sendDataDb(data, "inno",
            "search_warehouse", Common.URL_SEARCH_WAREHOUSE);
    } catch (Exception e) {
        Log.e(TAG, "창고 목록 조회 실패: " + e.getMessage());
        return "";   // ★ 통신 예외도 "빈 문자열"로 수렴 — 조회 0건과 구분 불가
    }
}
```

원본(구 시스템)에는 이 WarehouseSearchTask 자체가 없었고(오류 24 참조), 오류 24 수정 시 하드코딩 fallback을 제거하면서 "조회 0건 시 안내 다이얼로그" 로직이 신규로 추가되었다. 이 신규 로직이 통신 실패 케이스를 함께 흡수하면서 오원인 안내 문구 문제가 발생.

## 원인

### 문제 1 (주요): 통신 실패와 데이터 0건이 동일한 빈 문자열로 수렴

#### 코드 위치
- `LoginActivity.java` : 96~105줄 (`WarehouseSearchTask.doInBackground`)

#### 현재 문제 코드
```java
// LoginActivity.java:101-104
} catch (Exception e) {
    Log.e(TAG, "창고 목록 조회 실패: " + e.getMessage());
    return "";
    // ★ 네트워크 타임아웃, 서버 미응답, 파싱 예외 등 "통신 실패"와
    //   서버가 정상 응답했지만 PDA여부='1' 창고가 실제로 0건인 "데이터 0건"이
    //   똑같이 빈 문자열("")로 반환되어 onPostExecute에서 구분 불가
}
```

#### 발생 시나리오
1. EDA51의 네트워크 상태가 불안정하거나 서버 응답이 지연되어 `HttpHelper.sendDataDb()`가 예외를 던짐
2. catch 블록이 예외를 로그로만 남기고 `""` 반환 → onPostExecute에는 "정상 응답인데 0건"인 경우와 동일한 값이 전달됨
3. onPostExecute는 원인을 구분할 방법이 없으므로 항상 "ERP 창고관리(C0114)에서 PDA여부를 설정하라"는 고정 문구를 표시

### 문제 2 (보조): 조회 실패 시 안내만 있고 재시도 수단이 없음

#### 코드 위치
- `LoginActivity.java` : 127~134줄 (`onPostExecute`)

#### 문제 코드
```java
// LoginActivity.java:127-134
if (Common.warehouseNames.isEmpty()) {
    new AlertDialog.Builder(LoginActivity.this)
        .setTitle("창고 목록 없음")
        .setMessage("등록된 PDA 사용 창고가 없습니다.\nERP 창고관리(C0114)에서 PDA여부를 설정하세요.")
        .setPositiveButton("확인", null)
        .show();
    return;  // ★ Spinner 미구성 상태로 화면이 멈춤 — 재조회(재시도) 버튼이 없어
             //   사용자가 취할 수 있는 조치는 앱 강제 종료 후 재시작뿐
}
```

## 상세 흐름

1. **앱 시작** (LoginActivity.onCreate)
   - `new WarehouseSearchTask().execute()` 호출

2. **서버 조회 시도** (WarehouseSearchTask.doInBackground)
   - **경로 A (통신 성공, 데이터 0건)**: PDA여부='1' 창고가 실제로 없어 서버가 빈 문자열 정상 응답
   - **경로 B (통신 실패)**: 타임아웃/예외 발생 → catch에서 `""` 반환
   - 두 경로 모두 리턴값이 동일(`""`)하여 이후 단계에서 구분 불가

3. **응답 처리** (onPostExecute)
   - `receiveData`가 비어있으므로 `Common.warehouseNames`, `Common.warehouseCodes` 모두 비어있음

4. **문제 발생 단계** (onPostExecute:127-134)
   - 경로 A/B 무관하게 동일한 "ERP 창고관리(C0114)에서 PDA여부를 설정하세요" 다이얼로그 표시
   - 실제로는 경로 B(통신 실패)였음에도 사용자는 ERP 설정 문제로 오인
   - Spinner 미구성 + return → 로그인 화면이 멈춘 상태로 유지, 재시도 버튼 없음

5. **재현/복구**
   - 앱 강제 종료 후 재시작 시 동일 조건(회사코드 20)에서 창고 "(테스트) 부산센터"(W301) 정상 조회됨 → 통신 실패였음이 사후 확인됨

## 영향 범위
- `LoginActivity.java` (96~105줄 `doInBackground`, 127~134줄 `onPostExecute`) — 창고 목록 조회 전체 흐름
- 로그인 화면 전체 — 조회 실패 시 로그인 자체가 차단되고 앱 재시작 외 복구 수단 없음
- 사용자 경험 — 통신 문제를 ERP 설정 문제로 오인하여 불필요한 ERP 확인/문의 유발 가능

## 수정 방안

### 수정 1: 통신 실패와 데이터 0건을 구분하는 결과 타입 도입

```java
// LoginActivity.java 수정 방향
protected String doInBackground(Void... params) {
    try {
        String data = " WHERE 회사코드 = '" + Common.selectCompanyCode + "'";
        return HttpHelper.getInstance().sendDataDb(data, "inno",
            "search_warehouse", Common.URL_SEARCH_WAREHOUSE);
    } catch (Exception e) {
        Log.e(TAG, "창고 목록 조회 실패: " + e.getMessage());
        return null;  // 통신 실패는 null로 별도 표시 (데이터 0건은 "" 유지)
    }
}
```

### 수정 2: 원인별 안내 문구 분리 + 재시도 버튼 추가

```java
// LoginActivity.java 수정 방향
if (receiveData == null) {
    // 통신 실패
    new AlertDialog.Builder(LoginActivity.this)
        .setTitle("창고 목록 조회 실패")
        .setMessage("서버와 통신 중 오류가 발생했습니다.\n네트워크 상태를 확인 후 다시 시도하세요.")
        .setPositiveButton("재시도", (d, w) -> new WarehouseSearchTask().execute())
        .setNegativeButton("취소", null)
        .show();
    return;
} else if (Common.warehouseNames.isEmpty()) {
    // 정상 응답이나 데이터 0건
    new AlertDialog.Builder(LoginActivity.this)
        .setTitle("창고 목록 없음")
        .setMessage("등록된 PDA 사용 창고가 없습니다.\nERP 창고관리(C0114)에서 PDA여부를 설정하세요.")
        .setPositiveButton("확인", null)
        .show();
    return;
}
```

> 수정 시 주의사항: 오류 24번(하드코딩 fallback 제거) 취지를 유지하면서, "원인 불확실 안내"만 개선 대상. 재시도 버튼 추가 시 무한 재시도 루프가 발생하지 않도록 최대 횟수 제한 검토 필요.
