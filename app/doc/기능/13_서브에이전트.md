# 서브 에이전트

**작성일**: 2026-04-09

---

## 개요

반복 작업 자동화를 위한 Claude Code 서브 에이전트 8개.
문서 생성(그룹A), 코드 검증(그룹B), 커밋+일정(그룹C), 테스트(그룹D), 문서 정합성(그룹E)으로 구성되며, 개발 사이클 전체를 커버한다.

---

## 1. 전체 흐름

```
[실기기 테스트 / 개발 작업]
        │
        ├─ 오류 발견 ──→ ② 오류 문서 ──→ ⑧ 문서 정합성 ──→ ③ 개발 가이드
        │                                                      │
        │                               ⑧ 문서 정합성 ←─────────┘
        │                                      │
        │                          [메인 에이전트 + 사용자 지시]
        │                            Step별 코드 수정 (수동)
        │                                      │
        │                    ┌─────────┬────────┼────────┐
        │                    ▼         ▼        ▼        ▼
        │               ⑤ 코드    ⑥ 원본    ⑦ 테스트  ④ 기능/
        │                 검증      비교      시나리오  소스분석 문서
        │                    │         │        │        │
        │                    └─────────┴────────┘    ⑧ 문서 정합성
        │                              │                │
        │                     검증+테스트 완료              │
        │                              │                │
        └─────────────────→ ① 일정+커밋 ←──────────────┘
                         (커밋+푸시+체크리스트+일정)
```

**코드 수정은 서브 에이전트가 아닌 메인 에이전트가 담당한다.**
- 사용자가 "Step N 진행하라"로 지시 → 메인 에이전트가 개발 가이드 참조하여 실행
- 이유: 코드 수정은 가장 위험한 단계이며, 프로젝트 제1원칙("기존 기능과 100% 동일")과 AI 제약 조건("다음 step은 지시를 기다린다")을 준수하기 위함
- 서브 에이전트는 코드 수정 전후의 보조 작업(문서 생성, 검증, 커밋)만 담당

| **③ 개발 가이드** | **⑤ 코드 검증** | 코드 수정 step 완료 후 | 인덱스+파라미터+컴파일 정합성 확인 |
| **③ 개발 가이드** | **⑥ 원본 비교** | 코드 수정 step 완료 후 | 100% 기능 동일성 확인 |

### 3.2 그룹 분류

**그룹 A. 문서 생성 (입력)**

| # | 에이전트 | 출력물 | 다음 단계 |
|:-:|---------|--------|----------|
| ② | 오류 문서 | `오류/XX_오류명.md` | → ③ 개발 가이드 |
| ③ | 개발 가이드 | `개발/XX_개발명.md` | → ⑤⑥ 검증 |
| ④ | 기능/소스분석 | `기능/XX.md`, `소스분석/XX.md` | → ① 커밋 |

- ②→③은 **순차 의존** (오류 문서가 있어야 개발 가이드 작성 가능)
- ④는 **독립** (개발 사이클과 무관하게 언제든 작성)

**그룹 B. 검증 (판정)**

| # | 에이전트 | 검증 대상 | 병렬 가능 |
|:-:|---------|----------|:--------:|
| ⑤ | 코드 검증 | 인덱스+파라미터+WHERE+컴파일+로컬DB | O |
| ⑥ | 원본 비교 | PDA-INNO(원본) ↔ 현재 | O |

- **2개 병렬 실행 가능** (서로 의존 없음)
- 하나라도 실패 → 코드 재수정 → 다시 검증

**그룹 C. 마무리 (출력)**

| # | 에이전트 | 역할 |
|:-:|---------|------|
| ① | 일정+커밋 | 모든 에이전트의 최종 출구 (허브) |

- **모든 에이전트가 ①로 수렴**
- 가장 자주 호출됨

**그룹 D. 테스트**

| # | 에이전트 | 출력물 | 다음 단계 |
|:-:|---------|--------|----------|
| ⑦ | 테스트 | `테스트/XX.md`, `테스트데이터/XX.md` | → ① 커밋 또는 → ② 오류 문서 (실패 시) |

- 개발 프로세스 흐름의 마지막 단계: `개발/ → 테스트/ → 오류/ (재발 시)`
- 테스트 성공 → ① 커밋, 테스트 실패 → ② 오류 문서 (사이클 반복)

**그룹 E. 문서 정합성**

| # | 에이전트 | 검증 대상 | 호출 시점 |
|:-:|---------|----------|----------|
| ⑧ | 문서 정합성 | 관련 문서 간 번호/이름/경로/WF 일치 | 문서 수정 후 (커밋 전) |

- 문서 생성 에이전트(②③④)가 문서를 수정한 후, ① 커밋 전에 호출
- 불일치 발견 시 → 문서 재수정 후 재검증

### 3.3 상관관계 요약

| 관계 | 설명 |
|------|------|
| **② → ③** | 순차 의존 (오류 → 개발 가이드) |
| **⑤, ⑥** | 병렬 독립 (검증 2종 동시 실행) |
| **① ← 전체** | 허브 (모든 에이전트의 최종 출구) |
| **④** | 독립 (개발 사이클과 별개) |
| **⑦ → ②** | 테스트 실패 시 오류 문서로 사이클 반복 |
| **②③④ → ⑧** | 문서 수정 후 정합성 검증 (커밋 전) |

## 4. 워크플로우

### WF-1. 오류 발견 → 수정 → 커밋 (풀 사이클)

가장 빈번한 워크플로우. 실기기 테스트 중 오류 발견 시 전체 사이클.

```
[오류 발견]
    ↓
② 오류 문서  ─→  ⑧ 문서 정합성  ─→  ① 커밋 (오류 문서 커밋)
    ↓
③ 개발 가이드  ─→  ⑧ 문서 정합성  ─→  ① 커밋 (개발 가이드 커밋)
    ↓
사용자 지시 → [메인 에이전트: Step별 코드 수정]
    ↓
┌───┬───┐
⑤   ⑥    (병렬 검증)
└───┴───┘
    ↓ 전부 통과        ↓ 실패
① 커밋 (step 완료)    코드 재수정 → 재검증
    ↓
[다음 Step: 사용자 지시 대기]
    ↓
① 커밋 (최종 step 완료)
    ↓
⑦ 테스트 시나리오 작성+실행
    ↓ 성공              ↓ 실패
① 커밋 (테스트 완료)    ② 오류 문서 (사이클 반복)
```

**호출 순서**: ② → ⑧ → ① → ③ → ⑧ → ① → [사용자 지시 → 메인 → ⑤⑥ → ①] × N회 → ⑦ → ① (또는 → ②)
**사용 에이전트**: 8개 전부
**예시**: 오류19(회사코드 잘림) → 개발32(packet수정) → 코드 수정 → 검증 → 커밋

---

### WF-2. 기능/소스분석 문서 작성 → 커밋

개발 사이클과 무관하게 코드 분석이나 기능 정리가 필요할 때.

```
[기능 정리 / 소스 분석 요청]
    ↓
④ 기능/소스분석 문서
    ↓
⑧ 문서 정합성
    ↓
① 커밋 (문서 커밋)
```

**호출 순서**: ④ → ⑧ → ①
**사용 에이전트**: 3개
**예시**: 기능12(계근상세정보 팝업), 소스분석39(이마트출하 전체흐름)

---

### WF-3. 단순 코드 수정 → 검증 → 커밋

오류 문서 없이 바로 코드 수정이 필요한 경우. (하드코딩 변경, 소스 정리 등)

```
[코드 수정 요청]
    ↓
③ 개발 가이드  ─→  ⑧ 문서 정합성  ─→  ① 커밋 (개발 가이드 커밋)
    ↓
사용자 지시 → [메인 에이전트: 코드 수정]
    ↓
┌───┬───┐
⑤   ⑥    (병렬 검증)
└───┴───┘
    ↓ 전부 통과
① 커밋 (step 완료)
```

**호출 순서**: ③ → ⑧ → ① → [사용자 지시 → 메인 → ⑤⑥ → ①] × N회
**사용 에이전트**: 5개 (②오류 문서, ⑦테스트 제외)
**예시**: 창고코드 하드코딩 변경, 회사코드 추가

---

### WF-4. JSP 수정 → 코드 검증 → 커밋

JSP SELECT/out.println 수정 시 인덱스 정합성이 핵심인 경우.

```
[JSP 수정]
    ↓
⑤ 코드 검증 (인덱스+파라미터+컴파일)
    ↓
① 커밋 (JSP 커밋 + step 완료)
```

**호출 순서**: ⑤ → ①
**사용 에이전트**: 2개
**예시**: search_shipment.jsp에 GI_L_ID 컬럼 추가 (개발31 Step 4)

---

### WF-5. 하루 시작/종료

매일 반복되는 일정 관리.

```
[하루 시작]
    ↓
① 일정+커밋: 오늘 일정 문서 확인 / 생성
    ↓
[작업 진행]
    ↓
[하루 종료]
    ↓
① 일정+커밋: 오늘 완료 작업 최종 반영 + 다음날 일정 생성
```

**호출 순서**: ① (시작) → [작업] → ① (종료)
**사용 에이전트**: 1개
**예시**: 2026-04-09.md 생성, 완료 작업 반영, 2026-04-10.md 생성

---

### WF-6. 테스트 중 오류 재발

테스트 시나리오 동작 중 오류가 재발하여 사이클이 반복되는 경우.

```
⑦ 테스트 시나리오 실행
    ↓ 오류 발생
② 오류 문서  ─→  ⑧ 문서 정합성  ─→  ① 커밋
    ↓
③ 개발 가이드  ─→  ⑧ 문서 정합성  ─→  ① 커밋
    ↓
[사용자 지시 → 메인 코드 수정 → ⑤⑥ → ①]
    ↓
⑦ 테스트 시나리오 재실행
    ↓ 또 오류 발생
② 오류 문서 (사이클 반복)
```

**호출 순서**: WF-1 반복
**사용 에이전트**: 8개 전부
**예시**: 이마트 전체 흐름 테스트 → 오류15(GI_D_ID 비유니크) → 개발31 → 재테스트 → 오류19(회사코드) → 개발32

## 6. 주의사항

- 에이전트 동시 실행 상한: 10개 (병렬 검증 2개는 문제없음)
- 권장 에이전트 수: 3~7개 (현재 8개 = 상한 초과, 문서 정합성의 실질적 필요성으로 허용)

- 문서 수정 후 ⑧ 정합성 검증 → 통과 후 ① 커밋
- ① 일정+커밋은 **모든 에이전트의 허브** — 작업 완료 시 반드시 호출
- 순번 자동 부여 시 해당 폴더의 기존 파일 번호를 확인 후 +1
